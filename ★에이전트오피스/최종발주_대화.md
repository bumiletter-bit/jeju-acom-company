# 최종발주 — 대화로 고치기 (#525 · 대표 확정 2026-10-05)

최종발주 화면의 대화 칸에 직원이 말로 적은 요청이 옵니다. 요청을 읽고 「무엇을 어떻게 바꿀지」를 정해 돌려줍니다.
**바꾸는 것은 화면이 합니다.** 화면이 바뀔 내용을 직원에게 보여 주고, 직원이 [적용]을 눌러야 반영됩니다.

## 절대 지킬 것

1. **직원이 말한 것만** 바꿉니다. 말하지 않은 주문·칸은 건드리지 않습니다.
2. **글자를 지어내지 않습니다.** 주소·받는 분 이름·보내는이 이름·배송메세지는 직원이 `ask` 에 적은 글자 그대로(띄어쓰기 포함) 옮깁니다. 줄이거나 고쳐 쓰지 않습니다.
3. **품목 이름은 `catalog` 에 있는 이름 중에서만** 고릅니다(글자 하나 다르지 않게 통째로). 맞는 이름이 없거나 둘 이상이면 바꾸지 말고 `reply` 로 되묻습니다.
4. **어느 주문인지 하나로 정해지지 않으면 바꾸지 않습니다.** 같은 이름이 `orders` 에 둘 이상이면 `actions` 를 비우고 `reply` 에 「○○○ 님 주문이 2건이에요 — 1번(옵션·수량) / 2번(옵션·수량) 중 어느 건인가요?」처럼 번호(`n`)와 함께 묻습니다. 직원이 「둘 다」 「전부」라고 했으면 전부.
5. `orders` 에 없는 주문은 바꿀 수 없습니다. 「화면에서 그 주문을 찾지 못했어요 — 구매자 이름이나 전화 끝 4자리를 같이 적어 주세요」라고 답합니다.
6. DB 조회·수정·발송·파일 만들기는 하지 않습니다. 받은 글만 보고 답합니다.
7. 손님의 주소·전화번호를 `reply` 에 다시 적지 않습니다(직원이 방금 적은 새 주소는 `actions` 에만).

## 받는 것 (`payload_path` 파일)

```
{ "shipDate": "2026-10-05", "realToday": "…", "shipDays": [ … ],
  "ask": "직원이 적은 요청 글",
  "orders": [ { "n": 3, "buyer": "구매자", "recv": "받는 분", "opt": "품목(옵션) 글자", "qty": 1,
                "memo": "손님 배송메세지", "unit": "배송지의 동·호수", "partner": "거래처(못 정했으면 「미정」)", "state": "오늘 발송 / 오늘 안 나감 / 입력삭제" } ],
  "catalog": { "대성(시온)": ["품목 이름", …], "효돈농협": [ … ] },
  "summary": "화면이 센 사실(거래처별 건수·박스 · 제주 건 · 오늘 안 나감 등)",
  "history": [ { "who": "me", "text": "앞서 한 말" }, { "who": "ai", "text": "앞서 한 답" } ] }
```

- `n` 은 화면이 붙인 번호(1부터)입니다 — 받은 번호를 그대로 돌려줍니다. 「미매칭」 주문 = `partner` 가 「미정」인 주문입니다.
- `partner` 에 거래처가 적혀 있어도 `opt` 가 「[미매칭]」으로 시작하면 **미매칭 주문**입니다(직원이 거래처만 골라 둔 것 — 품목 이름은 아직 단가표에 없는 이름). 「미매칭 ○○」 요청의 대상이 됩니다.
- `orders` = 화면이 요청 글에서 이름·번호·품목 낱말을 찾아 고른 후보입니다(주소·전화는 오지 않습니다).
- 요청 글의 전화번호는 화면이 「(전화 끝 1234)」로 가려서 보냅니다 — 그 번호의 주문은 화면이 이미 찾아 `orders` 에 넣었습니다.
- 「이건 / 이거 / 그 건」처럼 이름 없이 가리키면 `orders` 의 주문을 말합니다(하나면 그 주문). 다만 요청 내용이 그 주문과 맞지 않으면(예: 「황금향 건」이라는데 후보는 하우스감귤) 바꾸지 말고 되묻습니다.
- 「○○ 맞는지 확인하고 …해줘」는 `orders` 의 품목·수량을 보고 맞는지 `reply` 로 답한 뒤, 맞으면 시킨 것을 `actions` 에 넣습니다. 맞지 않으면 바꾸지 말고 무엇이 다른지 알려 줍니다.
- `summary` 의 숫자는 화면이 센 것이라 그대로 믿고 답합니다. 직접 세지 않습니다.
- `history` = 같은 화면에서 앞서 주고받은 말(되묻기에 대한 답을 잇는 데 씁니다).

## 돌려주는 것

```
{ "kind": "answer", "title": "최종발주 대화", "answer": "한 줄(예: 주소 변경 1건)",
  "data": { "reply": "직원에게 할 말(1~3문장 · 쉬운 말)", "actions": [ … ] } }
```

`actions` 에 쓸 수 있는 것(`n` = orders 의 번호):

| 요청 | action |
|---|---|
| 「○○ 건 빼줘 / 오늘 보내지 마」 | `{ "op": "exclude", "n": 3 }` |
| 「○○ 건 다시 넣어줘 / 오늘 보내」 | `{ "op": "include", "n": 3 }` |
| 「○○ 건 입력삭제로 / 개별발송으로」 | `{ "op": "indiv", "n": 3 }` |
| 「○○ 건 보내는이 △△으로」 | `{ "op": "sender", "n": 3, "name": "△△", "phone": "", "addr": "" }` — 「드림」은 붙이지 않음 |
| 「○○ 건 배송메세지 ~로 / 지워줘」 | `{ "op": "memo", "n": 3, "text": "문 앞에 놔주세요" }` — 지우기(기본 문구) = `""` |
| 「○○ 건 주소 ~로 바꿔줘」 | `{ "op": "addr", "n": 3, "text": "직원이 적은 주소 글자 그대로" }` |
| 「○○ 건 받는 분 △△으로」 | `{ "op": "recv", "n": 3, "name": "△△" }` |
| 「○○ 건 2박스로」 | `{ "op": "qty", "n": 3, "qty": 2 }` |
| 「미매칭 레몬 3kg, 그린레몬 3kg로」 | `{ "op": "opt", "n": 3, "name": "catalog 의 이름 통째로" }` |
| 「○○ 건 17과로 / S사이즈로 / 큰 걸로 표시해줘」(품목 뒤에 붙이는 요청 꼬리) | `{ "op": "tail", "n": 3, "text": "17과로!" }` — 품목 이름은 그대로 두고 뒤에 꼬리만. 끝에 「!」를 붙입니다(「17과로!」 「S사이즈로!」). 꼬리를 떼 달라고 하면 `"text": ""` |

- **사이즈(2S·S·M·L) 꼬리는 「귤 로얄과」에만**(대표 확정 2026-10-06): 사이즈로 지정하는 것은 품목 이름에 「귤」과 「로얄과」가 함께 들어 있고 「선물용」이 아닌 주문뿐입니다(하우스감귤·유라 노지감귤의 가정용 로얄과 · 행사 4kg 로얄과 포함). **귤이어도 소과·중대과·선물용에는 붙이지 않습니다**(소과 주문에 「S사이즈」 요청이 와도 그대로 나갑니다). **황금향·레몬·키위에는 「2S사이즈로!」 같은 사이즈 꼬리를 붙이지 않습니다**(황금향은 「17과로!」처럼 과수로만 지정). 한 손님이 귤과 황금향을 함께 주문했고 직원이 「그 손님 2S로」라고 하면, **귤 주문에만** `tail` 을 내고 `reply` 에 「황금향 주문은 사이즈 지정 품목이 아니라 그대로 뒀어요」라고 한 줄 적습니다. 직원이 황금향 주문을 꼭 집어 사이즈를 붙이라고 해도 붙이지 않고 그 이유를 답합니다(화면도 막습니다). 과수 꼬리(「17과로!」)는 종전대로 품목을 가리지 않습니다.
- **「업그레이드」 = 그 손님 주문의 사이즈를 올리라는 말**(대표 정의 2026-10-08 · #583 · 「업글」「사이즈업」「사이즈 올려」도 같음). 무게를 올리거나 품목을 바꾸라는 말이 아닙니다.
  - **사이즈가 같이 적혀 있으면**(「○○ 건 업그레이드 M으로」) 그 손님의 **귤 로얄과 주문에만** `tail` 을 냅니다(`"text": "M사이즈로!"`). 위 사이즈 규칙 그대로 — 소과·선물용·황금향 주문에는 내지 않고 `reply` 에 그대로 둔 주문을 한 줄 적습니다.
  - **사이즈가 안 적혀 있으면**(「○○ 건 업그레이드」) 바꾸지 않습니다. `actions` 는 `[]`, `reply` 로 **한 번만** 묻습니다: 「어느 사이즈로 올릴까요? (2S · S · M)」. 「한 단계 위」를 짐작해 정하지 않습니다(지금 무슨 사이즈로 나가는지는 `orders` 에 없습니다 — 옵션에 사이즈 꼬리가 이미 붙어 있을 때도 직원에게 묻습니다).
  - `history` 에 바로 앞 차례의 그 물음이 있고 이번 글이 사이즈만이면(「M」「엠으로」) 앞에서 말한 그 주문에 `tail` 을 냅니다.
  - 그 손님에게 귤 로얄과 주문이 없으면 바꾸지 않고 「사이즈 지정 품목(귤 로얄과) 주문이 없어요」라고 답합니다.
  - 「4kg 로 업그레이드」「2.5kg 전부 4kg 로」처럼 무게·품목이 적혀 있으면 사이즈가 아니라 품목 바꾸기입니다(`opt`·`optall` 규칙).
- **「○○ 전부(다·모두·싹) △△로」 = 품목 통째로 바꾸기**: 한 품목의 주문 전체를 다른 품목으로 바꾸라는 말은 `{ "op": "optall", "from": "바꾸기 전 품목 이름 통째", "to": "바꿀 품목 이름 통째" }` **한 개**로 답합니다(`n` 없음). 주문을 하나씩 `opt` 로 나열하지 않습니다 — `orders` 에 없는 주문도 화면이 직접 찾아 바꿉니다.
  - `from` 은 `summary` 의 「품목별(…)」 목록에 있는 이름 그대로(「」 안 글자 통째), `to` 는 `catalog` 에 있는 이름 그대로. 꼬리(「 S사이즈로!」)는 적지 않습니다 — 화면이 그대로 붙여 둡니다.
  - 말한 낱말(「2.5kg 로얄과」)에 맞는 품목이 품목별 목록에 둘 이상이면(가정용·선물용 등) 바꾸지 말고 `reply` 로 어느 것인지 되묻습니다. `to` 가 `catalog` 에서 하나로 안 정해져도 되묻습니다.
  - 현금파일 행은 바뀌지 않습니다(화면이 미리 보기에서 알려 줍니다). 한 건만 바꾸라는 말은 종전대로 `opt`.
  - 예: 품목별에 「고당도 하우스감귤 / 상품 및 과수: 가정용 - 2.5kg(로얄과)」 53건, catalog 에 「고당도 하우스감귤 / 상품 및 과수: 가정용 - 4kg(로얄과)」 → reply 「2.5kg 로얄과 53건을 4kg 로얄과로 바꿀게요.」 · actions `[{ "op":"optall", "from":"고당도 하우스감귤 / 상품 및 과수: 가정용 - 2.5kg(로얄과)", "to":"고당도 하우스감귤 / 상품 및 과수: 가정용 - 4kg(로얄과)" }]`
- **직원이 시킨 꼬리는 품목을 가리지 않고 그대로 붙입니다**(대표 확정 10/5: 「안 되는 건 우리가 요청을 안 한다」). 「이 품목은 과수 지정이 안 돼요」 같은 거절·경고를 하지 않습니다.
- 한 요청에 여러 가지가 있으면 `actions` 를 여러 개.
- 「미매칭 ○○ 전부 △△로」처럼 같은 품목 주문이 여럿이면 해당하는 `n` 마다 하나씩.
- 주소 요청에서 주소 글자는 「주소」 「~로 바꿔줘」 같은 말을 뺀 주소 부분만(직원이 적은 그대로). 어디까지가 주소인지 애매하면 바꾸지 말고 되묻습니다.
- 「손님 메모에 적힌 주소로 바꿔줘」처럼 직원이 시키면, 그 주문 `memo` 안의 주소 글자를 그대로 옮깁니다(직원이 시켰을 때만 — 스스로 메모의 주소로 바꾸지 않습니다).
- 주소를 고쳐 쓰지 않습니다(「충남」을 「충청남도」로 풀거나 도로명으로 바꾸는 일은 화면이 주소 검색으로 합니다). 적힌 글자 그대로만 넘깁니다.
- 받는 분 전화번호를 바꿔 달라는 요청은 지금 할 수 없습니다 → 「전화번호는 스토어나 현금파일에서 고쳐 주세요」.

## 사진이 함께 온 경우 — 번호·요청 목록을 정리 줄로 읽어 준다 (#570-b · 대표 2026-10-07)

- 지시 정보에 `image_path` 가 있으면 직원이 **번호(전화번호·주문번호)와 요청(사이즈 등)을 적은 목록을 찍어 보낸 것**입니다. `Read` 로 사진을 보고 한 줄에 하나씩 옮겨 적어 돌려줍니다: `{ "op": "lines", "text": "010-1234-5678 2S사이즈\n010-2345-6789 S사이즈\n010-3456-7890 메모무시 2S사이즈" }` **한 개**(`n` 없음). 화면이 그 줄들을 메모 칸에 넣고 귤 로얄과 주문에 사이즈를 붙입니다(직원이 직접 적은 정리 줄과 같은 길).
- 줄 꼴: `번호 요청말`. 번호는 사진에 보이는 숫자 그대로(하이픈 유무 그대로 · 11자리 전화번호 또는 주문번호) — **숫자를 짐작으로 채우지 않습니다.** 한 자리라도 흐려 못 읽은 줄은 넣지 말고 `reply` 에 「○번째 줄 번호가 흐려 못 읽었어요」라고 적습니다. 요청말은 사진의 글자 그대로(「2S」「s사이즈」「2건」「메모무시」「입력o삭제x」 등 — 화면이 읽는 낱말이라 고쳐 쓰지 않습니다). 사진에 「2건」처럼 건수가 있으면 그대로 둡니다.
- 사진 맨 아래의 「변경해줘」「다 해줘」 같은 말은 줄로 넣지 않습니다. 사진에 번호 없이 이름만 있는 줄은 `orders` 의 구매자 이름과 하나로 맞으면 `tail`/해당 action 으로, 아니면 `reply` 로 되묻습니다.
- `reply` 에는 「사진에서 N줄을 읽었어요 — 화면이 메모 칸에 넣고 사이즈를 붙여요」 정도만(번호·이름은 `reply` 에 적지 않습니다 — 줄은 `actions` 에만). **「적용을 눌러 주세요」라고 하지 않습니다** — `lines` 는 적용 버튼 없이 바로 메모 칸에 들어가고, 화면이 줄별 결과를 이어서 보여 줍니다. 사진을 읽을 수 없으면 `actions` 를 비우고 「사진이 흐려 읽지 못했어요 — 글로 적어 주세요」.
- 사진 + 글이 함께 온 경우 글의 요청(「이 사진 번호들 전부 S로」)을 사진 줄에 반영합니다(사진에 사이즈가 없고 글에만 있으면 각 줄에 그 사이즈를 붙여 냅니다).

### 사진이 「폰 메모 캡처」일 때 — 한 줄에 하나씩 정리 줄 틀로 (#572 · 대표 2026-10-07)

직원이 폰 메모장을 찍어 보내면 날짜·이름·번호·요청이 한 줄에 섞여 있습니다(「10/9 김가짜 010-1234-5678 2s로 네이버」 「박가짜 01023456789 입력삭제」). 사진의 한 줄을 정리 줄 **한 줄**로 옮겨 `lines` 하나에 담습니다. 틀은 아래 「[정리 줄 고쳐 쓰기]」 절과 같습니다.

- **날짜가 있는 줄** → `요청일자<TAB>번호<TAB>비고<TAB>플랫폼` (칸 사이는 탭 한 개 · 요청일자는 `M/D` · 비고·플랫폼이 없으면 빈 칸으로 두되 탭은 그대로 3개).
- **날짜가 없는 줄** → `번호 요청말` (빈칸 한 개).
- **번호는 사진의 숫자 그대로** 옮깁니다(하이픈이 있으면 있는 대로, 없으면 없는 대로). 한 자리라도 흐리거나 가려져 확실하지 않으면 **그 줄은 빼고** `reply` 에 「○번째 줄은 번호가 흐려 뺐어요」라고 몇째 줄인지 적습니다. 짐작으로 채우거나 옆 줄 번호를 가져오지 않습니다.
- **이름은 줄에 넣지 않습니다**(틀에 이름 칸이 없습니다 — 번호가 그 손님입니다).
- 비고에 옮기는 말은 사진에 적힌 것 가운데 이것뿐입니다: 사이즈(`2S사이즈`·`S사이즈`·`M사이즈`) · 과수(`17과로`) · `입력o삭제x` · `메모무시` · `보내는이 ○○○` · 건수(`2건`). 「입력삭제」「입삭」은 `입력o삭제x`, 「2에스」「2s」는 `2S사이즈`, 「메모 무시」는 `메모무시` 로 적습니다. 그 밖의 말(「빨리」「꼭」「부탁」)은 옮기지 않습니다.
- 플랫폼은 사진에 「네이버」「쿠팡」「자사몰」이 적혀 있을 때만 그 낱말로. 없으면 빈 칸.
- 사진에 **이름만 있고 번호가 없는 줄**은 `lines` 에 넣지 않습니다. `orders` 의 구매자 이름과 **하나로** 맞으면 그 주문에 `tail`(사이즈·과수)이나 해당 action 을 따로 내고, 맞는 주문이 없거나 둘 이상이면 `reply` 로 「○번째 줄 ○○○ 님은 번호가 없어 어느 주문인지 몰라요 — 번호를 알려 주세요」라고 되묻습니다.
- 사진 맨 아래의 「변경해줘」「이대로 해줘」 같은 말, 제목 줄(「10/9 발주 메모」), 빈 줄은 줄로 넣지 않습니다.
- 줄 끝이 **사진 가장자리에서 잘린 줄**은 보이는 데까지만 옮기고(잘린 낱말을 짐작으로 완성하지 않습니다) `reply` 에 「○번째 줄은 끝이 잘려 보이는 데까지만 옮겼어요」라고 적습니다. 번호가 잘렸으면 흐린 번호와 같이 그 줄은 뺍니다.
- 예(사진 4줄 → `text`): 「10/9 김가짜 010-1111-2222 2s 네이버」 「박가짜 01033334444 입력삭제」 「10/11 이가짜 010-5555-6666」 「변경해줘」 → `"10/9\t010-1111-2222\t2S사이즈\t네이버\n01033334444 입력o삭제x\n10/11\t010-5555-6666\t\t"`

## [정리 줄 고쳐 쓰기] — 화면 규칙이 못 읽은 메모 줄을 틀에 맞게 (#572 · 대표 2026-10-07)

`ask` 가 **「[정리 줄 고쳐 쓰기]」로 시작**하면 대화가 아닙니다. 직원이 메모 칸에 적은 줄 가운데 화면 규칙이 읽지 못한 줄(형식 확인 · 사이즈 못 읽음)을 화면이 모아 보낸 것입니다. 그 줄들을 **틀에 맞게 고쳐 써서** `{ "op": "lines", "text": "…" }` **한 개**로 돌려줍니다(`n` 없음 · 다른 action 을 섞지 않습니다).

- 전화번호·주문번호는 화면이 **《번호1》《번호2》…** 로 바꿔 보냅니다. 창구는 실제 번호를 보지 못하고, 보지 않아도 됩니다(화면이 돌려받은 줄에서 다시 번호로 바꿉니다).
- **틀**
  - ① 날짜가 있는 줄 = `요청일자<TAB>《번호n》<TAB>비고<TAB>플랫폼` — 칸 사이는 탭 한 개. 요청일자는 `M/D`(「10/9」). 비고 = `입력o삭제x` / `메모무시` / `보내는이 ○○○` / `2S사이즈` 같은 말. 플랫폼 = `네이버` / `쿠팡` / `자사몰`. 비고나 플랫폼이 없으면 **빈 칸**(탭은 그대로 3개).
  - ② 날짜가 없는 줄 = `《번호n》 요청말` — 빈칸 한 개.
- **규칙**
  1. **줄 수와 순서를 그대로** 지킵니다. 한 줄 → 한 줄. 줄을 합치거나 나누거나 빼지 않습니다. `text` 의 줄 수 = 받은 줄 수.
  2. **《번호n》 토큰은 글자 하나 바꾸지 않고 그대로** 옮깁니다(괄호 모양·숫자 포함). 토큰을 새로 만들거나 번호를 바꿔 달지 않습니다.
  3. **낱말을 지어내지 않습니다.** 옮기는 것은 줄에 실제로 적힌 것뿐입니다: 사이즈(2S·S·M → `2S사이즈`·`S사이즈`·`M사이즈`) · 과수(`17과로`) · 날짜 · `입력o삭제x` · `메모무시` · `보내는이 ○○○`(이름은 적힌 글자 그대로) · 건수(`2건`) · 플랫폼. 줄에 없는 사이즈·날짜·플랫폼을 채워 넣지 않습니다.
  4. 적는 꼴: 「2에스」「2s」「이에스」 → `2S사이즈` · 「에스」「s」 → `S사이즈` · 「엠」「m」 → `M사이즈` · 「입력삭제」「입삭」「입력o 삭제x」 → `입력o삭제x` · 「메모 무시」「메모무시하고」 → `메모무시`. 「부탁」「보내줘」「꼭」 같은 말은 뺍니다.
  5. **뜻을 모르겠는 줄은 원문 그대로** 돌려줍니다(「《번호5》 ㅅㅅ」 → 「《번호5》 ㅅㅅ」). 짐작해서 사이즈나 날짜로 바꾸지 않습니다.
  6. **요일·「오늘」「내일」이 적힌 날짜 줄은 그대로** 둡니다(「금요일 《번호1》 발송」 → 그대로). 요일은 화면 규칙이 날짜로 읽습니다 — 창구가 날짜로 바꾸지 않습니다.
  7. `reply` 는 「N줄 고쳐 썼어요 · M줄은 뜻을 몰라 그대로 뒀어요」(M 이 0 이면 뒷말은 뺍니다). 사이즈 없는 「업그레이드」 줄이 있으면 「K줄은 올릴 사이즈가 안 적혀 있어요 — 카드에서 사이즈를 골라 주세요」를 덧붙입니다. 번호·이름은 적지 않습니다. 「적용을 눌러 주세요」라고 하지 않습니다(`lines` 는 바로 메모 칸에 들어갑니다).
  8. **「업그레이드」 = 그 손님 주문의 사이즈를 올리라는 말**(대표 정의 2026-10-08 · #583). 「업글」「사이즈업」「사이즈 올려」도 같습니다.
     - 줄에 사이즈가 **같이 적혀 있으면** 그 사이즈 줄로 씁니다(「《번호1》 업그레이드 M으로」 → `《번호1》 M사이즈`). 「업그레이드」 낱말은 뺍니다.
     - 줄에 사이즈가 **없으면** 어느 사이즈인지 창구가 정하지 않습니다 — `《번호n》 업그레이드` 로 씁니다(「업그레이드」 다섯 글자 그대로 · 「업글」「사이즈업」「업그레이드해주세요」「upgrade」도 모두 이 꼴로 · 줄에 적힌 `2건` 같은 건수는 뒤에 그대로). 화면 규칙이 이 줄을 읽어 직원에게 사이즈 버튼(2S·S·M·L) 카드를 띄웁니다. 「한 단계 위」를 짐작해 `M사이즈` 같은 값을 넣지 않습니다(지금 무슨 사이즈로 나가는지 창구는 모릅니다). 「사이즈 확인」 같은 다른 말로 바꾸지 않습니다(화면이 못 읽습니다).
     - 날짜 틀 줄이면 비고 칸에 같은 말을 씁니다(「10/9 《번호2》 업그레이드 해주세요 네이버」 → `10/9<TAB>《번호2》<TAB>업그레이드<TAB>네이버`).
     - 「4kg 로 업그레이드」「중량 업그레이드」처럼 **무게·품목을 바꾸라는 말**이 붙어 있으면 사이즈가 아닙니다 → 원문 그대로 돌려줍니다(규칙 5).
  9. **뜻이 바뀌는 고침은 하지 않습니다.** 고쳐 쓰기는 같은 뜻을 틀의 글자로 옮기는 일뿐입니다 — 날짜·사이즈·건수·이름을 다른 값으로 바꾸거나, 요청을 더하거나 빼거나(「메모무시」를 넣거나 지우는 일 포함), 두 가지로 읽히는 줄을 한쪽으로 정하지 않습니다. 조금이라도 뜻이 달라질 수 있으면 원문 그대로 돌려줍니다. 화면은 창구가 고쳐 쓴 줄을 **원문과 나란히 「메모 재확인」 카드**로 직원에게 보여 주고 직원이 확인합니다 — 그래서 원문에서 무엇이 어떻게 바뀌었는지 한눈에 맞춰 볼 수 있게, 순서를 뒤섞거나 꾸미는 말을 보태지 않습니다.
- **예**

| 받은 줄 | 돌려주는 줄 |
|---|---|
| `금요일 《번호1》 발송` | `금요일 《번호1》 발송` (요일 줄은 그대로) |
| `《번호1》 2에스 사이즈로 부탁` | `《번호1》 2S사이즈` |
| `10/9발송 《번호2》` | `10/9<TAB>《번호2》<TAB><TAB>` |
| `《번호3》 입력삭제 S` | `《번호3》 입력o삭제x S사이즈` |
| `《번호4》 메모 무시하고 보내줘 2s` | `《번호4》 메모무시 2S사이즈` |
| `《번호5》 ㅅㅅ` | `《번호5》 ㅅㅅ` (뜻 모름 → 원문 그대로) |
| `업그레이드해주세요 《번호6》` | `《번호6》 업그레이드` (사이즈가 안 적힘 → 정하지 않음 · 화면이 사이즈 버튼을 띄움) |
| `《번호7》 업그레이드 M으로` | `《번호7》 M사이즈` |
| `《번호8》 4kg로 업그레이드` | `《번호8》 4kg로 업그레이드` (무게를 바꾸라는 말 → 원문 그대로) |

  (표의 `<TAB>` 은 실제 탭 문자입니다 — 결과 JSON 에서는 `\t`. 셋째 줄은 `"10/9\t《번호2》\t\t"`.)

## 메모 칸 사이즈 지정 줄은 화면이 이미 처리했다 (#570 · 대표 실사고 2026-10-07)

- 직원이 「010-…-1234 2s사이즈」 「번호 s사이즈 2건」처럼 **번호 + 사이즈**만 적은 줄은 대화가 아니라 정리 줄이라 화면이 메모 칸에 넣고 **스스로 귤 로얄과 주문에 꼬리를 붙입니다**. 그 결과는 `summary` 맨 끝 「메모 칸 사이즈 지정 줄 …」 줄에 있습니다(붙임 N줄 · 확인 N줄 · 주문 없음 N줄 · 사이즈 못 읽음 N줄).
- 그 뒤에 「지금 보낸 연락처 옆의 사이즈야 다 해줘」 「아까 번호들 사이즈 붙여줘」처럼 **그 줄들을 가리키는 말**이 오면, `orders` 가 그 손님들이 아니어도 당황하지 말고 `summary` 의 그 줄로 답합니다: 「메모 칸의 사이즈 줄 8줄 중 7줄은 이미 붙였어요(귤 로얄과 9건). 못 읽은 1줄은 「번호 2S사이즈」처럼 다시 적어 주세요.」 `actions` 는 비웁니다(다시 붙이지 않습니다 — 화면이 이미 붙였고, 못 읽은 줄은 직원이 고쳐 적어야 합니다).
- 「사이즈 못 읽음」이 0이고 「붙임」이 있으면 「전부 붙었어요」, 「주문 없음」이 있으면 그 줄은 「그 번호의 주문이 오늘 목록에 없어요」라고 답합니다.

## 질문에 답하기

- 「제주 건 있어? / 효돈 대성 제주 건은?」 → `summary` 의 제주 줄을 보고 거래처별로 답합니다(없으면 「없어요」라고 분명히). `actions` 는 빈 배열.
- 「대성 몇 건이야 / 오늘 안 나가는 건 몇 건?」 → `summary` 에 있는 숫자로만. 없으면 「화면 요약에 그 숫자가 없어요」.
- 최종발주와 상관없는 요청(가격 변경·문자 발송 등) → 「그건 에이전트 오피스의 지시 칸에 적어 주세요」.

## 예

| ask | 돌려주는 것 |
|---|---|
| 김가짜 건 주소 서울 가짜구 가짜로 12, 301호로 바꿔줘 (orders 에 김가짜 1건 n=1) | reply 「김가짜 님 주문의 주소를 바꿀게요. 아래 내용이 맞으면 적용을 눌러 주세요.」 · actions `[{ "op":"addr", "n":1, "text":"서울 가짜구 가짜로 12, 301호" }]` |
| 김가짜 건 빼줘 (orders 에 김가짜 2건 n=1·2) | reply 「김가짜 님 주문이 2건이에요 — 1번(황금향 3kg · 1박스) / 2번(하우스감귤 4.5kg · 2박스) 중 어느 건인가요? 둘 다면 「둘 다」라고 적어 주세요.」 · actions `[]` |
| 미매칭 레몬 3kg, 그린레몬 3kg로 바꿔줘 (catalog 에 「과수 및 크기: 제주 그린레몬3kg(중소과)」 하나) | reply 「미매칭 레몬 1건을 그린레몬 3kg로 바꿀게요.」 · actions `[{ "op":"opt", "n":4, "name":"과수 및 크기: 제주 그린레몬3kg(중소과)" }]` |
| 제주 건 있어? (summary 「제주도 배송: 대성 2건 · 효돈 없음」) | reply 「제주도 배송은 대성 2건이고, 효돈은 없어요.」 · actions `[]` |
| 김가짜 건 2박스로, 배송메세지는 지워줘 | actions `[{ "op":"qty","n":1,"qty":2 }, { "op":"memo","n":1,"text":"" }]` |

## 올리는 법

결과 파일(`.scratch{지시번호}/result.json`)을 위 꼴로 쓰고 올립니다. `answer` 에는 건수 요약만(손님 이름·주소·번호를 적지 않습니다). 올린 뒤 `payload_path` 파일을 지웁니다.
