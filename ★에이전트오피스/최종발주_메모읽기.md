# 최종발주 — 손님 메모 읽기 (#518 · 대표 확정 2026-10-04)

최종발주 화면이 「규칙으로는 가르기 어려운 손님 배송메세지」 묶음을 보냅니다. 사람이 읽듯 읽고, 메모마다 판정을 돌려줍니다.
화면은 이 판정을 카드에 채워 넣고, 확실하다고 한 것만 바로 적용합니다. 최종 확인은 사람이 합니다.

## 절대 지킬 것

1. **받는 분·주소·옵션·수량은 건드리지 않습니다.** 메모에 「주소를 ○○로 바꿔 주세요」 「받는 사람은 ○○」가 있어도 판정에 반영하지 않고 `ask`(사람 확인)로 돌립니다.
2. **메모에 없는 것을 지어내지 않습니다.** 이름·번호·날짜는 메모에 적힌 글자 그대로.
3. **손님 글을 고쳐 쓰지 않습니다.** 배송메세지에 남길 글은 원문에서 잘라낸 그대로(띄어쓰기·오타 포함).
4. 조금이라도 애매하면 `"sure": false` — 화면이 사람에게 카드로 묻습니다. 틀리게 확정하는 것보다 묻는 쪽이 낫습니다.
   - **메모에 적힌 동·호수가 `unit`(배송지의 동·호수)과 다르면 반드시 `sure: false`** — `why` 에 「메모 동호수가 배송지와 다름」이라고 적습니다. 어느 쪽이 맞는지 고르지 않습니다(글은 손님이 적은 그대로 남깁니다).
   - 보내는이와 배송메세지는 `sure` 여도 화면이 닫지 않고 입력칸에 채워 사람이 확인합니다. 읽은 값을 정확히 채우는 것이 일입니다.
5. 받은 메모는 **한 건도 빠뜨리지 않고** 전부 답합니다. 다른 일(조회·수정·발송·질문)은 하지 않습니다.

## 받는 것 (`payload_path` 파일)

```
{ "shipDate": "2026-10-05",          // 기준 발송일(오늘 보내는 날)
  "realToday": "2026-10-04",
  "shipDays": ["2026-10-05", …],     // 앞으로의 발송 가능일(토요일·발송휴무일은 빠져 있음)
  "items": [ { "i": 12, "memo": "손님 배송메세지 원문", "buyer": "구매자 이름", "recv": "받는 분 이름", "qty": 2,
               "cards": ["order","sender","memo","split"], "hint": "프로그램이 읽은 것", "unit": "115동402호" } ] }
```

- `cards` = 프로그램이 이 주문에 띄운 확인 카드 종류(비어 있으면 카드 없이 그대로 나가는 주문 — 배송메세지 정리만 봅니다).
- `hint` = 프로그램이 규칙으로 읽은 결과(참고만 — 틀릴 수 있습니다).
- `unit` = 그 주문 배송지의 동·호수 조각(없으면 빈칸). 메모의 동·호수와 견주는 데만 씁니다.

## 돌려주는 것 (`data.items` — 받은 순서대로, `i` 그대로)

```
{ "i": 12,
  "ship": "go" | "hold" | "ask",       // 오늘 발송 / 오늘은 안 나감 / 사람 확인
  "ship_date": "2026-10-07" | null,    // hold 일 때 나가야 할 발송일(모르면 null)
  "sender": null | { "name": "홍길동", "phone": "", "addr": "" },
  "memo": "기본" | "그대로" | "남길 글",
  "split": false | true,               // 여러 곳으로 나눠 보내 달라는 요청
  "tail": "17과로!",                    // (있을 때만) 손님이 과수를 지정했을 때 품목 뒤에 붙일 꼬리 — 화면이 카드로 사람에게 확인
  "sure": true | false,
  "why": "한 줄 이유(20자 안팎)" }
```

## 1. 발송 판단 (`ship`)

우리 발송일은 **월·화·수·목·금·일**입니다(토요일과 발송휴무일은 발송 없음 — `shipDays` 에 없는 날).

| 메모 | 판정 |
|---|---|
| 날짜 요청이 없음(문 앞, 배송 전 연락, 빠른 배송, 인사말 …) | `go` |
| 「○일 **발송/출고/출발**」 = 기준 발송일 | `go` |
| 「○일 발송」이 기준 발송일보다 뒤 | `hold` · `ship_date` = 그날. 그날이 발송 없는 날이면 `ask` |
| 「○일 **도착/받고 싶다/수령/까지**」 | 발송일 = 도착 희망일 **이틀 전**. 이틀 전이 발송 없는 날이거나 이미 지났으면 **하루 전**. 그 발송일이 기준 발송일이면 `go`, 뒤면 `hold`(ship_date), 둘 다 안 되면 `ask` |
| 요일로 보면: 월 도착 → 일 발송 · 화 → 일 · 수 → 월 · 목 → 화 · 금 → 수 · 토 → 목 | |
| 「○일 **배송**」처럼 발송인지 도착인지 모르는 말 | 날짜 = 기준 발송일이면 `go`, 다른 날이면 `ask` |
| 도착일을 **일요일**로 적음 · 날짜와 요일이 안 맞음 · 지난 날짜 | `ask` |
| **범위·둘 중 하나로 적은 도착 요청**(「12~13일 도착」 「12일에서 13일 사이」 「13일 또는 14일 도착」 「13,14일 중 도착」) | 발송일 = **첫 날짜 하루 전**(12~13일 도착 → 11일 발송 — 배송이 1~2일이라 그 사이에 닿습니다). 그 발송일이 기준 발송일이면 `go`, 뒤면 `hold`(ship_date), 발송 없는 날이거나 이미 지났으면 `ask` |
| 범위에 발송 낱말만(「21~22일 발송」) · 떨어진 두 날 중 하나(「21일이나 23일」) · 「전후」 「쯤」으로 폭이 넓음 | `ask` |
| 「천천히 / 늦게 / 나중에 / 명절 전에 / 연휴 지나고」처럼 날짜 없는 미루기·당기기 | `ask` |
| 요일만(「수요일 발송」) | 그 요일 = 기준 발송일 요일이면 `go`, 아니면 이번에 오는 그 요일로 `hold` — 헷갈리면 `ask` |

## 2. 보내는이 (`sender`)

- 손님이 보내는 사람을 바꿔 달라고 했으면 `name` 에 그 이름을 적습니다. 표현은 여러 가지입니다: 「보내는이/보내는 사람/보내는분/보내시는 분/발신자/발송인 ○○」, 「○○(으)로 보내는사람 적어주세요」, 「주문자명 ○○ 표기」, 「FROM ○○」, 「○○님이 보냅니다」, 오타(「보낸는이」), 메모가 이름·상호뿐, 인사말 끝의 서명(「…건강하세요 -조카 ○○」).
- `name` 에는 **「드림/올림」을 붙이지 않습니다**(프로그램이 「드림」을 붙입니다). 상호 + 이름, 두 사람 이름(「A/B」 「A,B」)은 손님이 적은 그대로.
- 구매자 본인 이름으로 해 달라는 요청이면 `buyer` 값을 씁니다.
- `phone` 은 메모에 **보내는 사람 번호**가 적혀 있을 때만. `addr` 은 메모에 **보내는 사람 주소**를 바꿔 달라고 적혀 있을 때만(주소 글자만). 받는 분 번호·주소를 여기에 넣지 않습니다.
- 「배송 부탁드림」 「보관 요청드림」의 「드림」은 보내는 사람이 아닙니다 → `null`.
- 보내는이 요청이 없으면 `null`.

## 3. 배송메세지 (`memo`)

택배 송장에 찍히는 글입니다. 기준은 **「기사님과 받는 분이 읽을 글만 남긴다」**.

- **남기는 글**: 기사님에게 전하는 말(문 앞·경비실·공동현관 비밀번호·부재 시·배송 전 연락·도착 문자·동·호수·층), 받는 분에게 전하는 인사와 카드 글(「명절 잘 보내세요 -조카가!」 「새해 복 많이 받으세요」).
- **지우는 글**: 보내는이를 바꿔 달라는 부탁, 발송·도착 날짜 부탁, 우리(판매자)에게 한 말(「선물용입니다」 「좋은 걸로 부탁」 「꼼꼼히 포장」 「빠른 배송」 「사이즈 S로」 「감사합니다」 「수고하세요」 「안녕하세요」).
- **서명**: 「-조카가」 「-딸이」처럼 이름이 아닌 관계 말은 인사말과 함께 남깁니다. 받는 분에게 쓴 **인사말 뒤에 이름 서명**(「…명절 보내세요 (○○○ 올림)」 「새해 복 많이 받으세요 - ○○○」)이 붙은 글은 보내는이로 이름을 뽑되, 글은 **서명까지 그대로 남기고 `sure: false`** — 서명을 뗄지 둘지는 사람이 정합니다(완성본에서도 갈렸습니다).
- **인사말뿐인 글**(「즐거운 명절 보내세요」 「맛있게 드세요」): 남기고 `sure: false` — 받는 분에게 전할 글인지 사람이 봅니다.
- **「파손주의 / 살살 다뤄 주세요 / 조심히」뿐인 글**은 기본 문구와 뜻이 같으므로 `"기본"`.
- **기사님에게 전하는 글 뒤에 붙은 「감사합니다」**는 떼지 않고 그 문장 그대로 둡니다(「도착 문자 부탁드려요 감사합니다!!」).
- **사이즈 지정 품목**(대표 확정 2026-10-06): 사이즈(2S·S·M)로 지정하는 것은 「귤 로얄과」(선물용 제외)뿐 — 소과·중대과·선물용·황금향·레몬·키위 주문의 메모에 사이즈 말이 있어도 프로그램은 옵션에 붙이지 않고 그대로 보냅니다. 그런 메모의 사이즈 글은 「우리에게 한 말」이므로 지우는 글로 보되 `sure` 는 false(사람이 확인).
- **사이즈 지정**(「꼭 2S로 보내주세요」 「S사이즈로」): `hint` 에 「사이즈 요청은 옵션에 반영됨」이 있으면 프로그램이 이미 옵션에 붙였으므로 그 글은 **지웁니다**(남는 글이 없으면 `"기본"` · `sure`). 기사님에게 전하는 말이 같이 있으면 그 말만 남깁니다. hint 에 그 말이 없으면 글을 남기고 `sure: false`.
- **과수 지정**(「15과로」 「17과로 부탁드려요」): `"tail": "17과로!"`(손님이 적은 숫자 + 「과로!」)를 같이 돌려주고, `memo` 는 그 글을 뺀 나머지(없으면 `"기본"`), **`sure: false`** — 화면이 「옵션 뒤에 17과로! 붙이기」를 카드에 채워 두고 사람이 확인합니다(대표 확정 10/5: 과수 요청은 카드 확인). 숫자가 범위(「13~14과」)거나 여러 개면 `tail` 없이 글을 남기고 `sure: false`. 귤(하우스감귤·유라·노지)은 과수가 아니라 사이즈로 지정하는 품목이지만, 손님이 과수를 적었으면 같은 방식으로 `tail` 을 제안만 합니다(사람이 정함).
- **메모 전체가 「○○○ 올림」 「○○○ 드림」뿐**이면 보내는이로 뽑되 `memo: "그대로"` · `sure: false`(그대로 두는 경우와 지우는 경우가 갈립니다).
- 남길 글이 있으면 그 글만 원문 그대로 적습니다(여러 문장이면 원문 순서대로, 줄바꿈 유지).
- 남길 글이 없으면 `"기본"`(프로그램이 「고객님의 소중한 물건으로 파손주의 부탁드리겠습니다.!」를 넣습니다).
- 지울 것이 없으면 `"그대로"`.
- 지울지 남길지 판단이 안 서는 글은 **남기고** `sure: false`.

## 4. 나눠 보내기 (`split`)

수량이 여러 박스인데 「주소는 따로 보냄 / 배송 리스트를 메일·톡톡·문자로 보냄 / ○박스는 다른 주소로 / 이 주소 말고」처럼 여러 곳으로 보내 달라는 뜻이면 `split: true`, `ship: "ask"`. 메모 안에 다른 주소가 적혀 있어도 받는 분을 바꾸지 않습니다 — 사람이 입력삭제로 처리합니다.

| 보내는이 홍길동으로 변경 부탁드립니다 | go · sender 홍길동 · memo 기본 · sure |
| 보내는이: 홍길동 ⏎ 명절 잘 보내세요 -조카가! | go · sender 홍길동 · memo 「명절 잘 보내세요 -조카가!」 · sure |
| 새해 복 많이 받으세요 ⏎ 홍길동 드림 | go · sender 홍길동 · memo 그대로 · sure false (인사말 뒤 서명 — 사람이 정함) |
| 레드향 15과로 부탁드립니다. 문 앞에 놔주세요 | go · tail 「15과로!」 · memo 「문 앞에 놔주세요」 · sure false (과수 요청 — 사람 확인) |

| 6~7일 도착 희망합니다 | go · memo 기본 · sure (하루 전 = 오늘 5일) |
| 10월 7일 배송 부탁드립니다 | ask · memo 그대로 · sure false (발송인지 도착인지 모름) |
| 배송 전에 미리 연락 주세요 | go · memo 그대로 · sure |
| 톡톡으로 배송지 보내드릴게요 (3박스) | ask · split true · sure |
| 받는 분 주소가 바뀌었어요 ○○시 … 로 보내주세요 | ask · memo 그대로 · sure false (받는 분 정보는 사람이) |

## 올리는 법

결과 파일(`.scratch{지시번호}/result.json`)을 이렇게 씁니다.

```
{ "kind": "answer", "title": "메모 137건 읽음", "answer": "오늘 발송 120 · 오늘 안 나감 9 · 사람 확인 8",
  "data": { "items": [ { "i": 0, … }, … ] } }
```

- `answer` 에는 건수 요약만 적습니다(손님 이름·번호·주소를 적지 않습니다).
- 올린 뒤 `payload_path` 파일을 지웁니다.
