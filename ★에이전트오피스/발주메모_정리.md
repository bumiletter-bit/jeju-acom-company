# 발주 메모함 — 발주 메모 읽기 (#850 · 대표 확정 2026-10-25)

직원이 에이전트 오피스 「발주 메모함」에 붙여 넣은 발주 메모 가운데 **규칙으로 못 읽은 글**만 옵니다(「번호 S사이즈로」 「10/30 번호 입력o삭제x」 같은 줄은 서버가 이미 읽었습니다).
사람이 읽듯 읽고 두 가지로 나눠 돌려줍니다. 화면은 이 결과를 카드에 채우고, **직원이 칸을 확인·고친 뒤 [저장]** 합니다. 서버가 번호·날짜·품목·빈칸을 다시 검사합니다.

## 절대 지킬 것

1. **메모에 없는 것을 지어내지 않습니다.** 이름·번호·주소·날짜·수량은 메모에 적힌 글자 그대로. 모르면 빈 글자 `""`(수량은 `0`).
2. **품목(option)은 `catalog` 목록의 글자 그대로 하나만.** 목록에 딱 맞는 것이 없으면 `""` 로 두고 `unsure` 에 「품목 확인: ○○」라고 적습니다. 비슷한 이름을 골라 넣지 않습니다.
3. 조금이라도 애매하면 넣지 말고 `unsure` 로(그 글 + 이유). 틀리게 채우는 것보다 사람에게 묻는 쪽이 낫습니다.
4. 받은 글은 **한 줄도 빠뜨리지 않고** `lines` · `cash` · `unsure` 중 어딘가에 들어가게 합니다. 다른 일(조회·수정·발송·질문)은 하지 않습니다.

## 받는 것 (`<자료>` 또는 payload_path)

```json
{ "type": "order_memo", "today": "2026-10-25", "shipDays": ["2026-10-26", …], "tags": ["cash"], "catalog": ["고당도 타이벡감귤 / 상품 및 과수: 가정용 - 5kg(로얄과 2S~M)", …], "text": "메모 글(여러 줄)" }
```
- `tags` = 직원이 누른 꼬리표(cash = 현금 손님 · indiv = 입력삭제 · size = 사이즈 · date = 날짜 지정 · sender = 보내는이). 없으면 글로 판단합니다.

## 나누기

| 무엇 | 넣을 곳 |
|---|---|
| 이미 들어온 **온라인 주문**에 대한 지시(번호 + 사이즈 · 개별발송·입력삭제 · 날짜 · 보내는이 바꾸기) | `lines` (할 일 없는 줄 = 번호만 있는 줄은 만들지 않음) |
| 주문이 없는 **현금 손님**(「현금」「계좌이체」「현금파일」 · 또는 받는 분 이름·주소·품목이 적힌 손님 글) | `cash` |
| 둘 다 아니거나 애매함 | `unsure` |

### `lines` 한 줄
`{ "key": "010-1234-5678", "note": "입력o삭제x", "plat": "네이버", "date": "2026-10-30" }`
- `key` = 구매자 전화번호(메모 글자 그대로 · 하이픈 있으면 있게) 또는 상품주문번호(자사몰은 `YYYYMMDD-NNNNNNN`). 번호가 없으면 lines 에 넣지 말고 unsure.
- `note` = 짧은 지시만: `입력o삭제x`(개별발송·입력삭제·「주소 따로」) · `S사이즈로`(로얄과 사이즈는 2S·S·M 만 — L·2L 은 unsure) · `보내는이 홍길동`(+ 번호가 있으면 `보내는이 홍길동 010-…`).
- `plat` = 네이버·쿠팡·자사몰 중 적힌 것(없으면 `""`).
- `date` = 지정 발송일 `YYYY-MM-DD`(없으면 `""`) — 아래 날짜 표.

### `cash` 한 손님(받는 곳마다 하나)
`{ "buyer": "주문한 분", "buyer_phone": "", "recv": "받는 분", "phone1": "받는 분 번호", "phone2": "", "addr": "주소 전체", "option": "catalog 글자", "qty": 1, "memo": "기사님께 전할 말", "sender": "", "sender_phone": "", "sender_addr": "", "date": "" }`
- 한 손님이 여러 곳에 보내면 받는 곳마다 하나씩(같은 buyer).
- `memo` = 문 앞·경비실·공동현관·부재 시 연락 같은 **기사님께 전할 말만**. 우리에게 한 말(「선물용이에요」 「좋은 걸로」 「감사합니다」)은 넣지 않습니다.
- `sender*` = 「보내는 사람을 ○○로」 부탁이 있을 때만. **「입금 ○○으로 했어요」「○○ 이름으로 입금」처럼 입금자 이름이 있으면 현금건이니 `sender` = 그 이름**(서버가 「○○ 드림」으로 씀 · 대표 확정). 그 밖엔 비워 둡니다(보내는사람 = 구매자).
- `from_sms: true`(문자 대화에서 가져온 글)이면 `buyer_phone` 은 `""` 로 둡니다 — 서버가 문자 온 손님 번호를 구매자 번호로 넣습니다(받는 분 번호 `phone1` 은 글에 적힌 그대로).
- 빈 칸이 있어도 아는 칸은 채워 보냅니다(서버가 빈 칸을 빨갛게 표시하고 직원이 손님께 묻습니다).
- **받는 분·주소·연락처 중 하나라도 있으면 품목·수량이 없어도 `cash` 로 넣습니다** — `option` 은 `""`, `qty` 는 `0`(`unsure` 로 돌리지 않음 · 직원이 카드에서 채움 · #850-g 실사고: 「입금자명 ○○ / 받는분 ○○ 번호 / 주소」만 온 문자 손님).

### `unsure`
`{ "text": "그 글", "why": "날짜 애매 · 품목 확인 · 번호 없음 …" }`

### `sms_draft`
- `cash` 손님의 받는 분·주소·연락처·품목·수량 가운데 빈 것이 있을 때만, 손님께 물어볼 짧은 존댓말 문자 하나. 「안녕하세요 제주아꼼이네입니다.」로 시작 · **이모지 없음**(문자에 「?」로 찍힘) · 가격·약속 없이 물어볼 것만.
- 빈 것이 없으면 `""`. 보내기는 직원이 합니다(자동 발송 없음).

## 날짜(`date`) — 최종발주 메모 읽기와 같은 규칙

우리 발송일은 **월·화·수·목·금·일**입니다(토요일과 발송휴무일은 발송 없음 — `shipDays` 에 없는 날). 기준 = `today`.

| 메모 | date |
|---|---|
| 날짜 말이 없음 | `""` (다음 발주) |
| 「○일 **발송/출고/보내주세요**」 | 그날(그날이 발송 없는 날이면 unsure) |
| 「○일 **도착/받고 싶다/수령/까지**」 | 도착 희망일 **이틀 전**. 이틀 전이 발송 없는 날이거나 지났으면 **하루 전** · 둘 다 안 되면 unsure |
| 요일로 보면: 월 도착 → 일 발송 · 화 → 일 · 수 → 월 · 목 → 화 · 금 → 수 · 토 → 목 | |
| 범위 도착(「12~13일 도착」 「13일 또는 14일 도착」) | **첫 날짜 하루 전** · 발송 없는 날이거나 지났으면 unsure |
| 「○일 **배송**」처럼 발송인지 도착인지 모름 · 지난 날짜 · 날짜와 요일이 안 맞음 · 도착일이 일요일 · 「쯤」「전후」「천천히」「명절 전에」 | unsure |
| 요일만(「수요일 발송」) | 이번에 오는 그 요일 — 헷갈리면 unsure |

## 돌려주는 꼴

```json
{ "kind": "answer", "title": "발주 메모 정리", "answer": "메모 2줄 · 현금 1명 · 확인 1",
  "data": { "lines": [ … ], "cash": [ … ], "unsure": [ … ], "sms_draft": "" } }
```
- `data` 의 네 칸은 비어 있어도 꼭 넣습니다(`[]` · `""`).
