# 문의시나리오 DB 전환 — 대표님 실행 절차

> 작성 2026-07-25 · 코드 작업은 전부 완료된 상태. 아래 순서대로만 하시면 됩니다.
> 상태: 회사프로그램 v5.9.55 배포됨 · 시나리오 47건 DB 이관·검증 완료(전건 바이트 일치) · 톡톡봇 코드는 커밋만 된 상태(push 대기)

## ① 토큰 만들기 (1개 값을 3곳에 넣습니다)

PowerShell에서 실행해 랜덤 토큰 1개를 만듭니다:

```powershell
-join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })
```

나온 64자리 문자열을 복사해 두세요. (= `여기에_토큰값`)

## ② Render 환경변수 등록 (2개 서비스)

1. **회사프로그램 서비스(jeju-acom-company)** → Environment:
   - `SCENARIO_API_TOKEN` = `여기에_토큰값`
   - 저장하면 자동 재시작. 이걸 넣기 전까지 시나리오 API는 잠김(503) 상태라 서두르지 않아도 됩니다.
2. **톡톡봇 서비스** → Environment:
   - `COMPANY_API_URL` = `https://jeju-acom-company.onrender.com` (회사프로그램 실제 주소)
   - `SCENARIO_API_TOKEN` = `여기에_토큰값` (①과 동일값)
   - `SCENARIO_SOURCE` = `code`  ← **처음엔 반드시 code!** (기존 하드코딩 그대로 = 무중단)

## ③ 톡톡봇 마지막 git 배포 (이번 1회만)

PowerShell에서:

```powershell
cd "C:\Users\전승범\OneDrive\문서\★제주아꼼이네 톡톡봇"
git push
```

→ Render가 자동 재배포. **SCENARIO_SOURCE=code라서 손님 응답은 지금과 100% 동일합니다** (검토로 프롬프트 1718자 바이트 일치 확인).
이 push 이후로는 시나리오 문구 수정에 배포가 영영 필요 없습니다 — [문의 관리] 화면 저장이 끝.

## ④ 스위치 (배포 안정 확인 후, 아무 때나)

- 이미 로컬에서 **47건 전수 비교 전건 일치** 확인됨. 원하시면 실서버로 한 번 더:
  톡톡봇 폴더에서 `node scripts/compare-scenarios.js` (봇 폴더 .env에 COMPANY_API_URL·SCENARIO_API_TOKEN 필요)
  → "✅ 전체 47건 완전 일치 — 스위치 가능" 나와야 함.
- Render **톡톡봇 서비스** → Environment → `SCENARIO_SOURCE` = `db` 로 변경 → 저장(재시작 몇 초, 배포 아님).
- 이제부터 [문의 관리] 화면에서 저장 → **5분 내** 톡톡봇 실응답에 반영.

## ⑤ 전환 후 확인 체크리스트 (지시문 STEP5)

- [ ] 화면에서 답변 문구 하나 수정 → 5분 뒤 톡톡으로 그 질문 → 바뀐 문구로 응답
- [ ] 새 시나리오 추가 → 봇이 인식
- [ ] 시나리오 하나 사용 OFF → 그 응답 중지
- [ ] (대표 계정) 전체 자동응답 OFF → 봇 시나리오 응답 전면 중지 (담당자 연결 흐름만)
- [ ] [문의 관리] 수정 이력에 누가·언제·뭘 바꿨는지 기록됨

## ⑥ 문제가 생기면 (되돌리기)

- Render 톡톡봇 서비스에서 `SCENARIO_SOURCE` = `code` 로 되돌리면 **몇 초 만에 기존 하드코딩으로 복귀**합니다. 이게 비상 스위치입니다.
- 회사프로그램 API가 죽어도 봇은 **마지막으로 성공한 시나리오 캐시**로 계속 응답합니다(봇이 회사프로그램에 종속되지 않음). 캐시조차 없는 최초 기동 실패 시에만 텔레그램 알림 1회(톡톡봇 서비스에 TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID 설정 시) + 하드코딩 폴백.

## ⑦ 판매현황·가격 탭 이전 (2026-07-25 추가 — v5.9.56)

> 회사프로그램 [문의 관리] > **판매현황·가격 탭**은 이미 배포되어 사용 가능합니다(저장 → 봇 1분 내 반영).
> 아래는 톡톡봇 쪽 정리 배포(시즌 하드코딩 제거) 절차입니다.

1. **톡톡봇 정리 배포** — PowerShell:
   ```powershell
   cd "C:\Users\전승범\OneDrive\문서\★제주아꼼이네 톡톡봇"
   git push
   ```
   → 손님 답변 무변화(검토 확인: 코드 시드 36건 = DB 36건 완전 일치 상태에서 제거). 이 배포로 "화면에서 삭제해도 재시작 때 부활" 함정이 사라지고, 탭에서 삭제한 품목이 봇 답변에서도 빠집니다.
2. **검증 체크리스트**:
   - [ ] 탭2에서 가격 수정 → 1~2분 뒤 톡톡 "가격" 질문에 반영
   - [ ] 상태를 품절로 → 판매현황 답변에 품절 표시
   - [ ] (대표) 품목 삭제 → 봇 답변에서 사라짐 + 봇 재시작에도 부활 안 함
   - [ ] 같은 이름 재추가 → 복구되어 다시 표시
   - [ ] 수정 이력 기록 확인
3. **기존 관리 페이지 은퇴**: 검증 끝나면 Render **톡톡봇 서비스** → 환경변수 `PRODUCTS_PAGE` = `off` (재시작만, 배포 아님). 이후 /products 접속 시 "회사프로그램으로 이전됨" 안내만 표시. 되돌리려면 `on` 또는 변수 삭제. **/unmatched(문의 로그)는 계속 사용 가능.**
4. ⚠️ 시나리오 push(③)를 아직 안 하셨다면 이 정리 배포와 **한 번의 push로 같이** 나갑니다 — 별도 작업 불필요.

## 알아두실 것

- **영업시간외 문구(0번)**: DB에 넣어두긴 했지만, 현재 톡톡봇은 영업시간외 자동안내를 **보내지 않는 상태**(코드에서 미사용)라 화면에서 0번을 수정해도 봇 동작에는 영향이 없습니다. 나중에 영업시간외 자동안내를 다시 켜고 싶으시면 말씀해주세요 — DB 0번을 읽도록 연결해 드립니다.
- 하드코딩 제거(scenarios.js 정리)는 db 전환 후 **며칠 안정 확인되면** 별도로 요청해 주세요(정리 배포 1회). 그 전까지는 비상 폴백으로 남겨둡니다.
- API가 오래 죽어 있어도 봇은 오래된 캐시로 계속 응답합니다(알림은 캐시가 아예 없을 때만) — 화면 수정이 봇에 반영 안 되는 것 같으면 회사프로그램(Render) 상태부터 확인.
