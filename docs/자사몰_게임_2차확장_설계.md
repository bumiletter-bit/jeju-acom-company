## 1. 미니게임 신설 (애니팡류)

- **보상**: 승리·퀘스트 클리어 시 **물 또는 룰렛권 1회** 지급
- **원칙**: 물은 **게임에서 이겨야만** 나온다 — 접속·시청만으로는 물이 나오지 않는다
- 미정(대표 확정 필요): 게임 종류·난이도·1회 플레이 시간·승리 판정 기준·보상 수량

## 2. 목숨(게임 횟수) 시스템

- 플레이는 **목숨**을 소모하고, 목숨이 떨어지면 아래 3경로로 회복한다.

| 회복 경로 | 조건 |
|---|---|
| ① 사이트 둘러보기 | 몰 내 탐색 |
| ② 제철상품 실시간 영상 시청 | **시청 판정 로직 불필요**(대표 확정) |
| ③ 친구 초대 | 아래 3번 조건 참조 |

- 🔴 **핵심 안전장치(대표 확정)**: 회복 보상은 **게임 목숨만**이다. 물·룰렛권이 아니다.
  → 그래서 **일일 상한이 필요 없다.** 목숨을 아무리 채워도 물은 게임에서 이겨야 나오므로 경제가 무너지지 않는다.

## 3. 친구 초대

- **지급 조건**: 카톡 발송만으로는 **미지급**. **초대받은 친구가 실제 가입을 완료한 시점**에 지급.
- 지급 대상: 게임 목숨(2번 원칙에 따름). 물·룰렛권 지급 여부는 대표 확정 필요.
- 어뷰징 대비(설계 시 검토): 동일인 재가입·대량 초대 계정 — 가입 완료 기준이라 1차 방어는 되나, 가입 자체 어뷰징은 별도 정책 필요.

## 4. 초대 공유 문구 — 자랑·경쟁 자극형

- 카톡 공유 카드에 **귤나무 이미지 + 실시간 진행률**을 반영한다(정적 이미지 아님).

**대표 제시 예시**
```
🍊 나 귤나무 85% 키웠다
100% 채우면 진짜 귤 한 박스 온대
너도 심어볼래?
```
```
🌳 나 귤나무 다 키워서 귤 한 박스 받았다 😎
안 믿기지? 너도 해봐
```

- 구현 시 검토 항목: 카카오 공유 API(링크 미리보기 이미지 동적 생성), 진행률 스냅샷 이미지 생성 방식, 개인정보 노출 없는 공유 링크 설계.

## 5. 착수 전 확정이 필요한 것 (대표 결정 대기)

1. 미니게임 종류·승리 조건·보상 수량
2. 목숨 최대 보유 수·1회 소모량·회복 경로별 회복량
3. 친구 초대 보상의 종류(목숨만인지, 물·룰렛권도 주는지)
4. 게임 진입 동선(자사몰 하단 탭 신설 vs 나무 화면 내부)
5. 회원 인증 연결 방식 — 카페24 로그인 세션과 우리 게임 백엔드(`/api/mall/*`)를 잇는 방법
   ※ 이 항목은 1차 게임 가동에도 공통으로 걸리는 선행 조건입니다(지시 #85부터 미확정).

## 6. 기술 메모

- 기존 백엔드: `mall-api.js` + `/api/mall/*` 13종, 테이블 5종(`mall_members`·`points_ledger`·`roulette_spins`·`tree_state`·`reward_grants`)
- 현재 게이트: `MALL_API=on` + `MALL_API_TOKEN` 없으면 전 라우트 503(완전 잠금)
- 2차 확장 시 신규 테이블 예상: 게임 세션·목숨 잔량·초대 관계(inviter/invitee)·미니게임 결과 로그
- 경제값은 1차와 동일하게 **전부 DB + 화면 편집**으로 — 하드코딩 금지(대표 설계 원칙)
