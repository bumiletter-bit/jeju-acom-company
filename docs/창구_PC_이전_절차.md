# 에이전트오피스 창구 — 콘솔 API 전환과 발주컴퓨터 이전 절차 (2026-09-29)

> 목적: 직원 지시를 처리하는 「창구」 터미널을 ①회사 명의 콘솔 API 과금으로 바꾸고 ②대표 PC가 아닌 발주컴퓨터에서 돌린다.
> 회사프로그램·에이전트오피스 화면·규칙 문서·지시 기록은 바뀌지 않는다. 바뀌는 것은 창구 터미널이 도는 PC와 로그인 방식뿐이다.

## 1. 콘솔 API 준비 (대표 · 브라우저)

1. https://console.anthropic.com 에 기존 계정으로 로그인한다.
2. 결제 정보(Billing)에서 카드를 회사 카드로 바꾸고, 청구 정보의 이름·주소를 회사 것으로 고친다.
3. 작업 공간(Workspace)을 하나 새로 만든다. 이름 예: `agent-office-desk`.
   - 손님 응대(톡톡봇·문의 답변)가 쓰는 기존 키와 사용량이 섞이지 않게 하기 위해서다.
4. 그 작업 공간에 월 사용 한도(Spend limit)를 건다. 처음에는 낮게 잡고 1주일 뒤 조정한다.
5. 키는 여기서 미리 만들지 않아도 된다. 3-4단계에서 로그인하면 자동으로 만들어진다.

## 2. 발주컴퓨터에 설치 (1회)

PowerShell을 열고 차례로 실행한다.

```powershell
# ① Node.js, Git 설치 (이미 있으면 건너뜀)
winget install OpenJS.NodeJS.LTS
winget install Git.Git
```

PowerShell 창을 닫았다가 다시 연 뒤 계속한다.

```powershell
# ② Claude Code 설치
npm install -g @anthropic-ai/claude-code

# ③ 회사프로그램 내려받기 (원드라이브 폴더 밖에 둔다)
mkdir C:\akkome
cd C:\akkome
git clone https://github.com/bumiletter-bit/jeju-acom-company.git
cd jeju-acom-company

# ④ 부속 모듈 설치
npm install
```

## 3. 접속 정보 넣기 (대표가 직접)

1. `C:\akkome\jeju-acom-company` 폴더에 `.env` 파일을 새로 만든다.
2. 안에는 아래 **한 줄만** 넣는다. 값은 대표 PC의 `.env`에서 같은 줄을 복사한다.

```
DATABASE_URL=여기에_입력
```

3. 대표 PC의 `.env`를 통째로 복사하지 않는다. 창구는 DB 접속 하나만 있으면 되고, 다른 키(카페24·알리고·텔레그램 등)는 발주컴퓨터에 둘 이유가 없다.
4. 옮길 때 메신저·메일로 보내지 않는다. USB로 옮기거나 직접 입력하고, 옮긴 뒤 USB의 파일은 지운다.

## 4. 창구 열기

```powershell
cd "C:\akkome\jeju-acom-company\★에이전트오피스"
claude
```

1. 처음 실행하면 로그인 방식을 묻는다. **Anthropic Console account**(API 사용량 과금)를 고른다. 구독(Claude account) 쪽을 고르지 않는다.
2. 브라우저가 열리면 콘솔 계정으로 로그인하고, 작업 공간은 1-3에서 만든 것을 고른다.
3. 터미널로 돌아와 `창구 시작`을 입력한다.
4. 회사프로그램 에이전트오피스 화면이 30초 안에 「대기 중」으로 바뀌면 정상이다.

## 5. 대표 PC 쪽 정리

- 대표 PC에서 열어 둔 창구 터미널은 닫는다. 창구는 한 번에 한 곳에서만 연다.
- 대표 PC의 개발용 창(총괄)은 지금 구독 그대로 쓴다.

## 6. 발주컴퓨터 설정

- 절전·최대 절전을 끈다(전원 설정 → 화면 끄기는 상관없음, 절전은 「안 함」).
- 윈도우 업데이트 재시작 뒤에는 창구를 다시 열어야 한다(4번).
- 발주컴퓨터를 쓰는 사람은 DB 접속 정보와 콘솔 로그인에 접근할 수 있다. 윈도우 계정에 비밀번호를 걸고, 자리를 비울 때 잠근다.

## 7. 매일 쓰는 법

| 상황 | 할 일 |
|---|---|
| 아침에 PC를 켰을 때 | 4번의 두 줄 실행 → `창구 시작` |
| 화면이 「자리 비움」일 때 | 창구 터미널이 꺼졌는지 확인 → 4번 |
| 대표가 "규칙 바꿨다"고 할 때 | 창구 터미널을 닫고 아래 실행 뒤 4번 |

```powershell
cd C:\akkome\jeju-acom-company
git pull
```

## 8. 확인할 것 (전환 당일)

- 시험 지시 3종: 조회 1건 · 정산 발송목록 이미지 1건 · 쿠폰 요청 1건(승인 대기로 올라오는지).
- 힉스필드(이미지·영상 생성)는 대표 구독 계정에 연결된 것이라 콘솔 로그인 창구에서는 안 보일 수 있다. 안 되면 총괄 창에 알린다.
- 1주일 뒤 콘솔의 사용량(Usage)에서 작업 공간별 금액을 확인하고 월 한도를 조정한다.

## 9. 되돌리기

발주컴퓨터 창구를 닫고, 대표 PC의 `★에이전트오피스` 폴더에서 창구를 다시 열면 전환 전 상태로 돌아간다. 프로그램 쪽은 바꾼 것이 없어 되돌릴 것이 없다.

## 부록. 대표 PC에서 창구만 콘솔로 돌리기 (PC를 옮기지 않는 간단한 길)

🔴 창구 터미널에서 `/login`으로 콘솔 계정에 로그인하지 않는다. Claude Code 로그인 정보는 PC 사용자 단위로 저장되어, 그렇게 하면 같은 PC의 다른 창(대표 개발용)까지 콘솔 과금으로 넘어갈 수 있다.
대신 창구 창에만 API 키를 환경 변수로 넣어 실행한다.

1. 콘솔에서 창구용 작업 공간을 만들고 API 키를 발급한다(월 한도 설정).
2. 대표 PC에 키 파일을 만든다: `%USERPROFILE%\.akkome\desk-api-key.txt` (키 한 줄 · 저장소 밖).
3. 창구를 열 때는 `★에이전트오피스` 폴더에서 터미널을 열고 `akkome` 을 입력한다(`.\창구열기.ps1` 과 같다). **다른 폴더에서는 열리지 않는다** — 유료 창을 실수로 여는 것을 막기 위해서다. 같은 폴더에서 `claude` 로 열면 콘솔이 아니라 구독으로 열린다.
   - `akkome` 명령은 `%APPDATA%\npm\akkome.cmd` 이고, 실행 파일 위치는 `%USERPROFILE%\.akkome\desk-path.txt` 에서 읽는다(둘 다 저장소 밖 · PC마다 1회 설치). 폴더를 옮기거나 이름을 바꾸면 그 txt의 경로를 고친다.
   - 모델은 실행 파일이 Opus로 지정한다.
4. 처음 실행하면 "이 API 키를 쓸까요"를 묻는다. 예를 고른다.
5. `창구 시작` 입력.
6. 확인: 창구에서 `/status`를 입력해 인증이 API 키로 표시되는지 본다. 대표 개발용 창에서도 `/status`로 구독 그대로인지 본다.
