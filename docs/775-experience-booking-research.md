## 2. 네이버 주문 응답의 체험 옵션 글자 꼴

- 지금 DB·송장에 실주문이 없어 **실물 확인은 못 했습니다**(API 조회 범위 180일 밖).
- 우리 코드가 쓰는 칸은 이렇습니다(server.js 7318 · 8048).
  - `productOrder.productOption` = 옵션 글
  - `productName`
  - `quantity` / `remainQuantity`(부분취소 반영)
- 네이버 일반 규칙은 조합형 「묶음: 값」 + 입력형 「입력 칸 이름: 손님이 쓴 값」 을 「 / 」 로 잇는 꼴입니다(추정).
  - 예: `제주아꼼이네 귤체험: 내가 직접 딴 노지귤 2kg(36개월까지무료) / 00월: 11 / 00일: 30 / 00시 00분 (30분단위): 12:30`
- 손님이 자유롭게 적는 칸이라 「11」「11월」「십일월」「1」, 「12:30」「12시30분」「오후 12시 반」 처럼 글자가 제각각입니다. → 날짜·시각은 **정규식으로 최선 읽기 + 못 읽으면 직원 확인 줄**이 맞습니다.
- 인원:
  - 인원 칸은 따로 없습니다. **quantity = 같은 옵션 몇 개(= 몇 명분)** 입니다.
  - 옵션이 둘(체험 2kg / 입장만)이라 한 주문 번호(orderId) 안에 productOrder 가 옵션마다 따로 옵니다. → 「주문 번호별로 묶어 옵션마다 수량」 = 체험 인원 · 입장만 인원.
  - 36개월 이하 무료 아이는 주문에 안 잡힙니다.
- 입력형 값은 productOrder 마다 붙습니다(같은 주문의 두 옵션에 각각 날짜가 붙을 수 있음 · 다르면 직원 확인).
- 🔵 확인 방법(쓰기 0): 첫 실주문이 오면 상세조회 응답(`/product-orders/query`)의 productOption 원문을 PII 가린 채 한 번 기록합니다(naverMaskPII 는 옵션을 남김). 이 꼴로 파서를 확정합니다.

## 3. 발주확인 → 배송완료 → 취소 대신 반품

- 대표 확인 사실: 체험은 발주확인하면 바로 배송완료가 됩니다. 그 뒤 손님이 못 오게 되면 「취소」 가 아니라 「반품」 요청이 됩니다.
- 우리 클레임 수집(`collectClaim` · 타이머 claim 10분 · 켜짐):
  - last-changed-statuses 에서 claimType/claimStatus 에 RETURN·EXCHANGE 가 있으면 첫 1회 텔레그램 「⚠️ 반품·교환 N건 — 판매자센터에서 확인」 을 보냅니다(naver_claim_alerted · 180일).
  - **상품 구분이 없어 체험 반품도 잡힙니다(알림만 · 자동 처리 0).**
  - 다만 체험인지 택배 상품인지 알림 글에 안 나옵니다.
  - 취소(CANCEL)는 알림 제외(수집만)입니다. → 발주확인 전 체험 취소는 조용히 지나갑니다.
- 반품 승인·환불은 판매자센터 수기입니다(우리 쓰기 API 없음 · relay 허용 목록 = 읽기 + 발주확인뿐).
- 설계 메모: 우리가 체험을 자동 발주확인하지 않으면(0절), 방문 전 취소는 「취소」 로 남아 손님·직원 둘 다 쉽습니다.
  - 발주확인(= 배송완료)은 **방문 당일 또는 방문 뒤** 직원이 하는 편이 반품 길을 줄입니다(대표 결정).

## 4. 회사 문자(알리고 sendLms)로 체험 안내 자동 발송 — 끼울 자리 · 상한 · 수신거부

- 발송 함수: `kakaoNotify.sendLms({ receiver, subject, message })`(kakao-notify.js 265).
  - 스위치 `KAKAO_NOTIFY=on` 일 때만 실발송(꺼짐 = dry-run).
  - 키 없으면 keys-missing · `smsSafe` 로 이모지 제거(문자에 이모지 금지 · #549) · 제목 20자 · `ALIGO_TEST=Y` 면 시험 발송.
  - 지금 쓰는 곳 = 쿠팡 주문안내·발송안내(server.js 11123·11228) · 보류 건 수기 발송(6413).
- 끼울 자리(추천): **`collectKakaoNotify` 의 상세조회 직후 · 품목 판별 전**(server.js 8048 앞)에서 체험 상품이면 갈래를 나눕니다.
  1. 택배 주문안내·자동 발주확인 대신 **체험 접수 문자 1통**: 「예약 날짜·시각(읽은 값) · 인원 · 주소·주차 · 당일 연락처 · 변경은 톡톡/문자」.
     - 번호 가드는 그대로입니다(선물하기 마스킹 · 빈 번호 · 유선 = skip).
  2. 이력 = kakao_notify_log 에 mode `exp`/status 로 남기면 「알림 발송 이력」 화면·중복 방지(order_key UNIQUE)를 그대로 씁니다.
  3. 예약 목록 = 새 표(예: `experience_bookings` · order_key · 방문일 · 시각 · 인원 · 원문 · 상태)에 저장합니다. 전날 안내 문자(D-1)·당일 명단은 이 표로 만듭니다.
- 하루 상한:
  - sendLms 자체엔 상한이 없습니다.
  - 체험은 주문당 1통(접수) + 방문 전날 1통으로 묶고, 타이머 한 바퀴 상한(예: 50통)과 설정 키(예: `agent_office_config 'experience_notify' { enabled, daily_cap }`)를 따로 둡니다.
  - 문자 봇의 `hourly_send_cap 30` 은 회사폰(SMSGate) 경로라 알리고와는 별개입니다.
- 수신거부:
  - 알리고 경로엔 거부 목록이 없습니다(주문 관련 정보성 문자라 법정 거부 고지 대상은 아님 · 광고 문구 금지).
  - 회사폰 문자 봇은 「수신거부·그만 보내」 글을 `refuse` 로 기억합니다(sms/classify.js · index.js · 180일).
  - → 체험 문자 보내기 전에 그 번호가 refuse 로 기억돼 있으면 건너뛰는 한 줄을 권합니다(같은 손님이 회사폰에 거부 표시를 한 경우).
- 시간: 야간 발송은 피합니다. 접수 문자는 즉시, 전날 안내는 낮 시간(예: 10~18시) 틱에서만 보냅니다.

## 5. 정리 · 다음 단계 제안

1. (급함 · 작은 수정) 체험 상품을 주문안내 알림톡·자동 발주확인·문자 봇 발송 전 주문에서 빼기. 상품 번호 7673020911 또는 deliveryInfo 없음으로 판정합니다. **대표 결정 = 빼기만 할지 / 체험 접수 문자로 바꿀지.**
2. 첫 실주문 1건으로 productOption 원문 꼴 확정 → 날짜·시각 파서(못 읽으면 직원 확인).
3. 예약 표 + 접수 문자 + 전날 안내 + 당일 명단(에이전트 오피스 화면 또는 창구 조회).
4. 클레임 알림 글에 「체험」 표시(반품 = 날짜 변경·취소 문의일 가능성 높음).
