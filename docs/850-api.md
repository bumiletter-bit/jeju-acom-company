# #850 발주 메모함 — 서버 API 계약 (워커2 · 2026-10-25)

> 설계 = `docs/850-order-memo-design.md`(워커3) · 대표 결정 A~E = 권고대로(총괄 #850 「고」).
> 서버 = 새 파일 `order-memo.js` + server.js mount 1줄 · 표 2개(기동 때 CREATE IF NOT EXISTS) · 화면(워커1)은 이 문서만 보고 붙이면 된다.
> 🔴 최종발주 판정(v2 parseLines · sizeLines · prepLines · parseCash · cashCheck)은 한 줄도 안 바뀐다. 메모함이 내놓는 것은 **지금 사람이 메모 칸에 치는 글자 · 현금파일 엑셀 행과 같은 꼴**뿐.

## 0. 한눈에

| 길 | 누가 | 하는 일 | DB 쓰기 |
|---|---|---|---|
| `POST /api/order-memo/preview` | 누구나 | 붙여 넣은 글 → 정리 결과(카드) · 남은 글은 창구에 요청 | 메모함 표 **0**(창구 요청 줄 1 · 손님 글은 받은 뒤 지움) |
| `GET /api/order-memo/preview/:id` | 요청한 본인·관리자 | 창구 정리 기다리기(2~3초마다) | 0 |
| `DELETE /api/order-memo/preview/:id` | 요청한 본인·관리자 | 결과 받은 뒤·그만둘 때 = 손님 글·결과 지움 | 요청 줄 1 |
| `POST /api/order-memo` | 누구나 | 카드에서 고친 줄을 저장 | 건 1 + 줄 n |
| `GET /api/order-memo?state=open\|cleared` | 누구나 | 목록(건 + 줄) | 0 |
| `PUT /api/order-memo/rows/:id` | 누구나 | 줄 고치기(다시 검사) | 줄 1 |
| `DELETE /api/order-memo/rows/:id` | 누구나 | 한 줄 지우기(X) = 「비운 것」으로(30일 되살리기) | 줄 1 |
| `POST /api/order-memo/restore/:id` | 누구나 | 비운 줄 되살리기 | 줄 1 |
| `GET /api/order-memo/for-ship?date=` | 누구나 | 최종발주에 넣을 메모 칸 글 · 현금 행 | 0 |
| `POST /api/order-memo/used` | 누구나 | 「오늘 발주에 넣었다」 표시 | 줄 n |
| `POST /api/order-memo/clear` | 누구나(결정 D) | 오늘 발주분 비우기 | 줄 n |

- 전부 `authMiddleware`(로그인) · 옛 서버면 404 → 화면은 조용히 넘김(지금과 같게).
- 오류 꼴 = 기존 `handleAdminErr`(`{ error: '한국어 글' }` + 상태 코드 400/403/404/409/500).
- 감사 기록(`audit_logs` source `order_memo`) = 줄 수·종류·상태만 — **이름·번호·주소·원문 0**.
- 개인정보 보관 = 비운 줄은 `cleared_at` + 30일(설정 `order_memo.keep_days`) 뒤 **영구 삭제**(서버 6시간마다 · 줄이 다 지워진 건은 원문째 삭제).

## 1. 줄(Row) 꼴 — 모든 응답에서 같음

```js
{
  id: 12,                     // 저장 뒤에만(미리보기엔 없음)
  kind: 'line' | 'cash',      // line = 메모 칸 한 줄 · cash = 현금파일 한 행(13칸)
  ship_date: '2026-10-30' | null,   // 지정 발송일 · null = 다음 발주
  sure: true | false,         // false = 🟠 확인(최종발주에 안 들어감 · 목록에 남음)
  check_why: ['주소가 없어요', …],   // 🟠 이유(최종발주 카드와 같은 말투) · sure true 면 []
  src: 'rule' | 'ai' | 'edit',     // 규칙(즉시·무료) · AI · 사람이 고침

  // kind 'line'
  key: '010-1234-5678' | '2026102512345678',   // 구매자 번호 또는 상품주문번호(자사몰 YYYYMMDD-NNNNNNN)
  note: 'S사이즈로' | '입력o삭제x' | '보내는이 홍길동' | '',
  plat: '네이버' | '쿠팡' | '자사몰' | '',
  line: '10/30\t010-1234-5678\t입력o삭제x\t네이버',   // 메모 칸에 그대로 들어갈 글(서버가 만듦 · 규칙 줄은 원문 그대로)

  // kind 'cash'
  cells: [13칸 글자],          // HEADERS 순서(보내는사람 … 보내는이 변경주소) · 화면은 칸마다 고칠 수 있음
  missing: [3, 8],            // 빈 필수 칸 번호(빨간 테두리) — 3 수취인명 · 4 옵션정보 · 5 수량 · 6 수취인연락처1 · 8 배송지

  // 저장 뒤 목록에서만
  state: 'open' | 'cleared', used_on: '2026-10-26' | null, cleared_at, cleared_by, updated_at, updated_by
}
```

### 현금 행 13칸(cells) — 서버가 채우는 값
| 칸 | 값 |
|---|---|
| 0 보내는사람 | `!` + (보내는이 지정 있으면 「홍길동 드림」 · 없으면 「손님이름(제주아꼼이네)」 · 이름도 없으면 「제주아꼼이네」) — 🔴 `!` = 현금 손님 표식(parseCash bang) |
| 1 보내는사람연락처 | 보내는이 번호 → 없으면 구매자(주문한 분) 번호 · 하이픈 |
| 2 출고지 | 설정 `order_memo.origin_addr`(기본 「제주특별자치도 제주시 연삼로 1066-31, 제주아꼼이네」 = 현금파일 실자료와 같은 글) |
| 3 수취인명 · 6·7 수취인연락처 · 8 배송지 · 9 배송메세지 | 메모에 있는 그대로(배송메세지 비면 최종발주가 기본 문구) |
| 4 옵션정보 | **단가표 이름 그대로**만(그날 단가표 `pricing` 목록에 없으면 🟠 「품목을 못 정했어요」) |
| 5 수량 | 정수 ≥1(없으면 🟠) |
| 10 구매자연락처 | 주문한 분 번호(없으면 받는 분 번호) |
| 11 박스타입 | 빈칸 |
| 12 보내는이 변경주소 | 메모에 있으면 |

## 2. 길별 상세

### 2-1 `POST /api/order-memo/preview` — 정리 미리보기(저장 0)
요청 `{ raw: '붙여 넣은 글(≤4000자)', tags?: ['cash'|'indiv'|'size'|'date'|'sender'], source?: 'manual'|'sms:<thread_id>', phone?: '문자 대화 번호' }`

1. **규칙 먼저(무료·즉시)** — 한 줄씩:
   - 탭으로 9칸 넘게 갈라진 줄 = 현금 행(엑셀에서 복사한 꼴) → `cells` 로 바로.
   - 「번호 + 사이즈」(최종발주 `sizeLines` 가 읽는 꼴) → line ✅ (로얄 아닌 사이즈 L·2L = 🟠 그대로 같은 말).
   - 「날짜 ⇥ 번호 ⇥ 비고 ⇥ 플랫폼」 · 「번호 입력o삭제x」 · 「번호 ○일 발송」 · 「번호 보내는이 ○○」 처럼 송장변환 v2 `parseLines` 가 번호·날짜를 읽고 비고가 지시(입력삭제·날짜·보내는이·메모무시)뿐인 줄 → line ✅(원문 그대로 · `line` = 원문).
   - 나머지(손님 이름·주소·품목이 섞인 글 · 여러 줄 덩어리) → 2번으로.
2. **AI = 창구 경유(기본 · 대표 「고」)** — 남은 글을 **최종발주 메모 읽기와 같은 길**로 창구에 한 번 맡긴다(창구 요청 줄 `pending_orders` 「[발주 메모 읽기] 남은 글 n줄」 · 요청한 계정 = `created_by_id` → 대표·발주 컴퓨터 계정(`desk_subscription_users`)은 대표 요금제 · 그 밖은 창구 콘솔 키 · 규칙 문서 = `★에이전트오피스/발주메모_정리.md` · 모델 = 창구가 opus). 창구 답도 서버가 같은 검사를 다시 함(번호 8자리 · 날짜 · 단가표 이름 · 필수 칸).
   - 창구가 꺼져 있으면(대기 프로그램 2분 안 소식 없음) 요청 줄을 안 만들고 남은 글을 `leftover` 로 바로 돌려줌 + `desk.state 'off'`.
   - 설정 `order_memo.ai.direct true` 일 때만 서버가 직접 AI(예비 길 · 기본 꺼짐) · `ai.enabled false` = AI 안 씀(남은 글 그대로).

응답
```js
{ ok: true,
  rows: [Row…],                 // id 없음 · 규칙 줄(창구 경유면 여기엔 규칙 줄만)
  leftover: '정리 못 한 글' | '',
  rule_count: 3, ai_count: 0,
  ai: { used: true, via: 'desk' } | { used: false, why: '남은 글 없음'|'꺼짐'|'창구 꺼짐'|'실패: …' } | (direct) { used: true, model, ms, in_tokens, out_tokens },
  sms_draft: '' ,
  desk: null                                            // 규칙으로 다 읽힘 = 끝(즉시)
      | { state: 'wait', id: 3101, wait_sec: 30 }       // 창구가 정리 중 → 아래 2-1b 로 기다리기
      | { state: 'off', message: '창구가 꺼져 있어 지금은 규칙으로만 정리했어요 · 남은 글은 직접 채워 주세요' }
}
```
- 같은 사람 분당 20번 넘으면 429 「잠시 뒤 다시 해 주세요」(AI 비용 막이).

### 2-1b `GET /api/order-memo/preview/:id` — 창구 정리 기다리기 · `DELETE` — 받은 뒤 지우기
- 화면: `desk.state 'wait'` 이면 규칙 줄은 먼저 카드에 보여 주고, 아래에 「창구가 정리 중이에요 · 30초쯤」 + 2~3초마다 GET(최대 3분 · 넘으면 「오래 걸려요 — 남은 글은 직접 채워 주세요」로 멈추고 DELETE).
- 응답 `{ ok, state: 'wait' }` · `{ ok, state: 'done', rows: [Row…](AI 줄 · 서버가 다시 검사), ai_count, leftover, sms_draft }` · `{ ok, state: 'fail', leftover: '남은 글 그대로', message: '이유' }`.
- done 이면 받은 rows 를 카드 규칙 줄 뒤에 붙이고 **바로 `DELETE /api/order-memo/preview/:id`**(손님 글·결과를 서버에 안 남김 · 아직 안 집힌 요청이면 취소). fail 도 DELETE.
- 본인 요청만(관리자는 남의 것도) · 남의 것 403 · 없음 404. 화면이 DELETE 를 못 하고 떠나도 서버가 하루 뒤 글·결과를 지움.

### 2-2 `POST /api/order-memo` — 저장
요청 `{ raw, tags?, source?, rows: [미리보기 Row 를 화면이 고친 것] }` (rows 1~60)
- 서버가 줄마다 **다시 검사**(line = `line` 다시 만듦 · cash = 칸 정리·필수 칸) → `sure`·`check_why`·`missing` 은 서버 값이 정본(화면이 보낸 값 무시).
- 응답 `{ ok: true, entry_id, rows: [Row(id 있음)…] }`

### 2-3 `GET /api/order-memo?state=open|cleared`
- `open`(기본) = 아직 안 비운 줄이 있는 건 · `cleared` = 비운 지 30일 안 줄(되살리기 탭).
- 응답 `{ ok: true, keep_days: 30, entries: [{ id, created_at, created_by, source, tags, raw, rows: [Row…] }], counts: { open, unsure, wait, cleared } }` — 최근 순 · 건 200까지.
- `counts.unsure` = 🟠 줄 수(「지금 챙길 일」 한 줄 재료) · `wait` = 지정 발송일이 오늘(KST) 뒤인 줄.

### 2-4 `PUT /api/order-memo/rows/:id` — 고치기
요청(바꿀 칸만) line = `{ key?, note?, plat?, ship_date? }` · cash = `{ cells?, ship_date? }` (`ship_date: null` = 날짜 지정 풀기)
- 다시 검사 → 응답 `{ ok: true, row: Row }` · 비운 줄은 409 「비운 줄이에요 — 되살린 뒤 고쳐 주세요」.

### 2-5 `DELETE /api/order-memo/rows/:id` — 한 줄 지우기(X)
- `state 'cleared'` + `cleared_at`·`cleared_by` → 응답 `{ ok: true }` · 30일 안 되살리기.

### 2-6 `POST /api/order-memo/restore/:id`
- `state 'open'` · `used_on` 비움 → `{ ok: true, row }` · 영구 삭제된 줄은 404.

### 2-7 `GET /api/order-memo/for-ship?date=YYYY-MM-DD` — 최종발주용(쓰기 0)
`date` = 최종발주 화면의 **기준 발송일**(`s.shipDate`).

| 줄 | 넣나 | `state` |
|---|---|---|
| line · sure · 날짜 없음 | 메모 칸에 넣음 | `nodate` |
| line · sure · `ship_date = date` | 넣음 | `today` |
| line · sure · `ship_date > date` | **넣음**(v2 가 그 주문을 「오늘 안 나감」으로 뺌 — 지금 사람이 30일 발송 줄을 매일 남겨 두는 것과 같음) | `wait` (화면 = 「📅 10/30 발송 대기」) |
| line · sure · `ship_date < date` | 넣음(v2 가 「지난 날짜 확인」 카드로 올림) | `past` |
| cash · sure · 날짜 없음 또는 `= date` | 현금 행에 넣음 | `today` |
| cash · sure · `ship_date > date` | **안 넣음**(주문이 없는 현금 손님 = 그날 아침에만) | 목록 `waiting` |
| cash · sure · `ship_date < date` | 안 넣음 → `held`(「지난 날짜」 사람이 정함) | |
| sure false(🟠) | 안 넣음 → `held` | |

응답
```js
{ ok: true, date,
  memo_text: '10/30\t010-…\t입력o삭제x\t네이버\n010-… S사이즈로',   // lines 의 line 을 \n 으로 이은 것 = 메모 칸에 붙일 글
  lines: [{ id, line, state, ship_date }],
  cash_aoa: [HEADERS(13칸), [13칸]…] | [],     // parseCash 에 그대로 넣는 꼴(머리글 포함) · 현금 행 없으면 []
  cash_ids: [id…],                             // cash_aoa 의 1행부터 순서대로
  waiting: [{ id, kind, ship_date }],          // 날짜 대기 현금 행
  held: [{ id, kind, why: ['…'] }],            // 🟠·지난 날짜 현금 — 최종발주 띠에 「확인 안 된 메모 n줄은 안 넣었어요」
  ids: [id…]                                   // 넣은 줄 전부(lines + cash) — used 에 그대로 보내면 됨
}
```
- 화면 몫(워커1): 메모 칸에 이미 글이 있으면 **뒤에 붙임**(덮지 않음) · 띠 「메모함에서 메모 n줄 · 현금 n줄을 넣었어요 [빼기]」 · 현금 = 현금파일 칸이 비었으면 `cash_aoa` 를 `st.cash` 로, 엑셀을 고르면 엑셀 행 + 메모함 행 합침 · 넣은 뒤 `markStale()` · LOCKS 중엔 안 넣음.

### 2-8 `POST /api/order-memo/used` `{ date, ids }`
- 그 줄들 `used_on = date`(열린 줄만 · ids ≤ 500) → `{ ok: true, n }`. 화면이 메모 칸에 실제로 넣은 뒤 부름([빼기] 하면 `{ date, ids, undo: true }` = used_on 비움).

### 2-9 `POST /api/order-memo/clear` `{ date, all? }` — 비우기
- 기본 = `used_on = date` 인 열린 줄 중 **line 의 `ship_date > date` 는 남김**(30일 발송 줄은 26·27·28일 발주 뒤에도 남고, 30일 발주 뒤에 비워짐) → `{ ok: true, cleared: n, left: { open, wait, unsure } }`.
- `all: true` = 열린 줄 전부(화면이 되묻기 1회 · 남는 줄 수는 `GET` counts 로 보여 줌).

## 3. 표

```sql
order_memo_entries (id SERIAL PK, created_at TIMESTAMPTZ DEFAULT NOW(), created_by TEXT, created_by_id INTEGER,
  raw TEXT NOT NULL, tags TEXT[] NOT NULL DEFAULT '{}', source TEXT NOT NULL DEFAULT 'manual')
order_memo_rows (id SERIAL PK, entry_id INTEGER NOT NULL REFERENCES order_memo_entries(id) ON DELETE CASCADE,
  kind TEXT NOT NULL, ship_date DATE, line_key TEXT, note TEXT, plat TEXT, line TEXT, cells JSONB,
  sure BOOLEAN NOT NULL DEFAULT false, check_why JSONB NOT NULL DEFAULT '[]', src TEXT NOT NULL DEFAULT 'rule',
  used_on DATE, state TEXT NOT NULL DEFAULT 'open', cleared_at TIMESTAMPTZ, cleared_by TEXT,
  updated_at TIMESTAMPTZ DEFAULT NOW(), updated_by TEXT)
```

## 4. 설정 `agent_office_config 'order_memo'`(없으면 기본값)
