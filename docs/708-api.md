# #708 이벤트 관리 — API·응답 꼴 약속 (A 서버 ↔ B 화면 ↔ C 손님 페이지)

- 작성: 워커3(A · claude-b1) · 2026-10-15 · 설계 = `docs/708-event-design.md` 2·3·4·5절. **이 문서가 정본** · 바뀌면 워커1(B)·워커2(C)에게 다시 알림.
- 날짜는 전부 KST `YYYY-MM-DD` 글자. 시각은 ISO 글자. 그림 주소는 전부 **상대 주소**(`/api/lucky/asset/…`) — 같은 서버에서 그린다.
- 종전 칸·종전 응답 꼴은 **그대로**(추가만). 옛 lucky.html(캐시) 이 새 서버를 만나도 깨지지 않는다.

## 1. 상태값 `state` (서버 한 곳에서 계산 · 모두 이 값을 쓴다)

| state | 뜻 | 손님 페이지 | /guide 카드 · #59 |
|---|---|---|---|
| `preparing` | 준비 중(초안 · 아직 안 열림) | 「준비 중」 한 장 · 조회 400 PREPARING | 꺼짐 |
| `live` | 열림(응모 중 · 발표 전) | 종전 전체 화면 | 켜짐 |
| `published` | 발표 중(live + published) | 종전 + 당첨자 창 | 켜짐 |
| `down` | 내려감(내리는 날 지남 또는 [내리기]) | 「끝났어요」 한 장 · 조회 400 CLOSED | 꺼짐 |

- 계산: `live_mode==='down'` 또는 오늘 > `page_until` → down · `live_mode==='live'` 또는 (`'scheduled'` 이고 오늘 ≥ start) → live/published · 그 밖 → preparing.
- **옛 회차(live_mode 칸 없음 · 지금 0행이지만 검증·백업 복원 등) = live 로 봄**(종전과 같은 화면). `new-round`·`copy-round` 로 만든 회차만 `draft` 로 시작.
- 날짜가 비어 있으면(새 회차 직후) page_until 검사는 건너뛴다(down 으로 안 떨어짐).

## 2. 공개 API (손님 · 로그인 없음)

### GET `/api/lucky/event` `[?pk=<미리보기 키>]`
```json
{
  "event": {
    "title": "관리용 이름",                      // 종전
    "display_title": "손님 화면 큰 글자",         // 비면 title 과 같음(서버가 채워 줌 · 늘 글자)
    "start": "2026-10-20", "end": "2026-10-31", "announce": "2026-11-01",   // 종전
    "page_until": "2026-11-04",                 // 내리는 날(기본 announce+3 · 서버가 채움)
    "prizes": [ { "name": "황금향 5kg 선물용", "count": 5,
                  "desc": "설명(줄바꿈 \\n · 비면 '')", "note": "손글씨 한마디('')",
                  "image": "/api/lucky/asset/12?v=ab12cd34" } ],   // image = 주소 또는 null(null 이면 페이지가 i<3 종전 그림 · 그 밖 그림 없음)
    "published": false, "excludeProducts": ["청귤"],   // 종전
    "state": "live",                            // 1절
    "live_mode": "live",                        // draft|scheduled|live|down (참고용)
    "images": { "hero": "/api/lucky/asset/9?v=…", "winner": null, "result": null },   // null = 종전 기본 그림
    "texts": { "prize_head_hand": "제주의 좋은 마음을 선물합니다! ♡", "corner_hand": "늘 함께해 주셔서\n감사합니다! ♡",
               "search_hand": "성함·번호로 확인해보세요! ♡", "winner_hand": "함께해 주신 모든 분께 감사드립니다! ♡",
               "winner_foot": "당첨되신 분께는 순차적으로 연락드리며, 경품은 주문 시 배송지로 보내드립니다 🍊",
               "noitem_products": "감귤·황금향 등",
               "preparing_title": "이벤트 준비 중이에요 🍊", "preparing_line": "곧 열립니다. 조금만 기다려 주세요!",
               "closed_title": "이벤트가 끝났어요 🙏", "closed_line": "함께해 주셔서 감사합니다. 당첨되신 분께는 순차적으로 연락드려요." },
               // 서버가 기본값을 채워 늘 전부 글자로 온다(비어 있는 칸 없음)
    "store_url": "https://brand.naver.com/jejuakkome",   // 끝났어요 장의 구매 단추(env EVENT_STORE_URL · 브랜드스토어 주소 · lucky.html 폴백과 같은 글자)

  },
  "counts": { "orders": 0, "customers": 0 }     // 종전 · preparing/down 이면 0

```
- `state` 가 preparing/down 이고 pk 가 없으면 `prizes` 는 `[]`, `images` 는 전부 null, counts 0 (글자 칸·날짜는 그대로). pk 가 맞으면 전부 준다.
- 종전 15초 캐시 그대로(pk 응답은 캐시 안 씀).

### POST `/api/lucky/lookup` `{ q }`
- 종전 그대로 + state 가 preparing → `400 {"error":"PREPARING"}` · down → `400 {"error":"CLOSED"}`. pk 는 받지 않는다(조회는 실자료).

### GET `/api/lucky/winners` — 종전 그대로(published 일 때만).

### GET `/api/lucky/asset/:id`
- 그림 바이트 · `Content-Type` = 올린 mime(`image/webp`·`image/png`·`image/jpeg`) · `Cache-Control: public, max-age=31536000, immutable` · 주소 꼬리 `?v=<sha1 앞 8자>` 는 캐시 깨기용(서버는 무시) · 없음·비움(purged) → 404(페이지는 `onerror` 로 기본 그림).

## 3. 관리 API (`/api/agent-office/lucky/*` · `Authorization: Bearer <jwt_token>` · 전부 **직원 가능** · `restore` 만 관리자)

응답은 종전처럼 `{ ok:true, db, … }` — `db` = 회차 전체(주문 포함 · 화면이 그대로 씀). **새로 붙는 칸**: `state`(1절) · `checklist`.

```json
"checklist": { "ready": false,
  "steps": { "basics": true, "prizes": false, "images": true, "texts": true, "preview": null, "open": false },   // 단계 카드 ①②③④⑤⑥ 완료 여부(⑤ preview 는 서버가 모름 → null · 화면이 세션 기억)
  "missing": ["경품 2 그림", "경품 2 인원"] }                                               // 열기 단추 옆에 보여 줄 글
```

| 라우트 | 본문 | 응답·규칙 |
|---|---|---|
| GET `/state` | — | `{ ok, db, id, state, checklist }` (id = 회차 번호 · 0행이면 null) |
| GET `/rounds` | — | 종전 + 줄마다 `state`, `page_until` |
| POST `/event` | `{ event:{…아래 칸 중 보낸 것만}, excluded:[…] }` | 종전 칸 + 새 칸 저장 · `{ ok, db, state, checklist, synced:{ card:true|false, bot:true|false } }` · state 가 live/published 일 때만 동기화(synced true) |
| POST `/assets` | `{ slot:"hero"|"winner"|"result"|"prize"|"brand", mime, data:"<base64>", width, height, label?:"그린레몬" }` | `{ ok, asset:{ id, url:"/api/lucky/asset/<id>?v=…", slot, mime, size, width, height, label } }` · 상한 1.5MB(base64 전) · mime 3종만 · 그 밖 400 |
| GET `/assets?slot=brand` | — | `{ ok, assets:[ {id,url,slot,label,size,width,height,created_at} ] }` (slot 없으면 전부 · purged 제외) |
| DELETE `/assets/:id` | — | `{ ok }` · 현재 회차가 쓰는 그림이면 `409 {"error":"IN_USE"}` |
| POST `/go-live` | `{ mode:"live"|"scheduled"|"down"|"draft" }` | `{ ok, db, state, checklist, synced }` · live/scheduled 로 바꾸는데 `checklist.ready` 가 아니면 `400 {"error":"NOT_READY","missing":[…]}` · 바뀌는 순간 동기화 1회 |
| POST `/copy-round` | `{ from_id, title }` | `{ ok, db, state }` · 설정·그림 참조·문구만 복사 · 주문·당첨·제외·올린 기록 비움 · 날짜 비움 · live_mode draft · 현재 회차가 live/published 면 `409 {"error":"LIVE"}` |
| GET `/preview-key` | — | `{ ok, pk, expires_at, url:"/lucky.html?pk=<pk>" }` · 1시간 · HMAC(JWT_SECRET) |
| POST `/new-round` `{confirm:"NEW", title}` · `/reset` `{confirm:"RESET"}` · `/draw` · `/publish` | 종전 | **직원 가능**(종전 관리자만 → 바뀜 · confirm 글자 검사는 그대로 · 화면은 확인 창 1번 뒤 글자를 대신 넣어 보냄) |
| POST `/restore` | 종전 | **관리자만 그대로** |
| POST `/orders` · `/remove` | 종전 | 종전 |

### `event` 저장 칸(화이트리스트 · 길이 넘으면 자름)
| 칸 | 꼴 · 상한 |
|---|---|
| `title` · `start` · `end` · `announce` | 종전(80) |
| `display_title` | 글자 60 |
| `page_until` | 날짜 · 비우면 announce+3 자동 |
| `live_mode` | 저장으로는 못 바꿈(`/go-live` 만) |
| `prizes[]` | `{ name(60), count, desc(120 · \n 허용), note(40), image_id(정수|null) }` |
| `hero_image_id` · `winner_image_id` · `result_image_id` | 정수 또는 null(=기본 그림) |
| `texts` | 2절 열쇠 중 보낸 것만 · 각 120자 · 빈 글자 = 기본값으로 되돌림 |
| `coupon_text` | 80 · 봇 답(#59)에만 · 손님 페이지·알림톡 카드엔 안 나옴 |
| `guide_card` | `{ enabled(기본 true), title(60), lines[최대 3 · 각 120], btn(30), custom(boolean) }` · custom false 면 서버가 자동 글로 덮음 |
| `bot_reply` | `{ enabled(기본 true), keywords[최대 20 · 각 20], response(2000), custom(boolean) }` · 같은 규칙 |
| `pending_art` | `[ { order_id, slot:"hero"|"winner"|"prize:1", at } ]` 최대 20 · 화면이 「맡기기」 뒤 적어 두는 메모(서버는 보관만) |
| `excludeProducts` · `excluded`(본문 최상위) | 종전 |

- `image_id` 가 가리키는 그림이 없거나 비워졌으면 저장은 되고 응답 `image` 는 null(기본 그림).
- 저장 때 서버가 `db.event` 전체를 돌려주므로 화면은 응답 `db` 로 다시 그리면 된다(종전 꼴).

## 4. 미리보기 postMessage (C 가 lucky.html 에 받기 · B 가 보내기)

- iframe 주소 = `/lucky.html?preview=1` (서버 조회를 안 하고 메시지만 기다림 · 메시지 전엔 빈 화면·회색 뼈대). `?pk=` 는 서버에서 초안을 읽는 길(공유 링크용 · 메시지 없이 그린다).
- iframe → 부모(열리면 1회): `{ type:"lucky:ready" }`
- 부모 → iframe(칸이 바뀔 때마다 · 통째로 보냄):
```json
{ "type": "lucky:preview",
  "event": { …2절 GET /api/lucky/event 의 event 와 같은 꼴(초안 값 · state 는 부모가 'live' 또는 'published' 를 넣어 보냄) },
  "counts": { "orders": 0, "customers": 0 },
  "scene": "default" | "received" | "win" | "lose" | "noitem" | "outside" | "winners" | "preparing" | "closed" }
```
  - `scene` = 결과 칸을 가짜로 그려 보는 것(실조회 아님 · 글자는 「홍*동 고객님」 꼴 가짜) · `winners` = 당첨자 창을 열어 보임(이름 2개 가짜) · 기본 `default`.
  - 아직 서버에 안 올린 그림은 `image`/`images.*` 칸에 **`data:` URL** 을 넣어 보내도 된다(페이지는 src 로만 쓴다).
- iframe → 부모(그린 뒤): `{ type:"lucky:rendered", scene }`
- origin 검사: 둘 다 `event.origin === location.origin` 일 때만 받는다.

## 5. 동기화 산출물(서버가 쓰는 값 · B·C 는 읽지 않음 · 참고)
- `agent_office_config.guide_event_card` = `{ enabled, title: display_title, lines:[기간 줄, 경품 줄「총 N명 추첨: 1등 … · 2등 …」, 발표·확인 줄], btn:"접수·당첨 확인 바로가기", url: env EVENT_PUBLIC_URL(기본 https://event.akkome.com/lucky.html), start, end: page_until }` · 할인·쿠폰·%·원 글자 없음(서버가 거름).

## 6. 창구 「AI로 그림 맡기기」(B 가 지시 만들기 · C 가 창구 문서 · A 는 무접촉)
- 지시 만들기 = 기존 `POST /api/agent-office/orders` `{ content }` · 머리말 고정 꼴(첫 줄):
  `[이벤트그림] 회차 #<round_id> · 자리 <배너|발표|경품 n> · 품목 <이름> · 자세 <인사|귤들기|상자들기|기쁨|엄지척|안내> · 크기 <1200x350|900x471|480x480> · 요청: <한 줄 또는 없음>`
  둘째 줄: `후보 2~3장을 첨부로 답해 주세요(글자 없는 그림 · 3D 아꼼이 기준 · 품목 실사진 참고).`
- 창구 답(기존 respond.js) → 지시 상세 `GET /api/agent-office/orders/:id` 의 `result.files` = `[ { label:"파일이름.png", file_id: 123, size: 456789 } ]`(바깥 링크면 `{label,url}` · file_id 없음) → 그림 바이트 = `GET /api/agent-office/files/<file_id>/download`(이미지 확장자는 inline · `image/png` 등 mime).
- 화면은 그 바이트를 canvas 로 줄여 webp 로 `POST /assets` (slot 자리 · label 에 품목) → 돌아온 `asset.id` 를 `event` 저장.

## 8. 로컬 실서버를 가짜 표로 띄우는 법(B 실왕복 통합 확인용)
```
# 회사프로그램 폴더에서(Git Bash) · 포트는 자기 몫 · JWT_SECRET 은 아무 값(브라우저 jwt_token 은 그 값으로 서명한 토큰)
LUCKY_TABLE=lucky_events_vui JWT_SECRET=local708 PORT=3466 node -e "global.setInterval=()=>({unref(){},ref(){}}); require('./server.js')"
```
- 보장: lucky 모듈은 `lucky_events_vui`·`lucky_events_vui_assets` 만 읽고 씀(첫 요청 때 생성) · `guide_event_card`·`inquiry_scenarios` 쓰기 0 · 틱 0 · `/go-live` 응답 `synced` 는 `{card:false,bot:false}`(동기화 확인은 verify-708-server 의 가짜 받이 항목으로).
- 🔴 server.js 의 다른 모듈(문자·타이머·기동 복구 UPDATE)은 실DB 를 본다 → `setInterval` 차단은 필수 · 가능하면 워커2 `b700-ro.js` 꼴 읽기 전용 preload 로 띄울 것(CLAUDE.md #700). 끝나면 `DROP TABLE lucky_events_vui_assets, lucky_events_vui`(총괄에 알리고).
- 운영 표 이름(`lucky_events`·`lucky_assets`)을 LUCKY_TABLE 에 넣으면 모듈이 throw 로 멈춘다.
