# 자사몰(카페24) 판매가 = 네이버 정합 점검 · 인수인계서

> 최초 작성: 2026-09-06 (#426 — 대표 실물 "네이버·자사몰 판매가 다른 게 있는지 확인" 지시).
> 목적: **"자사몰 화면엔 맞게 뜨는데 실제 결제가 다르게 되는" 사고를 다시는 없게** 한다.

## 🔴 왜 "화면가"와 "결제가"가 갈라지는가 (대표 질문 — "왜 다르게 결제하기 누르면 되는거지?")

자사몰 상품 하나에 **가격이 두 군데**서 온다:

| 구분 | 어디서 오나 | 자동 동기화? |
|---|---|---|
| **화면 표시가** (akkome.com 카드·옵션 목록에 보이는 숫자) | 네이버 스냅샷(매일 새벽 04:30 수집 → `store-snapshot`) | ✅ 매일 자동 |
| **실제 결제가** (손님이 옵션 담고 [구매하기] 눌러 결제하는 값) | **카페24 옵션별 추가금**(variant `additional_amount`) | ❌ **자동 아님 — 손으로만** |

- 카페24 **기본가**는 새벽 `cafe24_sync`(05:10)로 네이버에 맞춰 자동 조정된다.
- 그러나 **옵션별 추가금은 자동이 아니다.** 네이버에서 옵션 가격을 올리거나 내리면, 카페24 추가금은 **옛날 값 그대로 남는다.**
- 결과: 화면(네이버 스냅샷)엔 새 가격이 뜨는데, 손님이 실제 담으면 **카페24 옛 추가금 기준으로 결제**된다 → 화면가 ≠ 결제가.
  - 손님이 **덜 내면** = 매출 손해 (2026-09 황금향 5kg 등 3옵션, 건당 −4,300원)
  - 손님이 **더 내면** = 과결제·환불 민원 (2026-08 청귤 #400, 2026-09 타이벡하우스 2.5로얄 +3,800·황금향3kg +4,300)

## ✅ 표준 점검·교정 절차

### 1) 점검 (판매가 대조)
```
node scripts/audit-400-priceset.js
```
- 판매중 상품별로 **카페24 실결제가 집합 vs 네이버 정본가 집합**을 정렬 비교한다.
- 🔴 **이름으로 매칭하지 말 것** — 카페24는 「·」, 네이버는 「/ 상품 및 과수:」로 형식이 달라 거짓 불일치가 난다. 반드시 **가격 집합**으로 대조(이 스크립트가 그렇게 함).
- `❌`가 뜨면 그 상품을 아래 3)으로 정밀 확인.

### 2) 네이버 정본 직접 조회 (스냅샷은 지연될 수 있으니 확정은 정본으로)
- `naver_query_request` 러너: `{calls:[{method:'GET',path:'/external/v2/products/origin-products/{originNo}'}]}`
- 응답은 `data_str`(문자열) → `JSON.parse` 후 `originProduct`.
- **기준가 = salePrice − 즉시할인(customerBenefit.immediateDiscountPolicy.discountMethod.value)**. 옵션 결제가 = 기준가 + `optionCombinations[].price`.
- ⚠️ **상품마다 기준가가 다르다**(c92는 29,000, c94는 33,500). 대조 스크립트를 새로 쓸 땐 각 채널의 자기 기준가를 쓸 것 — 남의 기준가를 쓰면 전 옵션이 어긋나 보인다(9/6 실수).

### 3) 카페24 추가금 교정 (네이버 기준으로 맞출 때)
- variant 코드 조회: `cafe24_product_request {action:'raw',method:'GET',path:'/api/v2/admin/products/{cno}/variants'}`
- 추가금 PUT: `{action:'raw',method:'PUT',path:'/api/v2/admin/products/{cno}/variants/{code}',body:{shop_no:1,request:{additional_amount:'{목표결제가 − 카페24기본가}'}}}`
- ⚠️ **카페24 GET은 ~1분 캐시** — PUT 직후 재조회는 옛값. 70초 뒤 재검산.
- 교정 후 반드시 `audit-400-priceset.js` 재실행으로 확인 + audit_logs 기록.

## ⚪ "가격은 맞는데 ❌"인 경우 = 옵션 구성 차이 (오류 아님)
- 한 채널에만 있는 옵션(예: 못난이 5kg = 네이버만 / 황금향 선물5kg = c92 카페24만)은 집합 크기가 달라 `❌`로 뜨지만 **공통 옵션 결제가는 일치**. 가격 오류가 아니다.
- 카페24는 **옵션 값 추가·삭제·이름변경을 API로 막아놨다**(422). 구성을 맞추려면 **대표가 카페24 관리자에서 수동**으로 해야 하며, 안 해도 결제가는 정확하다. 못난이(네이버만)는 akkome에서 담기 실패→확인 폴백(오담기 없음).
