# #824 계산서 발행현황 — 시온·효돈 묶음 머리 = 입금 기준(서버 계약 · 워커2 → 워커1)

배경(총괄 10/22): #823 머리는 「정산 − 계산서」였는데 대표가 쓰는 미발행계산서 엑셀은 **「입금 − 계산서」(입금했는데 계산서 안 온 돈)**. → 시온·효돈 머리를 입금 기준으로 바꿈. **CJ 는 무변경**(docs/823-api.md 그대로).

종전 칸(`settle_total` · `settle_basis` · `diff` · `issued_total` · `confirmed_total` · `count` · `check_count`)은 그대로. 줄 [확인]/[보류]·찾기·기간·PDF·[대조 확인] 무변경. #823 시온·효돈 `stats.balance` 는 **없어짐**(`mode` 가 `balance` → `paid`). **칸 이름 고정.**

## 0. 설정 — #823 그대로(`agent_office_config 'tax_invoice'`)
- `balance_start.date` = 기준일(기본 `2026-03-29`) · `balance_start.sion.carry` / `hyodon.carry` = **기준일 시점 「입금했는데 계산서 안 온 돈」**(기본 0 · 음수 허용 = 계산서가 앞선 돈).
- 기준일 앞 입금은 넣지 않는다(이월에 들어 있음 · 400).

## 1. 표 `tax_invoice_payments` (서버 기동 때 `CREATE TABLE IF NOT EXISTS` · tax-invoices.js ensureTable)
```
id SERIAL PK, supplier TEXT('sion'|'hyodon'), paid_on DATE, amount BIGINT(1~1,000,000,000), memo TEXT DEFAULT '',
source TEXT('manual'|'excel'), created_by INTEGER, created_name TEXT, created_at TIMESTAMPTZ DEFAULT NOW(), deleted_at TIMESTAMPTZ NULL
INDEX (supplier, paid_on)
```
- 지우기 = `deleted_at`(줄은 남음) · 모든 셈·목록·중복 검사는 `deleted_at IS NULL` 만.

## 2. GET /api/tax-invoices?from&to (또는 ?month) — 시온·효돈 `stats`

권한 = 종전(adminOnly · 직원 403).

```json
{ "supplier": "sion", "label": "시온(조천감귤농협)", "…종전 칸…": "…",
  "stats": { "mode": "paid", "start_date": "2026-03-29", "carry": 0,
             "cum_paid": 1500000, "cum_invoice": 1510099, "cum_settle": 1260099,
             "unissued": -10099, "unpaid": -239901, "paid_count": 2,
             "month_rows": [
               { "month": "2026-09", "paid": 500000, "invoice": 99, "diff": 499901, "balance": 499901 },
               { "month": "2026-10", "paid": 1000000, "invoice": 1510000, "diff": -510000, "balance": -10099 } ],
             "payments": [
               { "id": 12, "paid_on": "2026-10-02", "amount": 1000000, "memo": "시험 입금", "source": "manual", "by": "대표", "at": "2026-10-22T08:10:00.000Z" },
               { "id": 13, "paid_on": "2026-09-30", "amount": 500000, "memo": "", "source": "excel", "by": "대표", "at": "2026-10-22T08:11:00.000Z" } ] } }
```
(숫자는 시험 자료 · 실제 값 아님)

- `cum_paid` = `start_date` ~ `to` 입금 합(지운 것 뺌) · `paid_count` = 그 줄 수.
- `cum_invoice` = `start_date` ~ `to` 계산서 합(#823 그대로 · 보류 뺌 · 작성일, 못 읽은 줄은 받은 날 KST).
- `cum_settle` = `start_date` ~ `to` 우리 정산 합(#823 그대로 · 정산관리와 같은 단가 재계산).
- **`unissued` = `carry + cum_paid − cum_invoice`** = 미발행(입금했는데 계산서 안 온 돈 · + = 계산서 덜 옴 · − = 계산서가 앞섬).
- **`unpaid` = `cum_settle − cum_paid`** = 미입금(정산은 했는데 아직 안 보낸 돈 · 이월은 안 섞음).
- `to` 가 `start_date` 보다 앞이면 `cum_*` = 0 · `paid_count` 0 · `unissued` = `carry` · `unpaid` = 0.
- `month_rows` = `from~to` 에 걸린 달마다 1줄(오름차순 · CJ `month_rows` 와 같은 꼴) · **달 전체**(기간이 달 중간이어도 · 기준일로도 자르지 않음) · `paid` = 그 달 입금 합 · `invoice` = 작성일이 그 달인 계산서 합(보류 뺌) · `diff = paid − invoice`.
- **`month_rows[].balance` = 월말 누적 잔액** = `carry + (start_date ~ 그 달 말일 입금) − (start_date ~ 그 달 말일 계산서)` · 기준일이 든 달은 그 달 기준일부터 · 기준일 앞 달 = `carry`. 🔴 대성은 입금이 주 단위라 `diff`(달 차)가 달마다 ±로 흔들려도(예: 9월 말 입금이 10월 계산서 몫) `balance` 는 0 으로 맞을 수 있음 → 화면은 `balance` 를 주로, `diff` 는 보조로. 마지막 달 `balance` = 그 달 말일 기준(머리 `unissued` 는 `to` 기준 · `to` 가 달 말일이면 같음).
- `payments` = `from~to` 안 입금(지운 것 뺌) · `paid_on` 내림차순(같은 날 = id 내림차순) · **상한 200**(건수·합계는 전부 셈) · `by` = 넣은 사람 이름 · `at` = 넣은 시각 · `source` = `manual` | `excel`.
- CJ `stats` = #823 그대로(입금 칸 없음).

## 3. POST /api/tax-invoices/payments — 입금 넣기(adminOnly)
요청:
```json
{ "supplier": "sion", "paid_on": "2026-10-02", "amount": 1000000, "memo": "선택" }
```
- `amount` = 정수(숫자 또는 숫자만 든 글자 「1000000」 · 쉼표 글자 400).
응답 200 `{ "ok": true, "id": 12 }`
오류:
- 400 `supplier 는 sion · hyodon` / `paid_on 은 YYYY-MM-DD`(없는 날 포함) / `기준일(2026-03-29) 앞 입금은 넣지 않아요 — 이월(carry)에 들어 있어요` / `금액은 1원 ~ 10억 원 정수` / `메모는 200자까지`
- 409 `같은 입금이 이미 있어요`(같은 supplier + paid_on + amount 살아 있는 줄 · 메모 달라도) — 거래처가 다르면 받음 · 지운 뒤엔 다시 받음
- 403(adminOnly) · 500 `입금을 저장하지 못했어요 — 잠시 뒤 다시`
- 감사 = action `payment_add` · targetType `tax_invoice_payment` · targetId = 입금 id · source `tax_invoice` · changes `{supplier, paid_on, amount, source}`.

## 4. DELETE /api/tax-invoices/payments/:id — 지우기(adminOnly)
- 응답 200 `{ "ok": true }` · 이미 지웠거나 없는 번호 404 `그 입금이 없어요(이미 지웠거나 없는 번호)` · 숫자 아님 400.
- 감사 = action `payment_del`(성공 때만).
- 화면은 성공 뒤 GET 을 다시 불러 그리면 됨.

## 5. POST /api/tax-invoices/payments/import — 미발행계산서 엑셀 가져오기
권한 = adminOnly. 규격 = 워커3 #824-A(대표 바탕화면 「미발행계산서(26년).xlsx」 꼴).

요청:
```json
{ "data": "<xlsx 파일 base64 · data:…;base64, 머리 붙어도 됨>", "dry": true }
```
- `dry` 를 안 주면 **dry**(안전 쪽) · 실제로 넣으려면 `"dry": false`.
- 파일 상한 5MB(풀었을 때).

읽는 법:
- 시트 이름에 「대성」 → `sion` · 「효돈」 → `hyodon` · 그 밖 시트(한라포장·조천CJ·초당 …) 안 읽음.
- 열 고정 **A = 결제날짜(엑셀 날짜 칸) · B = 입금금액** · C~끝 = 메모(글 원문을 ` / ` 로 이어 저장 · 500자 · 안의 날짜·금액은 안 읽음). 머리줄 위치가 시트마다 달라 열 이름은 안 찾음.
- 읽는 줄 = A 가 날짜 칸 **그리고** B 가 숫자(수식 아님) **그리고** 1 ~ 10억 정수. 머리줄·빈 줄·합계줄(A 글자 · B 수식)·대성 아래 계산서 음수 줄·0 은 저절로 빠짐.
- `unreadable` = B 는 양수인데 A 가 날짜 칸이 아닌 줄(글자로 친 날짜 등) 건수 — 넣지 않고 알리기만.
- 기준일(`balance_start.date`) 앞 줄 = `before_start` 로 셈 · 안 넣음.
- 같은 supplier + paid_on + amount 살아 있는 줄이 이미 있거나 같은 파일 안에 앞 줄과 같으면 = `dup` 으로 셈 · 안 넣음 → 같은 파일을 다시 올려도 0줄.
- 입금 줄 ↔ 계산서 줄은 1:1 아님(한 입금 = 계산서 여러 장) → 짝 맞추기 없음 · 합계로만.

응답 200:
```json
{ "ok": true, "dry": true, "new": [ { "supplier": "sion", "paid_on": "2026-09-28", "amount": 1250099 } ],
  "dup": 1, "before_start": 1, "unreadable": 1, "sheets": ["대성", "효돈"] }
{ "ok": true, "dry": false, "new": [ "…" ], "dup": 1, "before_start": 1, "unreadable": 1, "sheets": ["대성", "효돈"], "inserted": 3 }
```
- 실행이면 `source` = `excel` · 넣은 사람 = 누른 계정 · 감사 = action `payment_import`(넣은 줄이 있을 때만 1줄) · changes = 건수만 `{inserted, dup, before_start, unreadable}`(금액·날짜 없음) · targetId null.
- 빈 시트 = 200 · `new` 빈칸 · `inserted` 0.

오류: 400 `data 는 base64 엑셀 파일` / `파일은 5MB 까지` / `엑셀을 읽지 못했어요 — xlsx 파일인지 확인해 주세요` / `「대성」·「효돈」 시트가 없어요` · 403 · 500 `입금을 저장하지 못했어요 — 잠시 뒤 다시`. 파일·금액은 서버 로그에 안 찍음.

실파일 읽기 확인(워커2 · 읽기만 · DB 0): 대성 50줄 · 효돈 41줄 → 기준일 3/29 뒤 39 · 30 · 글자 날짜 0 · 달마다 줄 수 = 워커3 조사와 같음.
