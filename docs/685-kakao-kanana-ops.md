# #685-C 카카오 채널 「카나나 상담매니저」 — 영향 점검 + 문서 초안

- 작성: 워커2(claude-cc) · 2026-10-14 · 읽기만(코드·DB·설정 변경 0 · DB 는 SELECT 1회)
- 카나나 = 카카오가 채널 1:1 채팅에 붙여 주는 AI 1차 응대(오픈빌더 챗봇 아님). 재료 = 채널 홈·메뉴·소식 + 직원이 「AI 답변으로 등록」한 답.

## 1. 영향 점검 결과

### ⓐ 우리 DB·알림 = 변화 0
- 카카오 글이 우리 DB(`message_logs` · user_id `kakao:`)로 들어오는 길은 **톡톡봇 `/kakao-skill` 하나뿐**이다(톡톡봇 `kakao-skill.js` 51행 · 장착 = 톡톡봇 `server.js` 1265행). 오픈빌더 챗봇이 이 주소를 불러야만 글이 온다.
- 회사프로그램 `server.js` 에는 카카오 글을 **받아 오는 코드가 없다**. `message_logs` 를 읽기만 한다:
  - 텔레그램 「📮 톡톡 확인」 = `server.js` 6544~6598행(대상 = 6554행 SELECT · 채널 표기 6538행 `chLabel` · 낱말표 6542행 `NEEDS_STAFF_RE`)
  - 「지금 챙길 일」 봇 실패 줄 = 14394~14400행(같은 낱말표)
  - 손님 연락 창 = `inbox-threads.js` 112~118행(카카오는 보기만 · 「관리자센터에서 답해 주세요」) · 미처리 셈은 톡톡만(147행)
  - 문의 관리 표의 「카카오채널」 배지 = `public/app.js` 14283행(user_id 앞글자로 표시만)
- 실DB(10/14 조회): `kakao:` 35건 · **마지막 2026-08-09 10:14 · 최근 30일 0건**. 8/9 챗봇 OFF 뒤로 들어온 글 없음.
- 카나나 이용 조건이 「챗봇을 사용하지 않는 채널」이라 `/kakao-skill` 길과는 **함께 켤 수 없다** → 카나나를 켜도 `kakao:` 줄은 계속 0 · 텔레그램·챙길 일·손님 연락 창 숫자 무변화.
- 뒤집어 말하면 **카나나 대화는 회사프로그램 어디에도 안 보인다**(텔레그램 알림 없음 · 에이전트 오피스에 안 뜸). 직원이 볼 곳은 카카오 채널 관리자센터(앱) 채팅 목록뿐.

### ⓑ 알림톡 버튼 — 엮이는 것은 「문의하기(MD)」뿐 · 단 발송안내4만이 아님
- 버튼 종류(`scripts/alimtalk-templates.json`): 채널 추가(AC) · 웹링크(WL = 배송조회 `/track` · 안내 `/guide` · 자사몰) · 문의하기(MD = 누르면 알림톡 글이 채널 채팅으로 전달).
- AC·WL 은 채팅을 열지 않는다 → 카나나와 무관.
- MD 가 붙은 템플릿 = `kakao-notify.js` 44행 `MD_TPL_KEY` 의 7종 전부: 주문안내 UK_5754 · 예약 UK_5755 · 발송안내3 UK_5756 · **발송안내4 UM_2824** · 환영 UK_5877 · 쿠폰 UL_7570·UL_7571. 즉 **주문안내·쿠폰 알림의 [문의하기]로 들어온 손님도 카나나가 먼저 받는다**.
- 미확인: 지금 Render env 로 실제 쓰는 코드(파일 표만 봄) · 이미지형 템플릿(WL → pf.kakao.com/_lbJLs/chat)은 쓰는지 안 봄(쓴다면 그것도 채팅으로 감).

### ⓒ 자사몰 「AI상담」(akkome.com/?chat=1) — 충돌 없음
- 그 창은 카카오 밖 웹 채팅이다(`mall:` → 톡톡봇 · 실DB 최근 30일 45건 · 마지막 10/12). 카나나와 통로가 다르다.
- 스킨 파일은 다른 저장소(akkome-website)라 이번에 열지 않았다(주소·구조는 CLAUDE.md 기록 기준).

### ⓓ 채팅방 메뉴·자동응답 메시지·첫인사와 동시 사용
- 공식 가이드(kakaobusiness.gitbook.io/main/channel/run/chat)의 카나나 이용 조건 = **비즈니스 인증 · 챗봇 미사용 · 채널 공개** 세 가지뿐. 채팅방 메뉴·자동응답 메시지를 꺼야 한다는 문장은 없다.
- cs.kakao.com 1073196492 는 「채팅방 리스트 메뉴·자동응답 메시지 ↔ **챗봇**」 배타만 말한다. 카나나 언급 없음.
- → 동시 사용을 막는 문서 근거는 없다. 하지만 **「같이 쓸 수 있다」고 적은 문장도 못 찾았다**(첫인사·부재중 메시지 포함). 잠자는 자동응답 6개는 「연결되지 않음」이라 손님에게 나갈 길이 없어 영향 없을 것으로 봄(추정).

## 2. 보고 세 묶음

**막을 것**: 없음(우리 쪽 코드·DB·알림 변화 0).

**알려 둘 것**
1. 카나나 대화는 우리 화면·텔레그램에 안 뜬다. [관리자 호출] 뱃지를 놓치면 알려 주는 장치가 없다 → 회사폰 채널 관리자 앱 알림이 켜져 있어야 한다.
2. 카나나는 **채널 홈·소식에 적힌 글로 답한다**. 우리 발송 달력·휴무일·판매현황 가격·시나리오 DB 를 모른다 → 발송일·가격·행사 답이 톡톡봇과 다를 수 있다(「발송일 안내는 계산기 하나만」 원칙 밖). 켜기 전에 채널 홈·소식의 낡은 글(끝난 시즌·행사)을 정리할 것.
3. [문의하기] 버튼은 발송안내4 말고도 주문안내·환영·쿠폰 알림톡에 다 있다(ⓑ).
4. 손님에게 AI 창구가 둘이 된다(카카오 = 카나나 · 자사몰 「AI상담」 = 우리 봇). 지식 원본이 달라 답이 갈릴 수 있다.
5. 나중에 톡톡봇 `/kakao-skill`(챗봇)로 되돌리려면 카나나를 먼저 꺼야 한다(조건이 서로 배타).
6. `server.js` 6598행 주석 「카카오는 이 알림이 유일한 통로」는 낡았다(동작 무해 · 고칠 필요 없음).

**이상 없음**: ⓐ DB·알림 · ⓑ AC·WL 버튼 · ⓒ 자사몰 AI상담.

**미검증(켠 뒤 실물로 볼 것)**
- 직원이 답하는 중에 카나나가 끼어드는지 · 관리자 답변 모드에서 카나나 모드로 언제 돌아가는지(가이드에 없음)
- [문의하기](MD)로 알림톡 글이 통째로 들어왔을 때 카나나가 뭐라고 답하는지
- 사진·클레임 글에 카나나가 답하는지 · 채팅방 메뉴·첫인사와 순서가 겹치는지 · 항상 답하는지 부재중에만 답하는지 · 요금(가이드에 없음 · 검색 요약에 「무료」)

## 3. 초안 A — ★에이전트오피스/업무지식.md 에 넣을 절(직원용)

### 카카오 채널 응대(카나나)
- 카카오 채널 채팅은 카카오의 AI(카나나 상담매니저)가 먼저 답한다. 우리 톡톡봇과는 다른 AI 이고, 채널 홈·소식에 적힌 글과 우리가 등록해 준 답으로만 답한다.
- 볼 곳은 카카오 채널 관리자 앱(회사폰)의 채팅 목록이다. 에이전트 오피스·텔레그램에는 안 뜬다.
- 채팅 목록에 **[관리자 호출]** 뱃지가 보이면 손님이 사람을 찾은 것이다. 그 방을 열어 직원이 이어서 답한다(열고 나오면 뱃지는 사라지니, 연 사람이 끝까지 답한다).
- 뱃지가 없어도 하루 두 번(오전·오후) 채팅 목록을 훑어 AI 답이 틀린 곳이 없는지 본다. 틀렸으면 직원이 바로 고쳐 답한다.
- 직원이 보낸 좋은 답은 그 말풍선을 길게 눌러 **「AI 답변으로 등록하기」** — 다음 비슷한 문의부터 AI 가 그 답을 쓴다. 날짜·금액이 든 답은 등록하지 않는다(낡는다).
- 파손·부패·환불·교환·보상 금액·주소 변경·취소는 AI 답과 상관없이 사람이 답한다.
- 발송일·가격·행사를 AI 가 틀리게 말했으면 직원이 정정하고 대표에게 알린다(채널 홈·소식 글을 고쳐야 한다).
- 끄는 곳: 채널 관리자센터 › 채팅 › 카나나 상담매니저 › 끄기(끄면 바로 종전처럼 직원이 전부 답한다).
