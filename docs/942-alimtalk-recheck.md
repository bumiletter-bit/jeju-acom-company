# #942 체험 알림톡 교환권 문장 재심사

대표 결정(11/1 A안) = 예약확인·방문안내 알림톡의 교환권 문장을 바꿔 다시 심사. **승인 전까지 옛 템플릿(UM_6987·UM_6988)으로 그대로 발송.**

바뀌는 곳은 두 장 모두 한 문장뿐이다.
- 전: (체험 당일 사용 · 제주시 서흘길 9, 3층)
- 후: (체험 시즌 중 언제든 사용 · 제주시 서흘길 9, 3층 · 10~20시)

## 등록 길

**길 1 = 서버 러너(추천 · 대표 폰 인증 불필요).** 로컬 PC 는 알리고 키가 없고 사이트는 대표 폰 인증(MFA)이 필요해서, 키가 있는 서버의 기존 러너를 쓴다.
1. 이 묶음(`scripts/alimtalk-templates.json` `templates_exp2` + `kakao-notify.js` 묶음 이름 1줄)을 배포한다.
2. 🔴 새 판으로 완전히 바뀐 뒤(`/api/public/version` 확인 + 몇 분) 요청 줄을 넣는다. 배포 중 옛·새 인스턴스가 겹칠 때 넣으면 중복 등록될 수 있다(#398 롤링 사고).
   ```sql
   INSERT INTO agent_office_config (key, value, updated_at) VALUES ('aligo_register_request', '{"go":"yes","audit":true,"set":"exp2"}', NOW())
   ON CONFLICT (key) DO UPDATE SET value = EXCLUDED.value, updated_at = NOW();
   ```
3. 1분 안에 `aligo_register_result` 에 새 코드(`tpl_code`)와 검수 신청 결과가 적힌다. 🔴 실패해도 같은 요청을 바로 다시 넣지 말 것(앞 장이 이미 등록됐을 수 있음 · `only` 로 남은 장만).

**길 2 = 대표가 알리고 사이트에서 직접.** 아래 전문을 붙여 넣는다.

## 승인 뒤 할 일(총괄)

순서를 지킨다. 코드만 먼저 바꾸면 승인 원문과 달라져 알림톡이 실패한다.
1. `aligo_selftest_request {full:true}` 로 새 코드 상태 APR 과 `template/list` 원문을 읽어 위 전문과 글자까지 대조한다.
2. `experience.js` `EXP_ALIMTALK` 의 열쇠를 새 코드로, 본문을 승인 원문으로 교체하고 `NOTIFY_DEFAULT.alimtalk` 기본 코드도 바꾼다. 배포한다. 새 상수와 옛 설정 코드가 잠깐 안 맞으면 그 사이는 LMS 로 나간다.
3. 실DB `experience_notify.alimtalk` 의 `confirm_tpl`·`remind_tpl` 을 새 코드로 바꾼다(audit).
4. 실DB `tpl_recv`·`tpl_eve` 문장과 `experience.js` `DEFAULT_TPL_RECV`·`DEFAULT_TPL_EVE` 도 같은 뜻으로 바꾼다. 대체 문자·LMS 글이다.
5. 다음 실제 예약 1건에서 `sms_recv_via = alimtalk` 을 확인한다.
6. 옛 UM_6987·UM_6988 정리: 대표 지시(11/3)로 러너 삭제 시도 → 알리고 509 「삭제 가능 상태가 아닙니다」(승인 status A). 발송엔 안 쓰임 · 알리고 화면 길은 대표 폰 인증 뒤 확인. 11/3 교체·시험 합격 끝(v5.9.694).

## 그동안

손님 알림톡은 승인 전까지 「체험 당일 사용」으로 나가고, 봇·상세는 「시즌 중 사용」으로 안내한다. 손님에게 더 넉넉한 쪽이라, 현장에서 다음 날 교환권도 받으면 된다. 알림톡에는 라운지 영업시간이 없으므로 09·10시 문제는 없다.
