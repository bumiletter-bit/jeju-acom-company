## 4. 짝 맞추기·입력삭제 처리 규칙(오매칭 > 미매칭)
- **열쇠 1(확정 · 추천)**: 거래처 택배사 양식(A~K)에 **네이버 상품주문번호(쿠팡 shipmentBoxId · 자사몰 order_item_code)를 LOIS 가 운송장 시트에 그대로 보존하는 칸**에 심는다(LOIS 「고객주문번호/참조」 칸이 있는지 = **샘플로 확인**) → 운송장 ↔ 주문 1:1 · 애매 0. 심을 칸이 없으면 열쇠 2.
- **열쇠 2(폴백)**: 받는 분 이름 + 받는 분 번호(숫자) + 주소(공백 제거) + 박스 수 가 **전부** 같을 때만 짝 · 하나라도 다르면 「확인 카드」(사람이 고름) · 같은 열쇠에 주문 둘 이상(같은 분께 두 주문) = 카드 · 선물하기(번호 가림 010-0000-0000) = 카드.
- **박스 n개(수량 2↑ 또는 #601 박스별 줄)**: 운송장 n개 ↔ 상품주문 1건 → 네이버 파일엔 **첫 운송장**(가장 작은 번호)만 · 나머지는 메모 칸이 아니라 **문자 응대·배송조회가 delivery_shipments 에서 전부 보여 줌**(#643 「송장도 다 알려주도록」 이미 됨) → 손님 안내는 빠지지 않음.
- **입력삭제(개별 주소)**: 현금파일 주소 줄 ↔ 운송장 = 받는 분 이름+주소 로 짝(그 줄은 우리 주문 주소와 다름) → 스토어 시트 노란 줄에 ①4박스 중 1박스만 다른 주소 = **그 1개 운송장** ②4박스 전부 개별 = **대표 결정 필요**(「주문자 요청 주소 중 1개 또는 4개」 — 네이버 칸은 1개라 4개는 못 들어감 → 규칙 제안 = 첫 운송장 1개 + 나머지는 문자 응대 자료) · 전부 카드로 보여 주고 사람이 [이 송장] 고르기(자동 금지).
- **그 밖**: 운송장 시트에 있는데 주문에 없는 줄(재발송·수기) = 「주문 없음」 목록 · 주문은 있는데 운송장이 없는 줄 = 빈칸+빨강(그날 안 나감) · 날짜요청 제외 건은 애초에 스토어 시트에 없음 → 그대로.
