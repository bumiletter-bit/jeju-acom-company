# #838-C 보고(워커3) — 입력삭제 메모 4꼴 가상 시험(코드 변경 0 · 실주문·실DB·실발송·실AI 0 · 가짜 번호 010-0000-xxxx 만)

## 시험 방법
- 최종발주 **실코드**를 그대로 돌림 = `public/final-order-core.js`(Node 모듈 · sizeLines → prepLines → applySenders → parseCash/cashCheck → buildRows) + `public/invoice-v2.js` 의 순수 함수(parseLines·applyLines·matchKey·telOf·idsOf·parseDate)를 떼어 냄 · 브라우저·서버·AI 호출 0.
- 가짜 주문 8건(네이버 6 = 일반·수량 4·황금향·2.5kg 로얄과·보내는이 대상·선물하기(구매자 번호 자리표시) · 쿠팡 1 · 자사몰 1) · 가짜 현금파일(13칸 양식 · 「!」 없는 줄 = 개별 주소 1줄 또는 2줄) · 기준 발송일 10/24 · 시나리오 4개(A 대표 메모 4줄 그대로+현금 1줄 · B 현금 2줄(2+2) · C ④ 되는 꼴+선물하기 사이즈+자사몰 주문번호+쿠팡 번호 · D 탭 꼴+「드림」만).
- 재현하지 않은 것 = 화면 카드 클릭 · AI 메모 읽기(aiToCards) · 손님 배송메모 해석(memoFlag) · v2 시트 실제 xlsx 쓰기(규칙만 재현 · buildSheet2 코드 읽음).

## 그 밖에 확인된 것
- 번호 매칭 = 메모 줄은 **구매자연락처(숫자 전체) 또는 주문번호(상품주문번호·주문번호·자사몰 YYYYMMDD-NNNNNNN)** · 자리표시 번호(010-0000-0000 류)는 매칭 금지 · **받는 분 번호로는 안 맞음**(사이즈 줄만 카드로 구제 · 입력삭제·날짜 줄은 「주문 없음」) → 선물하기 주문의 입력삭제는 메모 줄로 못 지정(현금파일 대조도 unchecked).
- 날짜 없는 입력삭제 줄 = 기준 발송일로 읽음(notes 안내) · 「개별발송」 낱말만 있어도 「입력o삭제x」로 바꿔 읽음.
- 쿠팡·자사몰 주문도 같은 규칙(채널 = 플랫폼 낱말 또는 주문번호 꼴 · 없으면 네이버).
- 하네스 한계 = 쿠팡 옵션 「…, 1개」가 거래처 미매칭으로 나온 것은 가짜 자료가 convertDataCoupang 정규화를 안 거친 탓(실코드 문제 아님).
