# #838-1 자동 송장 등록 — 화면 계약(서버 워커3 · 화면 워커1)

> 정본 = `838-자동송장등록-시공설계(정본).md` 2절 규칙. 이 문서는 요청·응답 JSON 꼴만. 1단계 = **외부 쓰기 0**(match 는 읽기 + 색인 저장 · register 는 dry 만).
> 🔴 파일 받기 = **JSON 본문 + base64**(기존 LOIS 업로드 `/api/delivery/shipments/upload` 와 같은 꼴 · 서버에 multer 없음 · express.json 15MB 안). 파일 1개 ≤ 5MB · 최대 4개.

## 1. POST `/api/agent-office/invoice-auto/match` (로그인 누구나)

### 요청
```json
{
  "files": [
    { "name": "제주아꼼이네송장(효돈)10.24.xlsx", "data": "<base64 · data:... 머리 있어도 됨>" },
    { "name": "제주아꼼이네송장(대성)10.24.xlsx", "data": "<base64>" }
  ],
  "ship_date": "2026-10-24",   // 선택 · 없으면 파일 이름 「MM.DD」 → 없으면 오늘(KST)
  "days": 30                   // 선택 · 3채널 재조회 기간(1~60 · 기본 30)
}
```
- 파일 안 시트 = 머리글(1~8행)에 「운송장번호」가 있는 시트(시트2 꼴 · 시트1 이 같이 있어도 됨).
- 거래처 = 파일 이름 괄호 「(효돈)」 → 없으면 `"?"`.

### 응답(200)
```json
{
  "ok": true,
  "run_id": 17,
  "ship_date": "2026-10-24",
  "files": [ { "name": "제주아꼼이네송장(효돈)10.24.xlsx", "partner": "효돈", "rows": 99 } ],
  "fetch": { "naver": { "ok": true, "orders": 412 }, "coupang": { "ok": true, "orders": 3 }, "cafe24": { "ok": false, "orders": 0, "error": "재승인 필요" } },
  "by_channel": {
    "naver":   { "auto": 240, "todo": 1, "cash": 0, "skipped": 2 },
    "coupang": { "auto": 3,   "todo": 0, "cash": 0, "skipped": 0 },
    "cafe24":  { "auto": 0,   "todo": 0, "cash": 0, "skipped": 0 }
  },
  "summary": { "shipments": 251, "auto": 243, "todo": 2, "cash": 3, "extra": 3, "unmatched": 0, "index_upserted": 251 },
  "rows": [
    {
      "id": "r1",                       // 이 실행 안에서만 유일 · register 에 그대로 보냄
      "channel": "naver",               // naver | coupang | cafe24
      "order_key": "2026102412345678",  // naver = 상품주문번호 · coupang = shipmentBoxId|vendorItemId · cafe24 = order_id|order_item_code

      "item_code": null,                // cafe24 만 = order_item_code(그 밖 null)
      "recipient_masked": "김*수 · 끝 1234",
      "option": "하우스감귤 가정용 - 3kg(소과)",   // 채널 주문의 옵션 글(손님 정보 아님)
      "qty": 1,
      "tracking": "612345678901",       // 자동이면 고른 운송장(숫자만 12자리 · 화면이 4-4-4 로 끊어 보임) · todo 면 null
      "tracking_all": ["612345678901"],  // 그 주문에 붙은 운송장 전부(수량 2 = 2개 · 첫 번째가 tracking)
      "rule": "auto",                   // 아래 3절 표
      "status": "auto",                 // auto | todo
      "pick_options": []                // todo 일 때만 = [{ "tracking": "...", "recipient_masked": "...", "product": "..." }]
    }
  ],
  "cash": [ { "tracking": "6123-...", "recipient_masked": "박*진 · 끝 5678", "product": "...", "why": "보내는이 ! = 현금 주문(송장만)" } ],
  "extra": [ { "tracking": "6123-...", "recipient_masked": "...", "why": "같은 구매자의 다른 주소 박스(입력삭제 나머지 · 등록 안 함 · 색인에만)" } ],
  "unmatched": [ { "tracking": "6123-...", "recipient_masked": "...", "product": "...", "why": "그날 주문에 받는분 이름·번호·주소가 같은 주문이 없어요" } ],
  "orders_without_tracking": 169   // 재조회 주문 중 운송장이 안 붙은 수(지정발송일·아직 안 보낸 주문 · 할 일 아님)

```
- 화면 묶음 = 채널별 `by_channel` 칩 · 「자동 n」 접힘 목록 · 「할 일 n」 카드(rows 중 status todo · `pick_options` 에서 운송장 고르기 또는 「수기」) · 「현금 n(송장만)」 · 「다른 주소 박스 n」 · 「주문 없음 n(unmatched)」.
- 손님 이름은 가림(`김*수`) · 번호는 끝 4자리만 · 주소는 응답에 없음.
- `by_channel.x.cash` 는 늘 0(현금 줄은 채널을 모름 → `summary.cash`·`cash[]` 를 볼 것) · `skipped` = 그 채널 주문에 붙었지만 등록 안 하는 운송장 수(수량 2 의 둘째 · 같은 구매자 나머지 박스).
- 409 = 다른 사람이 짝 맞추기를 돌리는 중(한 번에 하나).
- 오류: 400 `{ ok:false, error }`(파일 없음·5MB 초과·운송장 시트 없음·4개 초과) · 3채널 재조회가 하나 실패해도 200(그 채널 `fetch.x.ok=false` · 그 채널 주문은 짝 안 됨 → 그 채널 운송장은 unmatched).

## 2. POST `/api/agent-office/invoice-auto/register` (관리자만 · 1단계 = dry 고정)

### 요청
```json
{
  "run_id": 17,
  "picks": { "r5": "6123-4567-0000", "r9": "manual" },   // todo 줄의 선택(운송장 또는 "manual" = 수기) · 자동 줄은 안 보내도 됨
  "skip": ["r12"],                                        // 이번에 보내지 않을 자동 줄(선택)
  "dry": true                                             // 1단계는 무엇을 보내도 dry 로 처리(실제 전송 0)
}
```

### 응답(200)
```json
{
  "ok": true, "run_id": 17, "dry": true, "send_enabled": false,
  "ready": { "naver": 241, "coupang": 3, "cafe24": 0 },
  "already": 0,            // 같은 멱등 열쇠(채널:주문번호:운송장)가 앞 실행에서 「전송 준비」·「보냄」 이었던 수(다시 안 보냄)
  "manual": 1,             // 수기로 남긴 줄
  "skipped": 1,
  "items": [ { "id": "r1", "channel": "naver", "order_key": "...", "tracking": "612345678901", "idem": "naver:2026...:612345678901", "state": "ready" } ],
  "manual_file": null      // 2단계(#838-3)부터 = 실패·수기 줄 내려받기 주소
}
```
- 상태 저장 = 실행 행 `register_state = 'prepared'` · 멱등 열쇠 표에 `ready` 로 기록(같은 열쇠 두 번째부터 `already`).
- 403 = 관리자 아님 · 404 = run_id 없음 · 409 = 그 실행이 이미 「보냄」(2단계).

## 2-b. #838-4 전송(register `dry:false` + 설정 `invoice_auto.send_enabled` true 일 때만)

- `dry:false` 인데 설정이 꺼져 있으면 **409** `{ ok:false, error:"자동 송장 전송이 꺼져 있어요(…send_enabled)…", dry:true, send_enabled:false, ready, … }`(준비는 저장 · 전송 0).
- `dry` 를 빼거나 true 면 종전과 같은 준비 응답(`send_enabled` 는 설정 실제 값).
- 전송 응답(200):
```json
{ "ok": true, "run_id": 17, "dry": false, "send_enabled": true,
  "ready":   { "naver": 241, "coupang": 3, "cafe24": 1 },
  "sent":    { "naver": 239, "coupang": 3, "cafe24": 1 },
  "failed":  { "naver": 1,   "coupang": 0, "cafe24": 0 },
  "unknown": { "naver": 1,   "coupang": 0, "cafe24": 0 },
  "already": 0, "manual": 1, "skipped": 0,
  "confirmed": { "naver": 239, "checked": 239 },
  "items": [ { "id": "r1", "channel": "naver", "order_key": "...", "box_id": "...", "tracking": "612345678901", "idem": "naver:...:612345678901", "state": "sent" },
             { "id": "r7", "channel": "naver", "state": "failed", "error": "INVALID_STATUS 발송 처리할 수 없는 상태" },
             { "id": "r8", "channel": "naver", "state": "unknown", "error": "응답에 처리 결과 없음" } ],
  "manual_file": "/api/agent-office/invoice-auto/manual/17" }
```
- items[].state = `sent`(보냄) · `failed`(채널이 거절 · 사유 error · 다음 실행에서 다시 보낼 수 있음) · `unknown`(응답에 없음·연결 끊김 = **다시 안 보냄** · 채널 화면에서 확인) · `already`(앞 실행에서 보냄·보내는 중·모름) · `manual` · `skipped` · `ready`(dry).
- 쿠팡은 상자(box_id) 하나 = 한 단위 → 상자 안 줄이 여럿이면 줄마다 같은 state. 상자의 다른 줄을 건너뜀·수기로 두면 상자째 `manual`.
- 카페24 CJ 배송사 코드는 설정 `invoice_auto.cafe24_carrier_code` — 없으면 카페24 줄은 `failed` 「…코드 설정 없음」(보내지 않음).
- 보낸 실행에 다시 register = 409(실패 줄은 [짝 맞추기]를 새로 해서 보냄 · 보낸 주문은 already).
- 500 = 「보낸 줄이 있을 수 있으니 채널 화면을 먼저 확인」.

## 2-c. GET `/api/agent-office/invoice-auto/manual/:run_id`(로그인) = 실패·모름·수기 줄 xlsx
- 시트 「발송처리」(네이버 · 센터 엑셀 일괄발송 꼴) = 상품주문번호 · 배송방법(택배,등기,소포) · 택배사(CJ대한통운) · 송장번호 · 받는분(가림) · 옵션 · 사유.
- 시트 「쿠팡·자사몰」 = 채널 · 주문번호 · 배송번호·품주코드 · 운송장 · 받는분(가림) · 옵션 · 사유.
- 화면은 Authorization 머리를 붙여 fetch → blob 으로 내려받기(주소만 열면 401).

## 3. rule 값(정본 2절)

| rule | 뜻 | status |
|---|---|---|
| `auto` | 받는분 이름+번호+주소 셋 다 같은 주문 1건 · 운송장 1개 | auto |
| `auto_multi` | 위와 같고 운송장 여러 개(수량 2 등) · 첫 운송장을 등록 · 나머지는 색인만 | auto |
| `auto_qty_diff` | 셋 다 같은 주문 1건인데 운송장 수 ≠ 주문 수량(첫 운송장 등록 · 화면에 「박스 수 다름」 작은 글) | auto |
| `by_product` | 같은 분 다른 품목 여러 주문 → 시트2 상품명으로 가름 | auto |
| `same_item_any` | 같은 분 같은 품목 여러 주문 → 아무거나 1개씩 | auto |
| `indiv_store_addr` | 셋 다 맞는 운송장 없는 주문 → 구매자 번호(보내는분 전화)로 나간 운송장 중 스토어 주소와 같은 것 | auto |
| `indiv_any` | 위인데 스토어 주소 운송장 없음 → 그 구매자 운송장 중 아무거나 1개 | auto |
| `todo_product` | 같은 분 여러 주문인데 상품명으로 못 가름 | todo |
| `todo_pick` | 그 밖 사람이 골라야 하는 줄 | todo |

- 현금(보내는분 이름에 「!」) · 같은 구매자 나머지 박스 · 짝 없는 운송장은 rows 가 아니라 `cash` · `extra` · `unmatched` 에.
