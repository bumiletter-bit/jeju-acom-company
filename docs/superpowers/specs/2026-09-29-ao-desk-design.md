# #469 에이전트 오피스 → 클코 창구 전환 (설계 · 대표 GO 2026-09-29)

## 대표 확정
- 에이전트 오피스 처리 주체 = **전부 클코**(대표 PC의 「창구」 터미널). API 마루·에이전트 9명은 쓰지 않는다. 검증 뒤 코드 삭제.
- 창구가 꺼져 있으면 요청은 쌓였다가 켜진 뒤 처리(API로 넘기지 않음).
- 손님 응대(톡톡봇·상품문의·고객문의 자동 답변)는 **API 그대로 · 무접촉**(에이전트 오피스와 별개).
- 사용 대상 = 전 직원. 버튼 = 「클코에게 지시하기」. 조직도·법인/오션라운지 필터 제거.
- 디자인 = 에이전트 오피스 화면만 새 디자인(어두운 관제실 풍 · 클코가 구상 · 캐릭터는 힉스필드로 제작). 날씨 없음 · 채널별 주문현황 포함. 다른 메뉴는 인디고 가이드 유지.
- 힉스필드(이미지·영상 생성) = 직원 재량 사용.

## 처리 선(창구 규칙의 핵심)
| 구분 | 예 | 처리 |
|---|---|---|
| 바로 | 조회·보고, 초안, 시나리오·안내 문구 수정, 정산관리 입력·이름 교정, 판매현황 상태 변경, 힉스필드 생성 | 직원 요청만으로 실행 · audit · 되돌릴 수 있는 것만 |
| 대표 승인 후 | 쿠폰 발급, 가격 변경, 손님에게 나가는 발송, 카페24·네이버·알리고 설정 변경 | 「승인대기」로 올림 → 대표/조가영 [승인] 뒤 실행 |
| 금지 | 코드 수정, 배포, 데이터 삭제 | 창구는 거절하고 대표 창(총괄)으로 넘김 |

## 구조
```
직원: 회사프로그램 에이전트 오피스 「클코에게 지시하기」(글·이미지)
  → POST /api/agent-office/orders → pending_orders '대기'  (AI 호출 없음)
창구 터미널(직원창구/ 폴더):
  desk-watch.js(백그라운드 · AI 사용량 0) 10초 간격 DB 확인 + heartbeat 기록
  → 새 '대기'/'승인됨' 발견 시 종료 → 클코가 깨어나 처리
  → desk-get.js(지시·이미지 받기) → 처리 → desk-respond.js(결과·단계 기록) → 다시 watch
화면: 같은 자리에 결과(기존 result.type 형식) · LIVE 로그에 단계 · 종 알림
```
- **엔진 스위치** `agent_office_config 'ao_engine'` = `'desk'`(기본) | `'api'`(되돌리기용 — 2단계 삭제 전까지만). desk면 서버는 `processOrderWithMaru`를 부르지 않는다.
- **정산 이미지**: 창구가 이미지를 읽어 품목·수량만 판독(`desk_ocr_read`) → **단가 매칭·거래처 후보·확인표 생성·저장은 기존 서버 코드 그대로**(AI 없는 구간 재사용 — 금액·박스 차감 무회귀). 재사용 지점은 워커 W1 코드 지도에서 확정.
- **대표 확인함**: status `승인대기` + result `{type:'approval_request', action, summary, impact}` → `POST /orders/:id/approve|reject`(adminOnly) → `승인됨`/`반려` → 창구가 `승인됨`을 집어 실행.
- **창구 상태**: `agent_office_config 'desk_heartbeat' {at, state:'idle'|'busy', order_id}` → `GET /api/agent-office/desk-status` → 화면 「대기 중/처리 중/오프라인(마지막 확인 hh:mm)」(2분 무응답 = 오프라인).
- **알림**: 완료 → 요청자 종 알림 · 승인대기 → 활성 관리자 종 알림. 텔레그램 0.
- **기록**: pending_orders(요청·결과) + agent_runs(단계) 기존 테이블 재사용 → 보고서함·LIVE 로그는 같은 데이터 소스.

## 파일
- `직원창구/CLAUDE.md`(창구 규칙) · `직원창구/업무지식.md`(대표가 채우는 업무 지식 — 주제별 분할 가능) · `scripts/desk/*.js`(watch/get/respond/approval).
- 서버: 엔진 스위치, desk-status, approve/reject, 판독값→확인표 변환 훅. 프론트: 버튼명·상태 표시·확인함·필터/조직도 제거·보고서함 필터 교체.
- 2단계: 새 대시보드(시계·캐릭터·말풍선·채널별 주문현황·최근 매출·지금 꼭 할 일·지시 입력·LIVE 로그) — 실데이터만(허수 금지).

## 무회귀 경계
- 손님 응대 경로·알림톡·정산 수집·송장변환 무접촉. 정산 저장은 기존 서버 경로.
- 창구는 코드·배포 금지라 세 창이 같은 파일을 동시에 고치지 않는다.
- 삭제(에이전트 코드)는 전환 검증 + 실제 정산 며칠 운용 뒤 별도 배포.

## 검증
- 단위: 엔진 스위치(desk면 AI 호출 0) · 승인 흐름 · heartbeat 판정 · 판독값→확인표 변환이 기존 API 경로 결과와 동일(같은 품목 입력).
- 실렌더: 지시 입력→대기 표시→결과 카드 · 확인함 승인/반려 · 보고서함 · 오프라인 표시 · 다른 메뉴 무회귀.
- 실전: 대표·조가영 실제 정산 이미지 1건씩(창구 판독 vs 기존 기록 대조).
