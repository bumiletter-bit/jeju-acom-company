### 4-1. 조종 순서 (final-order.js)

1. 패널을 열면 숨은 iframe을 만들고 `__ivt` 준비를 기다린다. `S.calendar`(suggested · shipDays · realToday)로 기준 발송일 고르개를 채운다.
2. [시작]: 네이버 → 자사몰 → 쿠팡 버튼을 **하나씩** 누르고 끝나길 기다린다(버튼 disabled 풀림 + `#msg-{ch}` 글. 「⚠️」로 시작 = 실패 → 그 채널 실패를 화면에 알리고 계속할지 묻는다).
3. `core.prepLines(메모, …)` → v2에 넘길 글자(`v2Text`) + 보내는이 지정 목록 + 카드. `S.shipDate` = 고른 날(반드시 `shipDays` 안의 값) → `#ln-all.value = v2Text` → `await __ivt.saveLines(S)`.
4. `S.merged` · `S.allLines` 를 읽어 카드를 만든다(§6). 현금파일이 있으면 `core.parseCash` → `core.cashCheck`.
5. 카드를 사람이 처리한다. 주문 카드의 [오늘 발송]/[제외] = `e.excluded` + `e.userTouched = true`. 메모·현금파일을 고쳐 [다시 판정]하면 3번부터 다시(주문은 다시 불러오지 않음). 이미 내린 결정은 주문 키(`ch:i`)로 기억했다가 다시 적용한다.
6. [파일 만들기]: iframe의 `XLSX.writeFile` 을 빈 함수로 덮고 `wb = await __ivt.download()` → 되돌림. `null` 이면 iframe의 `#msg-dl` 글을 그대로 보여 준다.
7. `list = S.merged.filter(e => !e.individual && !e.excluded)` (download **뒤에** 계산 — 쿠팡 취소 재확인이 목록을 바꿀 수 있다). `wb.Sheets.Sheet1` 의 r = i+2 행이 `list[i]`.
8. `core.buildOutput(...)` → 거래처별 행 묶음 → 거래처별 워크북(Sheet1 택배사 양식 + 「수량」 시트) + 스토어 워크북(v2의 「발주발송관리」 시트를 그대로 옮김) → 결과 화면에서 파일별 [저장] · [전부 저장] · 거래처별 [수량 이미지 저장].
9. 세션 만료(iframe 요청 401 → 「로그인 필요」) · dateGuard(null) · 불러온 뒤 날짜가 바뀜 = 화면에 사유를 보여 주고 멈춘다.

## 5. 메모 줄 다듬기 — `core.prepLines`

입력 줄은 v2 `parseLines` 와 같은 꼴(탭 구분 「요청일자·번호·비고·플랫폼」 또는 공백 구분 「번호 …」 옛 형식). 줄 수와 줄 번호는 바꾸지 않는다(v2의 `srcLine` 과 1:1 — 뺄 줄은 빈 줄로).

| 메모에 적힌 것 | 다듬기 | v2가 하는 판정 |
|---|---|---|
| 비고에 「개별발송」(「개별발송처리」 포함) | 「입력o삭제x」 를 비고에 덧붙임 | 기준일이면 개별발송(시트1 제외·시트2 노란) |
| 「번호 금요일 발송」처럼 요일만 | 실제 오늘 이후(오늘 포함) 첫 그 요일의 날짜로 바꿔 「M/D⇥번호⇥비고」 꼴로 | 날짜 규칙 그대로 |
| 요일이 토요일·발송휴무일로 풀림 | 줄은 그대로 넘기고 카드(`line-noship`) | 뒤 날짜면 제외 |
| 비고에 「N박스 중 M박스」 「N박스는」 「나머지」 | 카드(`line-split`) — v2엔 그대로 넘김 | — |
| 비고에 「보내는이/보내는 사람/보내는분/발신 ○○○ [번호] [주소 …]」 | 보내는이 지정으로 떼어 냄. 줄에 날짜가 없으면 그 줄은 v2에 넘기지 않는다(발송 판정에 영향 0). 날짜가 있으면 보내는이 부분만 뺀 줄을 넘긴다 | 날짜 규칙 그대로 |

보내는이 지정 읽기:
- 이름 = 「보내는이」 뒤 첫 덩어리(「으로/로 변경」「드림」 꼬리는 뗀다). 직원이 적은 것이므로 이름 모양 검사는 하지 않는다. 단 이름이 비었거나 20자를 넘으면 애매.
- 번호 = 이름 뒤의 전화번호 꼴(0으로 시작 9~12자리). 없으면 연락처는 안 바꾼다.
- 주소 = 「주소」 낱말 뒤의 글자 전부(「주소:」「주소는」 포함). 「주소」 낱말이 없는데 이름·번호 뒤에 글이 더 남으면 애매.
- 애매 = 자동으로 넣지 않고 카드(`sender-ambiguous` — 이름·번호·주소 칸을 사람이 고쳐 확정).
- 적용 대상 = 그 줄의 번호(구매자연락처 숫자 전체 또는 주문번호·상품주문번호)와 같은 주문 전부. 비고에 「수취인 ○○○」가 있으면 그 수취인만. 맞는 주문이 0건이면 카드(`sender-nohit`).
- 출력: A = 「이름 드림」(이미 「드림」으로 끝나면 그대로) · B = 번호(있을 때) · M = 주소(있을 때) · 세 칸 연파랑(DDEBF7).

## 7. 결과물 만들기 — `core.buildOutput`

### 7-1. 행 모으기
- 프로그램 행: v2 Sheet1 의 r = i+2 행(A~K 값·서식 그대로) + L·M 빈칸. `list[i]` 와 짝.
- 현금 행: 현금파일 Sheet1 의 자료 행 13칸 값 그대로(「!」 포함 · 번호는 글자 그대로). 서식은 프로그램 기본 서식(테두리·맑은 고딕 11)으로 입힌다.
- 직원 보내는이 지정을 프로그램 행에 적용(§5).

### 7-2. 거래처
- 재료 = `/api/invoice/catalog` 의 `byPartner`(오늘 걸리는 단가표). 옵션정보가 그 거래처 목록에 정확히 있으면 그 거래처. 없으면 사이즈 꼬리(`공백 + 2S|S|M + 사이즈로!`)를 떼고 다시 찾는다. 그래도 없으면 「거래처 못 정함」 카드에서 고른 값.
- 파일 이름용 짧은 이름: 「대성(시온)」→「대성」 · 「효돈농협」→「효돈」 · 그 밖은 괄호·「농협」을 뗀 이름.

### 7-3. 정렬 · 제주
- 거래처마다: 제주 아닌 행(옵션정보 글자 오름차순) → 제주 행(옵션정보 글자 오름차순). 비교는 `localeCompare(…, 'ko')`(v2 정렬과 같은 비교). 같은 옵션 안에서는 현금 행(파일 순서) 먼저, 그다음 프로그램 행(v2 순서). 안정 정렬.
- 제주 = I칸(배송지) 글자가 앞뒤 공백을 뗀 뒤 「제주」로 시작. 제주 행의 I칸 = 노랑(FFFF00). 「제주」로 시작하지 않는 행의 I칸 노랑은 지운다(v2는 「제주」가 들어 있기만 해도 칠함 — 사람 기준은 「시작」).

### 7-4. 배송메세지
- 글자는 바꾸지 않는다(#453 원칙 — 색 표시된 칸은 사람이 확인 후 지움). **비어 있을 때만** 기본 문구를 넣는다.

### 7-5. 양식
- 머리글 13칸: v2 시트1 머리글(A~C 초록 92D050 · D~K 노랑 FFFF00) + L 「박스타입(입력x)」 초록 · M 「보내는이 변경주소」 노랑.
- 칸 너비 = 20.6 / 14.9 / 51.3 / 18.3 / 60.9 / 6.1 / 15.3 / 15.3 / 69.4 / 72.5 / 13.6 / 13.6 / 17.3.
- 시트 이름 「Sheet1」(본보기와 같음). 둘째 시트 「수량」.

### 7-6. 수량 표
- 그 거래처 Sheet1 의 옵션정보 글자별 수량 합(사이즈 꼬리 행은 별도 줄 — 본보기와 같음). 옵션정보 오름차순. 맨 아래 합계 줄.
- 색 = `qtyCategory(이름)`(app.js 실함수 · 부모 창 전역) → 노랑 FFFF00 · 주황 F4B183 · 파랑 BDD7EE · 초록 C6E0B4 · 분홍 F4CCCC.
- 이미지 = 같은 표를 canvas 로 그려 PNG 저장(품목 | 수량 · 합계 줄).

### 7-7. 파일
- `제주아꼼이네송장(대성) MM.DD.xlsx` · `제주아꼼이네송장(효돈) MM.DD.xlsx` (MM.DD = 기준 발송일) — 행이 0인 거래처는 만들지 않는다.
- `스마트스토어 발주발송관리 MM.DD.xlsx` — v2 「발주발송관리」 시트 그대로(네이버 주문이 없으면 만들지 않는다).
- `수량(대성) MM.DD.png` · `수량(효돈) MM.DD.png`.
- 🔴 저장된 파일을 다시 읽어 고쳐 쓰지 않는다(색이 사라진다 — #496). 전부 메모리 워크북에서 만든다.

에이전트 오피스 「자주 쓰는 일」 줄에 [최종발주](`#desk-final-now`) → 화면 전체를 덮는 패널(`#fo-panel` · 인디고 가이드 토큰 · 기존 「크게 보기」와 같은 닫기·Esc·뒤로가기).

| 단계 | 요소(id) |
|---|---|
| ① 입력 | 기준 발송일 `#fo-ship`(select) · 현금파일 `#fo-cash`(file) + `#fo-cash-none`(체크) · 메모 `#fo-memo`(textarea) · `#fo-start` |
| ② 불러오기 | `#fo-progress`(채널 3줄 상태) |

카드 마크업 약속: 카드 = `#fo-cards [data-fo-card="종류"]`(order · split · sender-memo · sender-line · line · cash-missing · cash-notindiv · cash-boxdiff · cash-format · partner) · 끝난 카드 = `data-fo-done` · 버튼 = `[data-fo-act]`(order send/excl · split all/excl · sender-memo keep · line ok · cash-boxdiff ok · cash-notindiv extra · cash-missing skip · sender-line use/skip) · 거래처 고르기 = `select[data-pick]` · 남은 주문 확인 일괄 = `[data-bulk="send"]`. 안내만인 것(주문 없음 줄 · 현금파일에만 있는 구매자 · 요일 풀이)은 `#fo-info` 에만.

메모·현금파일·기준 발송일을 바꾸면 [다시 판정] 전까지 [파일 만들기]가 꺼진다.

조용히 틀리지 않게 하는 장치(워커2 결함 검토 10/4 — 5건 재현 후 반영):
- 주문 키 = 원본 행 객체의 고유값(`채널#일련번호`). `채널:순번`은 v2의 쿠팡 취소 재확인이 순번을 당겨 결정이 다른 주문에 걸린다.
- 판정 성공 확인: v2 `saveLines` 는 실패를 안에서 삼키므로, 호출 전 `S.today` 를 비우고 끝난 뒤 채워졌는지 본다. 실패면 파일을 못 만든다.
- 카드 결정은 지금 떠 있는 카드의 것만 인정하고, 판정 시작 때 전 주문의 `userTouched` 를 지운 뒤 판정이 끝나면 다시 건다.
- 주문을 불러온 날이 지나면 [다시 판정]·[파일 만들기]를 막고 [주문 다시 불러오기](`#fo-reload`)로만 진행한다(v2 날짜 가드는 판정 때마다 기준이 오늘로 다시 적힌다).
- 실행 중에는 메모·기준일·현금파일 입력을 잠근다.
- 현금파일 카드 id 에 내용(박스 수·행 번호)을 넣어, 파일이 바뀌면 다시 묻는다.
- 「없이 계속」은 실패한 채널이 받아 둔 주문도 비운다. 쿠팡 취소 재확인 실패 글은 결과 화면에 보인다.

현금파일을 고르지도 「없음」을 체크하지도 않으면 [시작]이 켜지지 않는다. 폰(390px)에서도 한 줄로 접혀 쓸 수 있게 한다.
