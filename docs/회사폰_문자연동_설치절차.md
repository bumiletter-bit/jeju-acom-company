# 회사폰(갤럭시 폴드7) 문자 연동 — 설치·시험 절차 (#610-A)

> 작성 2026-10-10 · 워커2 · 대표·직원이 폰을 들고 그대로 따라 하는 문서.
> 앱 = **SMS Gateway for Android(SMSGate)** · cloud 모드 · 무료.
> 걸리는 시간 = 설치 약 20분 + 시험 약 30분.
> 기술 스펙(총괄용)은 `docs/sms-gateway-spec.md`.
>
> 표기: 「✅ 정상」 = 그 단계 뒤 화면에 보여야 하는 것. 다르게 보이면 **멈추고 총괄에게 화면 글을 그대로** 알려 주세요.
> 🔵 폴드7 화면의 한글 메뉴 이름은 버전마다 조금 다를 수 있습니다(삼성 서비스센터 안내·앱 공식 문서 기준으로 적었고, 실기기에서 확인하지 못한 곳은 「(이름이 다를 수 있음)」으로 표시).

## 준비물

- 회사폰(폴드7) · 충전기에 꽂아 두기 · 와이파이 또는 데이터 연결
- 대표 폰(손님 역할 — 시험 문자를 보내고 받는 용도)
- 종이와 펜(아이디·비밀번호·서명 키 3가지를 적음)
- 🔴 **아이디·비밀번호·서명 키는 카카오톡·문자·메일로 보내지 않습니다.** 종이에 적어 대표에게 직접 → 대표가 Render 환경변수에 입력.

## ① 채팅+ 끄기 (가장 먼저)

채팅+(파란 말풍선)로 온 글은 전달 앱이 읽지 못합니다. 꺼야 모든 글이 일반 문자로 옵니다.

1. **메시지** 앱을 엽니다.
2. 오른쪽 위 **더보기(점 3개)** → **설정**
3. **채팅+ 설정** → **채팅+ 관리** → **채팅+ 끄기** → **끄기**

✅ 정상: 채팅+ 설정 화면에 「꺼짐」(또는 스위치가 회색)으로 보임. 대화창 입력 칸의 안내 글이 「채팅+ 메시지」가 아니라 「문자 메시지」(이름이 다를 수 있음)로 보임.

- 메뉴가 안 보이면: 통신사 114 로 전화해 「채팅플러스 해지」 요청(SKT 114 · KT 1588-0010 · LGU+ 1544-0010).
- 끄면 달라지는 것: 읽음 표시·입력 중 표시·5분 안 전송 취소가 사라지고 일반 문자·MMS 로 오갑니다. 손님 쪽 화면이 어떻게 바뀌는지는 공식 설명이 없어 시험 a 에서 대표 폰으로 같이 봅니다.
- 🔴 폰 업데이트·유심을 뺐다 끼운 뒤에는 이 화면을 다시 확인하세요(다시 켜지는지 확인된 바 없음).

**같이 확인 — MMS 자동 받기**: 메시지 → 더보기 → 설정 → **추가 설정** → **멀티미디어 메시지** → **자동으로 가져오기** 켬(이름이 다를 수 있음).
✅ 정상: 스위치가 켜져 있음. (꺼져 있으면 손님 사진이 서버로 올라오지 않습니다.)

## ② 앱 받기·설치

구글 플레이에는 없는 앱입니다. 공식 배포처(GitHub)에서만 받습니다.

1. 회사폰 크롬에서 엽니다: `https://github.com/capcom6/android-sms-gateway/releases/latest`
2. 제목이 **v1.77.1**(2026-10-01)인지 확인합니다. (그 사이 새 안정판이 나왔으면 그 번호여도 됩니다. **Pre-release** 표시가 붙은 판은 받지 않습니다.)
3. 아래 **Assets** 에서 **`app-release.apk`** 를 누릅니다. 크기 약 **12.1MB**(12,646,990 바이트).
   - 🔴 `app-insecure.apk` 는 받지 않습니다(개발용).
4. 「이 파일은 기기에 손상을 줄 수 있습니다」류 경고 → **무시하고 다운로드**.
5. 받은 파일을 눌러 엽니다 → 「출처를 알 수 없는 앱 설치」 안내가 뜨면 **설정** → 크롬에 **이 출처 허용** 켬 → 뒤로 → **설치**.
6. **Play 프로텍트가 막을 때**:
   - 「안전하지 않은 앱 차단됨」 → **세부정보 더보기** → **무시하고 설치**(이름이 다를 수 있음).
   - 그 버튼이 없으면: **Play 스토어** → 오른쪽 위 프로필 → **Play 프로텍트** → 톱니바퀴 → **Play 프로텍트로 앱 검사** 끔 → 설치 → **설치 뒤 바로 다시 켬**.

✅ 정상: 앱 서랍에 **SMS Gateway**(SMSGate) 아이콘이 생김. 열면 위쪽에 **Local Server** · **Cloud Server** 스위치 두 개와 아래쪽에 **Offline** 버튼이 보임.

## ③ 권한 주기

앱을 처음 열면 권한을 묻습니다. **전부 허용**합니다.

| 권한 | 왜 |
|---|---|
| SMS(문자 보내기·받기·읽기) | 받은 문자 올리기 · 보내기 · 사진(MMS) 읽기 |
| 전화(전화 상태) | 회사폰 번호·유심 확인 |
| 알림 | 앱이 돌고 있다는 표시 |

**SMS 권한이 회색이라 안 눌릴 때**(새 안드로이드에서 플레이 밖 앱에 생김):
1. 폰 **설정 → 애플리케이션 → SMS Gateway**
2. 오른쪽 위 **더보기(점 3개)** → **제한된 설정 허용** → 잠금 해제
3. 다시 **권한 → SMS → 허용**

✅ 정상: 설정 → 애플리케이션 → SMS Gateway → 권한에서 **SMS · 전화 · 알림** 이 모두 「허용됨」 아래에 있음.

- 그래도 안 되면 멈추고 총괄에게(PC 에 연결해 권한을 주는 길이 따로 있습니다).

## ④ cloud 모드 켜기 · 아이디·비밀번호 적기

1. 앱 첫 화면(Home)에서 **Cloud Server** 스위치를 켭니다. (**Local Server 는 끕니다.**)
2. 아래 **Offline** 버튼을 누릅니다 → 잠시 뒤 **Online** 으로 바뀝니다.
3. **Cloud Server** 칸에 **Username** 과 **Password** 가 자동으로 생깁니다. 가입·메일·전화번호 입력은 없습니다.
4. 종이에 적습니다: ①Username ②Password. 대문자·소문자·숫자 0 과 영문 O 를 구별해 또박또박.

✅ 정상: 버튼이 **Online** · Cloud Server 칸에 Username 과 Password 가 보임. 상태 줄에 앱 알림 아이콘이 떠 있음.

- 계속 Offline 이면: 인터넷 연결 확인 → 앱을 닫았다 다시 열기.
- 🔴 이 아이디·비밀번호로 누구나 회사폰에서 문자를 보낼 수 있습니다. 종이는 대표에게 전달 뒤 폐기.

## ⑤ 서명 키 적기 · ping 켜기

1. 앱 아래쪽 **Settings** 탭 → **Webhooks** → **Signing Key** → 보이는 글자를 종이에 ③으로 적습니다.
   - 비어 있으면: 키는 「첫 전송 때 자동으로 만들어진다」고 문서에 적혀 있습니다 → 직접 영문·숫자 32자 이상을 넣고 저장한 뒤 그 값을 적습니다(이 칸에서 바꿀 수 있음).
2. 같은 화면 **Registered webhooks** 는 지금 비어 있어야 정상입니다(등록은 총괄이 서버에서 합니다 — 앱 화면에는 등록 기능이 없고 목록 보기만 있습니다).
3. **Settings → Ping** → 간격 **300**(초) 입력.

✅ 정상: Signing Key 칸에 값이 있음 · Ping 칸에 300.

**종이 3줄을 대표에게** → 대표가 Render 환경변수 3개(`SMSGATE_USER` · `SMSGATE_PASS` · `SMSGATE_SIGNING_KEY`) 입력(저장하면 서버가 다시 뜹니다 · 약 2분) → **총괄이 webhook 9종을 등록**합니다. (`SMSGATE_API_BASE` · `SMS_PUBLIC_URL` 은 기본값이 있어 넣지 않아도 됩니다.) 🔴 **서명 키를 넣고 webhook 이 등록되는 순간부터 회사폰으로 오는 문자가 회사프로그램에 적히기 시작합니다**(연동을 「켜기」 전이어도 기록은 됨 · 알림과 발송만 없음).

> **(총괄 몫 · 참고)** 서버 webhook 등록은 총괄이 배포 뒤 관리자 계정으로 `POST /api/sms/register-webhooks` 를 **1회** 부릅니다(이미 있는 것은 건너뜀 · 9종). 받는 주소 = `https://jeju-acom-company.onrender.com/api/sms/webhook`. 이벤트 = sms:received · sms:sent · sms:delivered · sms:failed · sms:cancelled · mms:received · mms:downloaded · system:ping · app:started. 같이 한 번: 앱 Settings → Messages 의 처리 순서를 **FIFO**(먼저 넣은 것 먼저)로 — 기본값은 나중 것 먼저라 여러 통으로 나눈 답의 순서가 뒤집힐 수 있습니다.

✅ 정상(총괄 등록 뒤): 회사폰에 「새 webhook 이 등록됐습니다」류 알림이 뜨고, 앱 Settings → Webhooks → Registered webhooks 에 **9줄**(Source = Cloud)이 보임. 몇 분 걸릴 수 있습니다.

## ⑥ 꺼지지 않게 하기

1. 앱 **Settings** 탭에서 **Start on boot**(부팅 시 시작)를 켭니다(System 묶음 근처 · 위치가 다를 수 있음).
2. 앱 **Settings → System → 배터리 최적화 끄기**(Disable battery optimizations) → 허용.
3. 폰 **설정 → 애플리케이션 → SMS Gateway → 배터리 → 제한 없음**.
4. 폰 **설정 → 배터리 → 백그라운드 사용 제한** → 「사용하지 않는 앱을 절전 상태로 전환」 목록·「초절전 앱」 목록에 SMS Gateway 가 **없게** 하고, **「절전 예외 앱」에 추가**(이름이 다를 수 있음).
5. 최근 앱 화면에서 SMS Gateway 아이콘을 길게 눌러 **이 앱 잠금**(실수로 모두 닫기에 안 쓸려 가게).

✅ 정상: 폰을 껐다 켠 뒤 5분 안에 상태 줄에 앱 아이콘이 다시 뜸. (이때 앱 Home 의 아이디 칸이 비어 보일 수 있습니다 — 알려진 표시 결함이고 동작은 정상입니다. Settings → Cloud Server → Credentials 에서 보입니다.)

## ⑦ 시험 7항목 — 🔴 **총괄이 「서버 배포했어요」라고 알린 뒤에만**

시험 번호·시각·결과를 종이나 메모에 적어 총괄에게 알려 주세요. 총괄은 서버 기록(문자 표·로그)으로 판정합니다.

> **(총괄 몫)** 시험 전: 설정을 **기록 모드로 켬**(`POST /api/sms/config {"enabled":true,"mode":"record"}` — 꺼진 채로는 받은 글은 적히지만 보내기 큐가 멈춰 있어 b 를 못 합니다). 시험 b·b-2 의 발송은 그 대화의 `POST /api/sms/threads/:id/reply`(에이전트 오피스 「문자」 카드의 답 보내기)로. 시험마다 `node scripts/sms-inspect.js --since 30m` → 맨 위 「시험 판정」 줄과 대화별 줄을 봅니다(읽기만 · 번호·주소 가림). 한 대화만 = `--thread <id>` · 들어온 순서 = `--events`. 🔴 폰 시험이 시작된 뒤에는 `verify-610-ops.js`·`verify-610-server.js` 를 돌리지 않습니다(실제 문자 줄을 건드림 · 스펙 10-7).

| # | 어떻게 | 통과 기준 |
|---|---|---|
| **a 받기** | 대표 폰 → 회사폰으로 문자 「시험a 받기」 | 총괄: 1분 안에 서버 기록에 `sms:received` 1건 · 글 「시험a 받기」 · 보낸 번호 = 대표 번호. 회사폰 삼성 메시지에도 평소처럼 보임. **같이 볼 것**: 대표 폰 대화창이 채팅+(파랑)가 아니라 일반 문자로 보이는지 |
| **b 보내기** | 총괄이 서버에서 「시험b 보내기」를 대표 번호로 발송(직원은 기다림) | ①대표 폰에 회사폰 번호로 문자 도착 ②**회사폰 삼성 메시지의 대표 번호 대화창에 「시험b 보내기」가 보낸 글로 보임** ③총괄: `sms:sent` 뒤 `sms:delivered` 기록 |
| **b-2 긴 글** | 총괄이 한글 100자 안팎 한 통 발송 | 대표 폰에 **한 덩어리로** 오는지 / 둘로 쪼개져 오는지 / 안 오는지 그대로 알림. 총괄: `partsCount` 값 · 실패면 `reason`. (결과에 따라 봇 답 길이 규칙이 정해집니다) |
| **c 손으로 보낸 답** 🔴1순위 | 직원이 회사폰 **삼성 메시지에서 직접** 대표 번호로 「시험c 직원답」 전송 | 총괄: 서버에 **아무 기록도 안 생기는지** 확인(앱 구조상 「안 올라옴」이 예상). 올라오면 어떤 이벤트인지 기록. → 이 결과로 「직원 답은 에이전트 오피스 화면에서만」 규칙이 확정됩니다 |
| **d 사진** | 대표 폰 → 회사폰으로 사진 1장 + 글 「시험d 사진」(MMS) | 총괄: `mms:received`(크기 숫자) → 곧이어 `mms:downloaded`(글 + 첨부 1개 · 바이트 수 > 0 · 사진이 열림). 안 오면 회사폰 메시지에서 사진을 눌러 받은 뒤 다시 확인하고 **「눌러야 왔다」고 알림**. 이어서 사진 3장 한 번에도 1회 |
| **e 죽였다 살리기** | 폰 설정 → 애플리케이션 → SMS Gateway → **강제 중지** → 앱을 다시 열고 Online 확인 | 총괄: `app:started` 1건 + 5분 안에 `system:ping` 다시 옴. 그 뒤 a 를 한 번 더 해서 받기가 되는지 |
| **e-2 재부팅** | 회사폰 재부팅(앱을 손으로 열지 않음) | 5분 안에 `app:started`·`system:ping` · 그 뒤 a 한 번 더. 안 오면 ⑥을 다시 |
| **f 꺼진 동안 온 글** | 회사폰을 비행기 모드로 → 대표 폰에서 「시험f」 전송 → 2분 뒤 비행기 모드 해제 | 총괄: 해제 뒤 몇 분 안에 `sms:received` 가 **1건만** 옴(늦게라도 오고 · 두 번 오지 않음) |

시험이 끝나면 대표 폰과 회사폰 대화창의 시험 글은 지워도 됩니다.

## 직원 안내 — 연동 뒤 달라지는 것

- 문자는 지금처럼 **회사폰 삼성 메시지로 그대로 옵니다.** 같은 글이 회사프로그램 **에이전트 오피스 「문자」 카드**에도 적힙니다.
- 봇이 답한 글은 회사폰 대화창에 **내가 보낸 글처럼** 보입니다. 봇은 한 손님에게 **하루 한 번만** 답하고, 그 뒤에 온 글은 전부 「직원 답 필요」로 넘어옵니다. 봇이 답을 준비하는 사이(약 75초)에 손님이 한 번 더 보내도 봇은 물러나고 직원 몫이 됩니다. 불만 글·환불·반품 이야기는 처음부터 직원 몫입니다.
- 사진이 오면 봇이 사진을 보고 상황을 알아본 뒤 답하거나(자동 단계일 때) 직원에게 넘깁니다. 어느 쪽이든 사진이 온 대화는 직원에게 알림이 갑니다 — 금액·반품·포인트는 직원이 정합니다.
- 알림은 **한 대화에 5분에 한 번**만 옵니다(손님이 연달아 보내도 한 번). 알림 글에는 손님 글이 적히지 않으니 카드를 열어 확인해 주세요.
- 봇 초안이 떠 있는 대화에 손님이 새 글을 보내면 초안은 남고 「직원 답 필요」로 바뀝니다 — 새 글까지 읽고 초안을 고쳐 보내 주세요.
- 답은 **에이전트 오피스 카드에서 보내는 것이 기본**입니다. 카드에서 보내면 서버가 「직원이 답했다」를 알고 봇이 그 손님에게 다시 끼어들지 않습니다.
- 직원이 답했거나 [처리함]을 누른 대화는 **[대화 끝내기]를 누를 때까지 봇이 다시 답하지 않습니다.** 일이 끝난 대화는 [대화 끝내기]를 눌러 주세요(안 누르면 그 손님이 나중에 다시 물어도 봇은 가만히 있고 직원에게만 알림이 옵니다).
- 🔴 **폰(삼성 메시지)에서 직접 답했다면, 카드에서 그 대화의 [처리함]을 꼭 눌러 주세요.** 폰에서 손으로 보낸 글은 서버가 알 수 없습니다. [처리함]을 누르지 않으면 화면에는 계속 「직원 답 필요」로 남고, 아직 봇이 답하기 전인 손님이었다면 봇 답이 뒤따라 나갈 수 있습니다.
- 전화는 지금처럼 직접 받습니다(연동은 문자만).
- 사진이 온 대화는 카드에서 사진이 보입니다. 「사진을 못 받았어요」 알림이 오면 폰 메시지에서 그 사진을 눌러 받은 뒤 확인해 주세요.
- 「회사폰 문자 앱 신호가 3시간 넘게 없어요」 알림(텔레그램)이 오면 아래 표의 첫 줄부터 봅니다.

### 지금 단계(총괄이 바꿉니다)

| 단계 | 봇이 하는 일 | 직원이 하는 일 |
|---|---|---|
| 꺼짐(설치 직후) | 받은 글을 적기만(서명 키가 들어간 뒤부터) · 알림 없음 | 지금과 같음 |
| 기록 | 적기 + 불만·사진 알림 · 아무것도 안 보냄 | 카드 또는 폰에서 답(폰에서 답하면 [처리함]) |
| 초안 | 답 초안만 만듦 | 초안을 보고 [이대로 보내기] 또는 고쳐서 보내기 |
| 자동 | 약 75초 기다렸다가 스스로 보냄(그 사이 직원이 카드에서 답하거나 [처리함]을 누르면 취소) | 「직원 답 필요」만 챙김 |

「자동」으로 넘어가는 것은 대표가 정합니다.

## 문제가 생기면

| 증상 | 먼저 볼 것 |
|---|---|
| 문자를 받았는데 서버에 안 옴 | ①채팅+ 가 다시 켜졌는지(①) ②앱이 Online 인지 ③Registered webhooks 9줄 ④SMS 권한 ⑤배터리 제한(⑥) |
| 서버가 보냈는데 안 나감 | 앱이 Online 인지 · 인터넷 · 앱 화면의 메시지 목록에 Failed 와 이유 글이 보이면 총괄에게 그대로(목록 위치는 실기기에서 확인) |
| 「RESULT_ERROR_LIMIT_EXCEEDED」 | 짧은 시간에 너무 많이 보냄 — 멈추고 총괄에게 |
| 사진이 안 올라옴 | 메시지 설정의 MMS 자동으로 가져오기(①) · 데이터 연결 |
| 앱이 자꾸 꺼짐 | ⑥ 전부 다시 · 「최근 앱 모두 닫기」를 누르지 않기 |
| 아이디 칸이 비어 보임 | 재부팅 직후의 표시 결함 — Settings → Cloud Server → Credentials |

## 하지 말 것

- 앱에서 **Local Server 를 켜지 않습니다**(같은 와이파이의 누구나 접근 가능한 서버가 폰에 생김).
- 앱을 **기본 문자 앱으로 바꾸지 않습니다**(삼성 메시지 그대로).
- Settings → Cloud Server 의 **API URL 을 바꾸지 않습니다**(바꾸면 아이디·비밀번호가 초기화되고 처음부터 다시).
- 회사폰에 다른 문자 전달 앱을 같이 깔지 않습니다(같은 글이 두 번 처리됨).
- 아이디·비밀번호·서명 키를 메신저로 보내지 않습니다.

## 되돌리기(연동을 끄고 싶을 때)

1. 앱 Home 에서 **Online → Offline** · Cloud Server 스위치 끔 → 그 순간부터 올리기·보내기 모두 멈춤(문자 자체는 삼성 메시지로 평소처럼 옴).
2. 완전히 걷으려면 앱 삭제 + 총괄이 webhook 9종 삭제.
3. 채팅+ 를 다시 켜려면 ①의 화면에서 켬.
