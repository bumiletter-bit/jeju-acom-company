# #1062 「아꼼이 문자」 앱 설계 v2 (대표 결정 반영 · 코드 0)

> **대표 뜻(11/9)**
> - 회사폰(폴드7)과 발주컴퓨터 PC 에 「문자만 다루는 앱」을 깐다.
> - 이 앱의 알림은 **문자만** 오고, **진짜 문자 앱처럼** 보인다.
> - 알림을 누르면 그 대화가 열려 바로 답한다.
> - 톡톡·문의·창구·결재 알림은 이 앱으로 오지 않는다. 톡톡·문의 알림은 네이버 앱이 띄운다.
>
> **v1 → v2 바뀐 것 (대표 결정)**
> - ① 새 계정을 만들지 않는다. 회사폰은 **발주컴퓨터 계정(user 10)** 으로 이미 로그인돼 있다.
> - ② 문자 앱을 **발주컴퓨터 PC 에도** 깐다. 문자가 많을 때 직원이 PC 에서 처리한다.
>   PC 에는 본 앱(브라우저)과 문자 앱이 같이 있으므로 **분리 길(/sms/ 별도 scope·매니페스트·서비스 워커)** 을 쓴다.
> - ③ 사진 답장은 하지 않는다. 받기·보기만 한다.
> - ④ 알림은 진짜 문자 꼴로 만든다.
> - ⑤ 알림 아이콘을 같이 만든다.
>
> 작성: 워커2 · 실DB 읽기만(11/9)

## 1. 구조 — /sms/ 분리 길

```
본 앱      https://…/        manifest.json(id "/")            sw.js(scope "/")        구독 label = UA(종전)
문자 앱    https://…/sms/    /sms/manifest.webmanifest        /sms/sw.js(scope "/sms/") 구독 label = 'sms-app'
                             (id "/sms/" · start_url "/sms/")
```

- **같은 PC 에 둘 다 깔려도 괜찮은 까닭**
  - `/sms/…` 아래 화면은 scope 가 더 좁은 `/sms/sw.js` 가 맡는다.
  - 문자 알림을 누르면 문자 앱 쪽 sw 가 `/sms/…` 주소를 연다.
  - 본 앱 sw 는 문자 알림을 받지 않는다(3절) → 같은 PC 에서 알림이 두 번 뜨지 않는다.
- **로그인**: 같은 도메인이라 로그인(localStorage `jwt_token`)을 같이 쓴다.
  - 발주컴퓨터 PC·회사폰은 이미 user 10 으로 로그인돼 있다 → 따로 로그인할 일이 없다.
- **`/sms/` 화면 = 본 앱 화면을 「문자 모드」로 다시 쓴다** (추천 · 워커1)
  - 서버 라우트 하나가 `public/index.html` 을 읽어 다음 넷만 바꿔 내보낸다.
    - ① `<base href="/">` 를 넣는다. index.html 이 `styles.css?v=` 같은 상대 경로를 쓰기 때문이다.
    - ② manifest 링크를 `/sms/manifest.webmanifest` 로 바꾼다.
    - ③ `<html data-app="sms">`
    - ④ 서비스 워커 등록을 `/sms/sw.js`(scope `/sms/`)로 바꾼다.
  - 화면(app.js·css)은 `data-app="sms"` 일 때 이렇게 한다.
    - 로그인 뒤 바로 에이전트 오피스 › 손님 연락 › 문자로 간다.
    - 옆·위 메뉴와 창구 입력 칸을 숨긴다.
    - 뒤로가기를 끝까지 누르면 문자 목록에서 멈춘다.
    - 「알림 받기」는 /sms/ sw 로 구독하고 `label: 'sms-app'` 을 보낸다.
    - 첫 화면 한 줄 안내: 「답은 이 앱에서 보내 주세요 · 폰 메시지 앱에서 보낸 글은 기록이 안 남아요」
  - **대안**: `public/sms/index.html` 을 문자 전용 가벼운 화면으로 새로 만든다(/api/sms/* 만 부름).
    - 본 앱 코드와 섞이지 않는다.
    - 하지만 목록·대화·초안·보내기 화면을 새로 짜야 한다(약 600줄+ · 1.5일+ · 기존 문자 화면과 두 벌 관리). **권하지 않는다.**

## 2. 알림 꼴 — 진짜 문자처럼

**언제 보내나: 손님 문자가 들어올 때마다**
- 일이 생겼을 때만 부르는 notifyStaff 와 따로 둔다. 5분 잠금이 없고, `staff_notify` 값과 상관없다.
- 붙일 자리
  - `recordInbound` 가 새 줄을 적은 뒤. 봉투 중복은 빼고, 「사진 받는 중(photo_pending)」 단계도 뺀다.
  - `mms:downloaded` 가 사진을 붙인 뒤. 사진 문자는 사진이 다 붙었을 때 한 번만 보낸다.
- 안 보내는 것
  - 시험 번호(0999…). 기존 `isTestDigits` 를 쓴다.
  - 대화 상태 `ignored`(사람이 「무시」로 정한 번호)
  - 우리가 보낸 글(직원 답·봇 글)과 전송 결과

**누구에게: 새 설정 `sms_gateway.app_user_ids: [10]`**
- 그 계정의 `sms-app` 꼬리표 구독에만 보낸다(회사폰 + 발주컴퓨터 PC).
- **알림 종(notifications 표)에는 적지 않는다.** push 모듈의 send 를 바로 부른다.
  - 발주컴퓨터 본 앱 알림 종이 문자마다 울리지 않게 하려는 것이다.
  - 그 대신 배달부(deliver)의 재시도가 없다(종전 배달부도 재시도 없음).

**제목**
- 이름 + 가린 번호. 예: `이*화 · 010-****-2485`
- 이름은 **문자 보낸 번호가 그 주문의 받는 분일 때(`role = 'recipient'`)만** 쓴다.
  - 받는 분 이름 전체가 있으면 가운데를 가린다: 2자 「이*」 · 3자 「이*화」 · 4자 이상 「남궁**수」
  - 성 한 글자만 있으면(발송 전 주문) 「이*」
- 번호가 구매자 쪽이거나(`role = 'buyer'` · 구매자 이름은 저장 안 됨), 주문을 못 찾았으면 **번호만**: `010-****-2485`
- 🔴 선물 주문에서 받는 분이 문자를 보낸 경우가 아니면 이름을 붙이지 않는다. 남의 이름이 붙는 오표시를 막기 위해서다.

**본문**
- 첫 줄 = 손님 글 전문. 사진이 있으면 끝에 `📷 사진 n장`, 글 없이 사진만이면 `📷 사진 n장` 만.
- 주문이 있으면 다음 줄에 `주문: <order_hint 그대로>`
  - order_hint 가 길면 「아꼼이네 상품선택: 」 머리말만 뗀다(선택 · 시공 때 대표에게 한 번 보여 줌).
- 봇 초안은 싣지 않는다(열면 보임).
- 상한은 종전 문자 푸시와 같은 300자다. 넘으면 앞 300자.
- 웹 푸시라 이모지 📷 는 문제없다. 「문자에 이모지 금지」 규칙은 손님에게 나가는 문자 얘기다.

**잠금 화면 노출**
- #707-B(대표 10/15)는 「손님 글·봇 답 전문이 잠금 화면에 떠도 된다」였다. 손님 글 전문은 그 범위 안이다.
- 다만 v2 제목의 **가운데 가린 이름 + 앞3·끝4 번호**는 종전 「끝 4자리만」보다 넓다.
  - 대표가 이번에 직접 정한 꼴이므로 허용으로 기록한다.
  - 주소·전체 번호는 넣지 않는다.

**소리·진동·덮어쓰기**
- 소리·진동은 기본으로 둔다(`silent` 안 씀). 바꾸려면 폰 설정 › 앱 › 아꼼이 문자 › 알림.
- `tag = 'sms-' + thread_id`, `renotify: true` → 같은 손님 알림은 한 장으로 바뀌고 매번 다시 울린다. 다른 손님은 따로 쌓인다.

**누르면**
- 열린 문자 앱 창이 있으면 앞으로 가져와 그 대화로 navigate 한다.
- 없으면 `/sms/#agent-office?sms=<id>` 를 연다. 대화 여는 길은 기존 `notiApplyHash` 그대로다.

## 3. 푸시 구독 · 보내기 규칙 (push.js)

- **구독할 때**: `/api/push/subscribe` 가 `body.label === 'sms-app'` 이면 label 을 `sms-app` 으로 적는다. 아니면 종전처럼 UA 를 적는다.
- **문자 앱 알림 보내기**: 새 함수 `sendApp(userId, payload)` 는 그 사람의 `label = 'sms-app'` 구독에만 보낸다.
- **종전 send()**: `sms-app` 구독은 **늘 건너뛴다.**
  - 그래서 창구·결재·정산·시험 알림과 종전 문자 알림(나중에 staff_notify 를 켜더라도)이 문자 앱으로 가지 않는다.
- **본 앱 구독**: 종전 그대로다. 문자 알림은 staff_notify false 라 지금처럼 안 간다.
- **같은 PC 에서 중복 알림 0**: 문자 → 문자 앱 구독만 · 그 밖 → 본 앱 구독만.
- **push_scope**: 전체 설정 `sms: false` 면 sendApp 도 보내지 않는다(전체 끄기 스위치 하나로).
- **실패 처리**: 404/410 이면 그 구독 줄을 지우고, 그 밖 실패는 fail_count +1(종전과 같음).

## 4. 사진 문자 · 답 보내기

- 사진 문자는 받기·보기만 한다(15일 보관).

## 7. 켜는 순서

1. 배포한다(위 파일).
2. **발주컴퓨터 PC** 크롬에서 `https://<회사프로그램 주소>/sms/` 를 연다 → 주소창 「앱 설치」 → 「아꼼이 문자」 창이 뜬다 → 「알림 받기」 → 허용한다.
3. **회사폰** 크롬에서 같은 `/sms/` 를 연다 → 메뉴 「홈 화면에 추가 / 앱 설치」 → 아이콘으로 연다 → 「알림 받기」 → 허용한다.
   - 폰 설정 › 앱 › 아꼼이 문자: 알림 켬, 배터리 **제한 없음**
   - SMSGate 앱도 배터리 제한 없음인지 확인한다
4. 총괄이 실DB 구독에서 user 10 의 `sms-app` 2줄(PC·폰)을 확인한다 → `sms_gateway.app_user_ids = [10]` 을 넣는다(audit). **staff_notify 는 false 그대로.**
5. 회사폰 기본 메시지 앱은 **알림만 끈다.** 앱은 지우지 않는다(SMSGate 가 받고 보내는 데 필요 · 기본 SMS 앱 지정 그대로).
6. 대표 폰 → 회사폰으로 시험 문자 1통 → 회사폰·PC 둘 다 「번호 · 글」 알림 1장씩(본 앱 쪽 알림 0) → 누르면 그 대화 → 답 1통 → 대표 폰 수신.
7. 사진 문자 1통 → 「📷 사진 1장」 알림 → 화면에서 사진 확인. 주문 있는 번호로 1통 → 「주문: …」 줄 확인.

## 8. 되돌리기 · 위험

**되돌리기 (가벼운 순)**
- ① 실DB `app_user_ids` 를 비우면 문자 앱 알림이 바로 멈춘다. 다른 동작 변화 0.
- ② 회사폰 메시지 앱 알림을 다시 켠다.
- ③ PC·폰에서 「아꼼이 문자」 앱을 제거한다. 구독은 다음 발송 때 410 으로 저절로 지워진다.
- ④ 코드는 다음 배포에서 빼도 된다. `/sms/` 라우트를 빼면 본 앱은 영향 0이다.

**위험과 대응**

| 위험 | 대응 |
|---|---|
| 폰 절전(도즈)으로 알림 늦음 | 웹 푸시는 TTL 1시간 · 보통 수 초 → 배터리 제한 없음 |
| SMSGate 늦음·끊김 | 문자가 서버에 늦게 올라온다(종전과 같음 · 「회사폰 전달 앱 연결 끊김」 카드 그대로) |
| 알림 두 번 | 회사폰 = 메시지 앱 알림 끄기로 막는다<br>PC = 본 앱 sw 가 문자를 안 받게(3절) 해서 막는다 |
| PC 에서 알림을 눌러도 앱 창이 아니라 브라우저 탭으로 열림 | 크롬 데스크톱 판에 따라 그럴 수 있다<br>문자 앱 창이 떠 있으면 그 창을 앞으로 가져오므로 보통 문제없다 · 실기기 확인 항목 |
| 이름 오표시 | 받는 분 번호일 때만 이름(2절) |
| `/sms/` 에서 본 앱 메뉴로 나가는 링크를 누름 | scope 밖이라 브라우저 탭으로 열린다 → 문자 모드에서는 메뉴를 숨겨 길이 거의 없다 |
| 서버가 잠든 사이 온 문자 | SMSGate 재전송으로 늦게 들어와도 그때 알림 1번(문자 훅은 들어온 때 기준) |
