# 아꼼이네 주문 정리기 — 회사 프로그램 이식 인수인계서

> 작성: 2026-08-21 · 현재 버전 v2.4 · 대상: 제주아꼼이네 오피스에 통합하는 Claude Code 세션

## 1. 이게 뭔가

현금·단체주문의 두서없는 주소를 자동 정리·검증하고 CJ대한통운 발송 엑셀을 만드는 도구.
현재는 **단일 HTML 파일**(아꼼이네_주문정리기.html, 11.5MB)로 완성되어 실사용 중.
크기가 큰 이유: 한국어 OCR 엔진(tesseract)이 통째로 내장되어 인터넷 없이 이미지 인식이 되기 때문.

## 2. 파일 구성 (이 폴더)

| 파일 | 내용 |
|---|---|
| `아꼼이네_주문정리기.html` | 완성본. 동작 기준(레퍼런스). 그대로 열면 실행됨 |
| `app_template.html` | **UI + 앱 로직 원본** (라이브러리는 `/*XLSX_LIB*/` 등 플레이스홀더) |
| `parser.js` | 자유 텍스트 주문 파서 (이름·전화·주소·상품·수량 추출) |
| `extract.js` | 파일 추출기 (xlsx/xls/csv 열 매핑, hwp/hwpx/docx 텍스트 추출) |
| `build.js` | 조립 스크립트 — 플레이스홀더에 라이브러리·OCR 데이터를 인라인 |

## 3. 외부 의존성 (npm)

```
xlsx-js-style          # SheetJS 0.18.5 포크. 읽기 + 스타일 쓰기 + CFB(HWP 컨테이너) 모두 사용
pako                   # dist/browser/pako_inflate.umd.min.js — HWP 본문 raw-deflate 해제
tesseract.js@5.1.1     # OCR (버전 고정! 워커 주입 방식이 이 버전 기준)
tesseract.js-core@5.1.1
@tesseract.js-data/kor # 4.0.0_best_int/kor.traineddata.gz
@tesseract.js-data/eng # 4.0.0_best_int/eng.traineddata.gz
```
`node build.js` 실행 시 위 파일들이 base64로 HTML에 인라인됨.

## 4. 핵심 로직 지도

- **텍스트 파싱**: `akParseOrders(raw)` (parser.js) → `{orders, context}`. 탭이 3개 이상이면 `tryParseTSV()`가 먼저 표 모드로 처리 (`akParseAoa`).
- **파일 추출**: `akExtractFile(file)` (extract.js) → 시트형은 `{type:'sheet', sheets:[{name,orders}]}` (시트 여러 개면 체크박스 선택 모달), 문서형은 `{type:'text', text}`.
- **주소 검증**: `verifyRow(i)` — 행정안전부 도로명주소 **JSONP** API (`business.juso.go.kr/addrlink/addrLinkApiJsonp.do`). 승인키는 설정 UI에서 localStorage(`akkom_apiKey`)에 저장. **file:// 환경 때문에 JSONP를 쓴 것** — 서버가 있는 회사 프로그램에서는 서버 프록시 + fetch로 바꾸는 게 더 깔끔함 (키도 서버에 숨길 수 있음).
- **OCR**: `ensureOcr()` → 워커 blob 하나에 코어+워커+fetch 가로채기(내장 traineddata 공급)를 전부 넣는 방식. 전처리 `preprocessImage()`(표 격자선 제거+3배 확대), 행 재조립 `ocrRowsFromLines()`(bbox y좌표 클러스터링). 서버가 생기면 서버측 OCR로 대체해도 됨 — 인터페이스는 "이미지 → 텍스트 → parseText()".
- **엑셀 내보내기**: `btnExcel` 핸들러 — 13컬럼 CJ 양식(헤더 색: A·C=CCCCFF, D~J·M=FFFF00, 전체 thin border, 맑은 고딕 11). **문제 셀 노랑 표시**: 주소 미확정=배송지(I), 수취인명 빈칸(D), 연락처 빈칸(G).

## 5. 반드시 지켜야 할 업무 규칙 (대표 확정)

1. **애매하면 자동 확정 금지.** 원문 그대로 검색해 정확히 1건일 때만 자동 ✅. 잘라서 찾았거나 후보 여러 개면 무조건 "선택필요". 아파트인데 호수 없으면 "동·호수 확인".
2. "원본 그대로 두기"는 **상태를 바꾸지 않는다** (확인필요 유지).
3. 수취인명에는 **수취인만** (업체명 병기 금지, 성명 비었을 때만 업체명 대체).
4. 보내는이 미입력 시 보내는사람/연락처 **공란** (자동으로 아무것도 붙이지 않음 — "드림" 등 금지).
5. 시트 불러오기는 **원본 행 순서 유지** (정렬 금지). 번호(1,2,3…) 컬럼은 수량으로 취급 금지.
6. 모달은 바깥 클릭으로 닫히지 않는다 (✕/취소만).
7. 엑셀 헤더 매칭은 공백 무시 ("주 소"="주소"), 유령 열 대비 앞 60열만 사용.

## 6. 디자인

이미 **아꼼이네 오피스 디자인 가이드(인디고/화이트 확정본)** 토큰으로 작성됨
(--primary #4F46E5, 카드 14px, 버튼 10px, 알약 배지 파스텔+색점, 표 sticky 헤더+72vh 스크롤).
이식 시 회사의 theme.css 토큰을 그대로 참조하도록 클래스만 맞추면 됨. 새 색 발명 금지.

## 7. 이식 시 권장 작업 순서

1. app_template.html의 `<style>`을 회사 theme.css/styles.css 토큰 참조로 치환 (기능 로직은 건드리지 않기 🔒)
2. parser.js / extract.js는 모듈로 그대로 이식 (순수 함수, DOM 의존 없음)
3. juso 검증을 서버 프록시로 전환 (승인키 서버 보관, JSONP → fetch)
4. OCR: 초기엔 현재 방식 그대로 두고, 무거우면 lazy-load 또는 서버 OCR로 분리
5. 설정 저장을 localStorage → 회사 계정/DB 설정으로 이전
6. 기존 완성본 HTML과 **같은 입력 → 같은 출력**인지 회귀 확인 (아래 테스트 케이스)

## 8. 회귀 테스트 케이스 (완성본에서 검증된 동작)

- "선릉로86길31롯데골드로즈2차1108호" → 검색어 "선릉로86길 31" + 상세 "롯데골드로즈2차 1108호"
- "김성종(태신스틸) 서울 금천구 벚꽃로 40 …" → 수취인명 "김성종(태신스틸)" 분리
- 탭 구분 표(순번/보내는사람/업체명/개수/성명/전화번호/주소) → 열 매핑, 순번 무시, 수취인명=성명
- 헤더 "주 소"(공백 포함) 인식, 시트 2개 이상이면 체크박스 선택
- 전화 자동 하이픈: 11자리 3-4-4, 10자리 3-3-4, 02는 2-3(4)-4
- 아파트 + 동만 있고 호수 없음 → "동·호수 확인" (자동 확정 금지)
